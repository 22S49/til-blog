if self.hp >= damage:

#### 클래스 변수(정적 변수), 인스턴스 변수

**클래스는 '설계도'고, 인스턴스는 그걸로 찍어낸 '실제 물건'**이에요. 그런데 설계도 안의 메서드(함수)는 하나인데, 그 메서드가 여러 개의 서로 다른 인스턴스에서 각각 동작해야 하잖아요. 그러면 "지금 이 메서드가 어떤 인스턴스를 대상으로 실행되고 있는지"를 알려줘야 하는데, 그 역할을 하는 게 `self`예요.

python

```python
class Dog:
    def __init__(self, name):
        self.name = name  # 이 인스턴스의 name 속성을 만듦

    def bark(self):
        print(f"{self.name}: 멍멍!")

d1 = Dog("초코")
d2 = Dog("보리")

d1.bark()  # 초코: 멍멍!
d2.bark()  # 보리: 멍멍!
```

`d1.bark()`라고 쓰면 파이썬이 내부적으로 `Dog.bark(d1)`로 바꿔서 실행해요. 즉 `self` 자리에 `d1`이 자동으로 들어가는 거예요. 그래서 `bark` 안에서 `self.name`이 "초코"인지 "보리"인지가 결정되는 거죠.

**`__init__`은 "초기화 함수"**예요. `Dog("초코")`처럼 클래스를 호출해서 인스턴스를 만드는 순간 자동으로 실행돼요. 그 안에서 `self.name = name`처럼 써주면, 그 인스턴스만의 데이터(속성)를 만들어서 저장하는 거예요. 이름 앞뒤로 언더스코어 두 개(`__`)가 붙은 건 파이썬이 "이건 특별한 용도의 메서드다"라고 미리 정해놓은 이름이라서 그래요 (매직 메서드/던더 메서드라고 불러요).

비유하자면:

- 클래스 = 붕어빵 틀
- `__init__` = 반죽 넣고 굽는 과정 (붕어빵 하나 만들 때마다 실행)
- `self` = "지금 만들고 있는 이 붕어빵"을 가리키는 말
- `self.name = name` = 이 붕어빵에 이름표를 붙이는 것

#### @classmethod, @staticmethod
- 객체를 생성하지 않아도 접근할 수 있는 메서드를 정의할 때 사용
```python
class Calculator:
    count = 0 

    @classmethod     # 객체를 만들지 않고 접근
    def add(clz, num1, num2): # clz: Calculator 클래스 객체 참조 변수
        # clz: 클래스 변수, 다른 클래스 메서드를 접근하기 위한 목적
        clz.count += 1
        print('호출 횟수:', clz.count)
        return num1 + num2

    @staticmethod
    def minus(num1, num2):
        return num1 - num2

Calculator.add(10, 20) # 호출 횟수: 2, 30
Calculator.minus(10, 20) # -10
```

#### 구문 오류 (Syntax Error)
- 파이썬 문법 사용상의 문제
- 인터프리터가 해석할 때 문제를 인식하기 때문에 실행(런타임) 안 됨
#### 런타임 예외 (Exception)
- 오류가 아닌 예외
- 문법 상에 오류는 없지만 논리적 오류가 있거나 시스템, 원격 등 실행 과정에서 발생하는 문제
1. IndexError — 리스트, 튜플 등 인덱스로 접근하는 객체에서 없는 인덱스로 접근하면 발생
2. ValueError — 특정 자료형으로 변환이 불가하거나 처리가 어려울 때 발생(int, float, boolen 등)
3. TypeError — 대표적으로 다른 타입끼리 연산하는 경우 발생 
4. ZeroDivisionError — 0으로 나누었을 때 발생
#### 예외 처리: try ~ except ~ else ~ finally
```python
try:

	예외가 발생할 가능성이 있는 코드

except:

	예외가 발생하면 유입되는 구간
	예외에 대한 대안 처리 또는 대체, 로깅
	예외마다 여러 개 정의할 수 있음 — except ZeroDivisionError:
		다중 예외 처리 시, 예외가 중복되더라도 가장 먼저 걸린 예외로 처리됨
	여러 예외를 튜플로 묶어서 처리할 수도 있음 — except (ZeroDivisionError, ValueError):
		튜플로 처리하는 경우는 예외를 범주화 해서 처리할 필요가 있을 때
	예외에 별칭을 지정해서 참조할 수 있음 — except ZeroDivisionError as e:
	※ 로깅은 오류가 발생하지 않더라도 하는 습관이 좋음 (정상처리로깅)
	
else:

	예외가 발생하지 않아야 유입되는 구간
	
finally:

	예외가 발생하든 정상 처리되든 항상 유입되는 구간 (공통처리구간)
	예외가 발생하지 않아도 항상 해야 하는 자원 정리 (메모리 해제)
	
```
- 모든 예외 클래스는 Exception의 자식 클래스 — 예외 특정 불가 시, Exception으로 처리

#### 사용자 정의 예외
- Exception은 모든 예외의 부모 클래스
- Exception을 상속 받거나 Exception을 상속 받은 자식 클래스를 상속 받으면 그 클래스도 예외 클래스
```python
# 사용자 예외 정의
class UserIdMismatchError(Exception):
    def __str__(self):
        return '아이디가 일치하지 않습니다.'

class UserPwMismatchError(Exception):
    def __str__(self):
        return '비밀번호가 일치하지 않습니다. '

# 기능 함수      
def login(user_id, user_pw):
    if user_id != 'user01':
        raise UserIdMismatchError
    if user_pw != '1234':
        raise UserPwMismatchError
    print('로그인 처리 로직...')

# 예외 처리   
try:
    login('user03', '13234')
except UserIdMismatchError as e:
    print(e)
except UserPwMismatchError as e:
    print(e)
```
#### 에러 트레이스백
- 주피터 노트북 기준으로 가장 아래의 내용이 가장 최초에 발생한 에러
##### 트레이스백 모듈의 쓰임

- 파이썬은 예외(Exception)가 처리되지 않으면 기본적으로 인터프리터가 트레이스백을 stderr로 출력하도록 되어 있다.
- 그런데 트레이스백 모듈을 쓰는 이유는? ― 예외의 원인을 잡아내고 명시적으로 트레이스백을 출력하기 위해서
    - 예외를 잡아서 처리는 하되, 디버깅용으로 기록을 남기고 싶을 때
    - 에러를 사용자에게는 보여주지 않고, 개발자용으로만 어딘가에 보내고 싶을 때
    - 별도 스레드/비동기 작업에서 발생한 예외일 때
    - 여러 예외를 모아서 나중에 한꺼번에 보고하고 싶을 때 (여러 항목 처리하다가 일부가 실패했을 때)
##### \[참고] 프로그램이 출력할 수 있는 통로

- stdout (표준 출력)
    - print()로 찍는 일반적인 결과물이 나가는 통로
    - "프로그램이 정상적으로 만들어낸 결과"
- stderr (표준 에러, standard error)
    - 에러 메시지, 경고, 트레이스백 같은 "문제 상황을 알리는" 내용이 나가는 통로
    - 파이썬에서 예외가 처리 안 되고 그대로 죽을 때 뜨는 트레이스백이 바로 여기로 나갑니다
- 출력이 나뉘어져 있는 이유
    - 터미널이나 콘솔 화면에서는 구분이 잘 안되는데, 실제로는 각각 따로 다룰 수 있다. 
    - 어떤 프로그램의 출력을 다른 프로그램에 파이프로 연결할 때, 보통 stdout만 넘어가는데  
        에러 메세지가 stdout에 섞여 있으면 결과가 오염되기 때문에 stderr로 분리해서 출력한다.
    - 그래서 트레이스백 모듈도 "이건 결과가 아니라 에러 정보다"라는 걸 명확히 하기 위해 기본적으로 stderr에 쓴다.

```python
import sys
print("정상 결과", file=sys.stdout)   # 그냥 print()랑 동일 (기본값이 stdout)
print("에러 발생!", file=sys.stderr)  # stderr로 강제 출력
```

#### all(iterable)
- 모든 요소가 True로 인식될 때 True
- 단, 빈 리스트는 False가 아니라 True로 인식

#### any(iterable)
- 요소 중 하나라도 True로 인식될 때 True
```python
any([False, 1, 0]) # True — 1 값이 True 이기 때문에
any([]) # False
```

#### 3번 문항

```python
def set_user_age(age):
    if age < 0:
        raise ValueError("나이는 음수가 될 수 없습니다.")
    print(f"사용자의 나이가 {age}세로 설정되었습니다.")

try:
    input_age = -5
    set_user_age(input_age)
except ValueError as e:
    print(f"[시스템 경고] {e}")
```
- **A**. \[시스템 경고] 나이는 음수가 될 수 없습니다.
- *age가 음수이므로 함수 내부에서 raise ValueError가 실행되어 함수 실행이 중단되고, 예외 객체가 상위 try 블록으로 전달됩니다. 바깥의 except ValueError as e 구문이 이를 잡아 메시지를 출력하므로 print 구문은 실행되지 않고 경고 메시지만 출력됩니다.*
#### 4번 문항
- **Q**. 파이썬에서 변수 이름 앞에 언더바 두 개(\_\_)를 붙였을 때, 외부에서 원래 이름으로 직접 접근하지 못하도록 이름이 자동으로 바뀌는 규칙을 무엇이라고 하나요?
- **A**. 이름 변형 규칙
- *언더바 두 개(\_\_)를 붙이면 내부적으로 '\_클래스명__변수명' 형태로 이름이 변형되는 이름 변형 규칙(Name Mangling)이 적용되어, 원래 이름으로는 외부에서 직접 접근할 수 없게 됩니다.*
#### 5번 문항
- **Q**. 빈 리스트(\[])를 all()과 any()에 각각 인자로 전달했을 때의 반환 결과로 올바른 것은 무엇인가요?
- **A**. all(\[])는 True, any(\[])는 False
- *all(\[])은 '거짓인 요소가 하나도 없으므로 참'으로 판단하여 True를 반환하고, any(\[])는 '참인 요소가 하나도 없으므로 거짓'으로 판단하여 False를 반환합니다. 이 때문에 실무에서는 데이터가 비어있지 않은지 먼저 검증하는 조건을 추가해야 합니다.*
