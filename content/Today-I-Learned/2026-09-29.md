# 매개변수
- 인수의 유연성 ─ 매개변수를 지정했더라도 꼭 그 매개변수의 개수만큼 인수를 넣지 않아도 된다.
	- 심지어 매개변수를 지정하지 않더라도 함수에 인수를 넣을 수 있다. 
```js
function add(num1, num2 = 10) {
    return num1 + num2;  
}
add(20); // 30

function add () {}   // undefined
add(10, 20, 30, 40); // undefined
function add (num1) {} // undefined
add(10, 20, 30, 40);   // undefined
```

## 가변 매개변수
- 나머지 매개변수, 전개 연산자
```js
function sum(num1, ...params) {
    console.log(num1, params);
}
sum(10, 20, 30, 40); 
// 10 [ 20, 30, 40 ]
// 순서를 고려하기 때문에 첫 인자를 num1에 할당하고 나머지를 개변 매개변수 배열(array)로 할당

function add(num1, num2) {
    return num1 + num2;
}
const nums1 = [10, 20];
console.log(add(nums1[0], nums1[1])); // 30
console.log(add(...nums1));           // 30 ⇢ 파이썬의 *nums 와 같은 기능

const nums2 = [...nums1]; 
console.log(nums1 === nums2); // false ⇢ 전개 연산자는 깊은 복사를 지원한다. 
```
## 비구조화 할당
- 구조가 있던 객체의 구조를 분해해서 변수에 할당 (파이썬의 언패킹 개념)
```js
const nums = [10, 20, 30, 40, 50];
const [a, b, c] = nums;
console.log([a, b, c]); // [ 10, 20, 30 ]

const [a, b, ...rest] = nums;
console.log([a, b, rest]); // [ 10, 20, [ 30, 40, 50 ] ]
```
### 객체 구조 분해 할당
- 객체 프로퍼티의 변수 이름을 변경하거나 분해할 수 있다. 
```js
const person = {name: "김철수", age: 20};
const name = person.name;              // 하나씩 꺼내기
const age = person.age;                // 이름을 바꿔서 꺼내기
const {name: a, age: b} = person;      // 이름 그대로 꺼내기
const {name: name, age: age} = person; // 이름 그대로 꺼내기의 축약형
const {name, age} = person;
// 위의 모든 출력 값은 김철수 20 으로 동일

/* 중첩 객체 분해 */
const person = { name: "김철수", age: 20, 
	address: { zipcode: "0111", addr1: "주소1", addr2: "주소2", } };
const { name, address: { zipcode: zipcode }} = person;
zipcode; // 0111
```
# 함수
## 정의 방식
- 선언문 ─ 세미콜론 없어도 되고 호이스팅 된다. ─ *e.g.* `abc(); function abc(nums1, num2) {}`
- 표현식 ─ 값 대입 구조니까 세미콜론이 필요하고 호이스팅 된다. ─ *e.g.* `const abc = fuction(num1, num2) {};`
## 주요 역할
- 호출 함수(normal())와 생성자 함수(new normal()) ─ this를 새로 받고 prototype 프로퍼티를 갖는다.
	1. 빈 객체를 새로 만든다. 
	2. 그 객체의 프로토타입을 normal.prototype으로 연결한다.
	3. 그 객체를 this로 넣어 함수를 실행한다. 
## 상속 구조
- 모든 함수 객체는 Function.prototype을 상속 받는다. 
	- 함수가 무엇으로 쓰이나(prototype)
	- 이름을 어디서 찾고(scope chain) 그 환경이 왜 남아 있는가(closure)
- apply, call ─ 함수를 호출하면서 그 함수 안의 `this`를 내가 원하는 객체로 지정해 주는 메서드
```js
abc.call(person, 10, 20);     // call: 인자를 하나씩 나열
abc.apply(person, [10, 20]);  // apply: 인자를 배열로 묶어서 전달

/* 사용례: 같은 함수 하나로 객체만 바꿔 실행 */
function introduce(greeting) {
    console.log(greeting + ", 나는 " + this.name);
}

const a = { name: "김철수" };
const b = { name: "이영희" };

introduce.call(a, "안녕");   // 안녕, 나는 김철수
introduce.call(b, "반가워"); // 반가워, 나는 이영희
```
- bind ─ 함수를 바로 호출하지 않고 `this`가 고정된 새 함수를 반환 (`this`를 바꾼 함수를 만들어 나중에 실행)
	- 콜백이나 이벤트 리스너에서 `this`를 잃어버리는 문제 (연결이 끊기는 문제) 를 해결하기 위해 사용

```js
/* 0. 점(.) 없이 함수 객체를 호출 */
setTimeout(user.hello, 1000); 
// this는 undefined 또는 window를 가리킨다.
// setTimeout은 hello 함수의 this를 모른다. hello 함수의 this는 hello 함수만 안다.
// setTimeout은 hello 함수를 호출한다. 

/* 1. bind: this가 user로 고정된 새 함수를 만든다 */
setTimeout(user.hello.bind(user), 1000);
// this는 user를 가리킨다.
// setTimeout은 hello 함수의 this를 모르지만 hello 함수가 this를 고정(fixed())한다.
// setTimeout은 hello 함수의 fixed()를 호출한다. hello 함수의 this를 알게 된다. 

/* 2. 화살표 함수로 감싸기 */
setTimeout(() => user.hello(), 1000);
// this는 user를 가리킨다.
// setTimeout은 hello 함수의 thist를 모르지만 hello 함수가 화살표 함수로 자가 호출한다.
// setTimeout은 hello 함수가 호출된 상태를 전달 받는다. hello 함수의 this를 알게 된다. 
// 사실 hello 함수는 자신의 this가 없지만 정의된 위치(인스턴스)의 this를 물려 받아 전달한다.

// 3. 클래스 필드에 화살표 함수 사용
class Counter {
    count = 0;
    handleClick = () => {   // this가 인스턴스로 고정됨
        this.count++;
    };
}
```

> [!NOTE] `this` 상실 문제
>  - 점(.) 앞에 있는 객체가 `this`가 되고 점(.)이 없으면 `this`는 `window`를 가리키는데
> 	 - 콜백 함수는 자기가 어떤 객체에 속해 있는지 기억하지 못하므로 `this`를 잃어버리고 
> 	 - 이벤트 리스너에서는 `this`를 클릭된 버튼 요소(이벤트 대상)로 지정하므로 `this` 를 잃는다.

| 메서드     | 실행 시점         | 인자 전달 | 대표 용도                                               |
| ------- | ------------- | ----- | --------------------------------------------------- |
| `call`  | 즉시            | 하나씩   | 메서드 빌려 쓰기, 부모 생성자 호출<br>대체: 유사 배열 변환 `Array.from()` |
| `apply` | 즉시            | 배열    | 배열을 인자로 펼쳐 넘기기<br>대체: 스프레드 문법 `fn(...arr)`          |
| `bind`  | 나중에 (새 함수 반환) | 하나씩   | 콜백/이벤트에서 `this` 고정<br>대체: 화살표 함수 (`this`를 바깥에서 상속)  |
## 일급 객체 3대 속성
- ① 변수 할당 ② 매개변수 전달 ③ 반환값 활용
```js
function square(num) {
    return num ** 3;
}

function calc(nums, callback) { // 함수를 정의하는 매개변수 기능 ⇢ 열린 기능
    let total = 0;
    for (const num of nums) {
        total += callback(num); // 사용자 정의 함수, callback 함수, 일회용 함수
    }
    return total;
}

calc([10, 20, 30,], square); // 36000
calc([10, 20, 30,], function(num) { return num ** 3; }); // 일회용 함수는 주로 익명함수로 사용
calc([10, 20, 30], x => x ** 3); // 그냥 람다 함수로 써도 된다. ⇢ 화살표 함수

const key = "name";
const person = { [key]: "김철수" } // 변수를 키로 받아서 객체 속성을 할당할 수 있다. 
person; // {name: '김철수'}
```
## 화살표 함수
- 자바스크립트의 람다 함수 (이름 없는 함수)
	- 기본 설계 ─ 생성자나 메서드 역할을 수행하지 않는다.
		- 따라서 arguments 객체도 없고 prototype 속성이 없다. ⇢ `new` 생성자를 사용할 수 없다. 
	- *cf.* 만약 호출한 객체를 `this`로 쓰고 싶다면 객체 메서드인 일반함수를 쓰고 바깥의 `this`를 그대로 유지하고 싶다면 메서드 안의 콜백으로 화살표 함수를 쓰면 된다. 
- 정의 방법
	- function 키워드 생략
	- 매개변수 정의부와 코드 실행 영역({}) 사이에 => 로 표기 
	- 코드 실행 영역이 한 줄이면 중괄호 생략 가능 ⇢ 이 경우 return도 생략해야 한다. 
	- 변수는 한 글자로 충분하고 매개변수가 1개이면 소괄호 생략 가능 ⇢ 단, 매개변수가 없거나 2개 이상이면 필요
```js
function square(num) { return num ** 2; }     // 기본형
const square = (num) => { return num ** 2; }; // function 키워드 생략 (대신 변수에 할당)
const square = (num) => num ** 2;             // 중괄호 및 return 생략
const square = (x) => x ** 2;                 // 변수 한 글자로 치환
const square = x => x ** 2;                   // 소괄호 생략 (매개변수 1개일 때)
```
- 제약 조건
	- 화살표 함수의 `this`는 호출 시점이 아니라 정의된 위치에서 결정되며, 자기 자신의 `this` 바인딩은 없다.
		- 그래서 정의된 위치의 바깥 스코프에 있는 `this`를 그대로 사용한다. 
```js
/* 일반 함수 */
const person = {
    name: "김철수",
    age: 20,
    showInfo() {                    // 일반 메서드인 showInfo()는 자기만의 this 보유
        console.log("this", this);  // 아직 호출되지 않았기 때문에 그 this가 뭔지 모름
    }
}
person.showInfo();                  // 호출되었습니다! 여기서 this는 person 입니다. 
// this {name: '김철수', age: 20, showInfo: ƒ}

/* 화살표 함수 */
const person = {
    name: "김철수",
    age: 20,
    showInfo: () => {              // 화살표 함수 showInfo()는 자기만의 this 미보유
        console.log("this", this); // this를 찾기 위해 바깥 범위로 올라갑니다. 
    }                              
}                                  // 객체 리터럴({...})은 스코프가 아니어서 패스
// 결국 최상위 코드(const person = ..)를 만납니다. ⇢ 최상위 코드의 this를 그대로 받습니다.
// 결국 최상위 코드의 this는 이미 정해져 있고 함수가 정의되는 시점에 this가 결정되는 셈입니다. 
// 바깥 변수를 기억해서 바깥 this를 받는다. ⇢ 이렇게 this를 찾아가는 동작 방식이 클로저 개념
person.showInfo();                 // this는 person이 아닙니다. (이미 정해져 있었기 때문)
// this Window {window: Window, self: Window, document: document, name: '', location: Location, …}

/* 일반 함수 + 화살표 함수 */
const person = {
	name: "김철수",
	age: 20,
	showInfo() {                    // 일반 메서드인 showInfo()는 자기만의 this 보유
		conts f = () => {           // 화살표 함수 f()는 자기만의 this 미보유
			console.log("this", this);  // this를 찾기 위해 바깥 범위로 올라갑니다.
		};                              // showInfo()를 만납니다. this를 찾았습니다!
		f();                            // f()가 호출되었습니다! this는 person 입니다.
	}
}
// 화살표 함수 f()는 showInfo()가 실행되는 도중에 만들어집니다.
// 따라서 스코프 체인을 따라 올라가다가 처음 만나는 this인 showInfo의 this를 그대로 받습니다.
```

```
                      this
          ┌────────────┴────────────┐
          ▼                         ▼
      일반 함수                  화살표 함수
  (호출 시점에 결정)         (자기 this 없음 → 바깥 것 빌림)
          │                         │
          ▼                         ▼
   new로 호출하면              스코프 체인
   this = 새 객체            (바깥 스코프에서 this를 찾는다)
          │                         │
          ▼                         ▼
      prototype                   클로저
  (생성자 역할 가능)         (바깥 환경이 끝나도 살아 있음)
```

> [!NOTE] 클로저를 사용하는 이유는?
> - 클로저는 체인이 가리키는 환경이 함수가 끝나도 사라지지 않도록 붙잡고 있는 모양새
> 	- 외부에서 직접 건들지 못하는 private 변수 등 데이터 은닉을 위해 사용한다.
> 	- 콜백함수와 이벤트 핸들러와 같이 정의된 곳의 값을 기억해야 할 때 사용한다.
> 	- 팩토리 함수로 설정값을 기억하는 함수를 써야 할 때 사용한다. 
> 	- React Hook 등 프레임워크 내부 구조가 클로저 기반이기 때문에 사용할 수밖에 없다. 
> - 하지만 클로저를 의도 없이 남발하거나 잘못 쓰면 문제가 된다. 
> 	- 바깥 변수를 붙잡고 있기 때문에 메모리 누수 발생하고 상태가 숨겨져서 추적이 어려워 진다. 
> 	- var 선언자를 쓸 경우 반복문이 의도대로 작동하지 않는다. 

## 고차함수
- 함수의 함수를 반환하는 함수 ⇢ 팩토리 함수, 비동기 처리에 활용한다. 
	- e.g. `const add = x => y => z => x + y + z;`
	- e.g. `[1, 2, 3].map(n => n * 2); // [2, 4, 6]`
### 팩토리 함수
- `new`나 `class` 없이, 호출하면 설정을 이어 받아 새 결과물 (함수 또는 객체) 을 만들어 돌려주는 함수
	- 함수를 반환하는 팩토리 함수는 고차함수이지만 객체를 반환하는 팩토리 함수는 그냥 팩토리 함수
	- 팩토리 함수가 되려면 팩토리로 넘어가는 인자와 클로저가 반드시 포함되어야 한다. 
- 함수는 함수를 반환하고 반환된 함수가 설정값을 기억(클로저)하기 때문에 함수를 계속 만들어 낼 수 있다.
```js
const step2 = work();   // "작업1 실행" 출력, 함수 하나를 만들어 반환 = 팩토리
const step3 = step2();  // "작업2 실행" 출력, 또 함수 하나를 만들어 반환 = 팩토리
step3();                // "작업3 실행" 출력, 반환값 없음
```
## 제너레이터
- `yield`로 값을 하나씩 반환하고 실행을 일시정지하는 함수 ─ 무한 시퀀스, 지연 평가, 이터레이터 생성
```js
function* count() {
  yield 1;
  yield 2;
  yield 3;
}

const g = count();
g.next(); // { value: 1, done: false }
g.next(); // { value: 2, done: false }
[...count()]; // [1, 2, 3]
```
# 객체 2분류
## 네이티브 객체 ─ 공통객체
- 원시 래퍼 객체 ─ 원시값을 객체로 만들어 매서드를 사용할 수 있다. 사용이 끝나면 원시값으로 돌아간다. 
- 내장(표준) 객체 ─ 처음부터 쓸 수 있는 편의 객체 
	- JSON ─ 자바스크립트 객체를 JSON 문자열로 변환하거나 JSON 문자열을 자바스크립트 객체로 변환
	- Math ─ abs(), sqrt(), round(), floor(), ceil(), trunc(), …
		- *e.g.* 1~10 사이의 정수 랜덤 반환 ─ `parseInt(Math.random() * 10) + 1;` 
- 내장(표준) 생성자 객체 ─ Object, String, Number, Boolean, Function, Date, Error, RegExp, Array, … 
	- isNaN(…) ─ 숫자 여부 판별
		- Number(…) 감싸서 호출 시 NaN이 나오면 True, 안 나오면 False
		- 문잦열 숫자는 false로 인식 ⇢ 판별 어려움
		- 정확한 판별은 typeof 를 사용
	- forEach ─ 배열의 각 요소에 대해 함수를 실행 (항상 콜백 함수를 인자로 받는다.)
		- 반환값이 없다. (`undefined`)
		- `break`로 반복을 중단할 수 없다. `return`은 현재 콜백만 종료하고 전체 반복은 중단할 수 없다. 
		- 콜백 안에 있는 비동기 처리 (`async`, `await`) 를 기다려주지 않는다. 
		- 배열, Map, Set 등에만 사용할 수 있고, 제너레이터나 일반 객체에는 사용할 수 없다. 
	- Symbol ─ 항상 고유한 값을 생성해 객체의 충돌 없는 키로서 활용
		- 반복문과 `Object.keys()`에서는 탐지되지 않는다. 
		- 단, 내장 심볼(`Symbol.iterator`)를 정의하면 객체를 반복문으로 순회할 수 있다.
```js
const a = Symbol('id');
const b = Symbol('id');
a === b; // false

const obj = { [a]: 123 };
obj[a]; // 123
```

					- *cf.* `history: [A] + [B] + [C]` ⇢ `replace(D)` ⇢ `history: : [A] + [B] + [D]`

# 배열 객체
- 배열 객체는 모든 타입의 값 지정이 가능하고 여러 개의 값을 관리할 수 있다. 
	- 물리적 객체라기보다 논리적으로 데이터 군집 (컬렉션 중 하나) 를 다루는 편의성 객체
	- 다르게 표현하면 인덱스라는 이름의 속성을 가진 객체에 가깝다고 할 수 있다. 
	- *cf.* 일반적 의미의 배열 ─ 같은 자료형(메모리 크기)을 가진 연속적인 공간
- 생성 방법 
	- 배열 생성자 함수로 생성 ─ *e.g.* `const fruits = new Array("사과", "배", "오렌지");`
		- 단축된 표현법 ─ *e.g.* `const fruits = ["사과", "배", "오렌지"];`
		- 배열 공간구성 ─ e.g. `const fruits = new Array(10);` ⇢ `(10)[empty × 10]`
	- 배열 프로토 타입을 상속 ─ 배열 생성자로부터 만들어진 배열인가? 그 배열의 상속을 받았는가?
- 배열 탐지
	- `instanceof` ─ 객체의 상속 관계 확인 (프로토타입 체인 관계 확인) ⇢ true 이면 배열
	- `Array.isArray(객체)` ─ true 이면 배열
```js
const fruits1 = new Array("사과", "배", "오렌지");            // 배열객체(함수생성)
fruit1 instanceof Array;                                     // true ⇢ 배열객체

const fruits2 = {0: "사과", 1: "배", 2: "오렌지", length: 3}; // 일반객체
fruit2 instanceof Array;                                     // false ⇢ 일반객체

fruit2.__proto__ = Array.prototype;                          // 배열객체(상속생성)
fruit2 instanceof Array;                                     // true ⇢ 배열객체
Array.isArray(fruit2);                                       // true ⇢ 배열객체

const dataList = [1, 2, {name: "김철수"}, "문자", function abc(){}]; // 배열객체
```
- CRUD 메서드
	- 추가 ─ 원본 데이터 변경
		- `push()` ─ 요소의 끝에 새로운 요소 추가
		- `unshift()` ─ 요소의 앞에 새로운 요소 추가
		- `splice(시작점, 0, ...추가요소)` ─ 지정된 위치의 요소를 추가
	- 삭제 ─ 원본 데이터 변경
		- `pop()` ─ 끝에 있는 요소 삭제 (끝 요소를 꺼내고(반환하고) 제거)
		- `shift()` ─ 앞에 있는 요소 삭제 (앞 요소를 꺼내고(반환하고) 제거)
		- `splice(시작점, 삭제개수)` ─ 지정된 위치의 요소를 삭제
		- *cf.* `delete` ─ 배열 요소를 지우는 게 아니라 인덱스 속성을 삭제할 뿐
			- 지운 인덱스 위치에 구멍(empty)이 생기고 인덱스는 당겨지지 않는다. 
			- `empty` ─ 속성 자체가 없는 상태 (`undefined` ─ 속성이 존재하는 상태)
	- 수정 ─ 새로운 배열 객체 반환
		- `map(콜백함수)` ─ 콜백함수 정의 내용대로 변경
		- `filter(콜백함수)` ─ 콜백함수 정의 내용대로 필터
		- `splice(시작점, 교체개수, ...교체요소)` ─ 지정된 위치의 요소를 교체
	- 조회
		- `forEach(콜백함수)` ─ 콜백함수 정의 내용대로 반복 전달
		- `indexOf()` ─ 요소의 위치 번호를 왼쪽에서 오른쪽 방향으로 조회 (못 찾으면 -1)
		- `lastIndexOf()` ─ 요소의 위치 번호를 오른쪽에서 왼쪽 방향으로 조회 (못 찾으면 -1)
		- `Symbol.iterater()` 반복자 ─ `for (… of …)` 로 처음부터 끝까지 조회
```js
const fruits = ["사과", "오렌지", "바나나", "망고", 10, "멜론"]
fruits[10] = "키위"
delete fruits[1]
// (11) ['사과', empty, '바나나', '망고', 10, '멜론', empty × 4, '키위']

/* 원본 데이터 변경 */
const fruits = new Array("사과", "배", "오렌지");
fruits.push("망고", "멜론");      
// fruits; ⇢ (5) ['사과', '배', '오렌지', '망고', '멜론']
const removed1 = fruits.pop();        // removed1; ⇢ '멜론'
// fruits; ⇢ (4) ['사과', '배', '오렌지', '망고']
const removed2 = fruits.shift();      // removed2; ⇢ '사과'
// fruits; ⇢ (3) ['배', '오렌지', '망고']
const removed3 = fruits.splice(1, 1); // removed3; ⇢ ['오렌지']
// fruits; ⇢ (2) ['배', '망고']

/* 새로운 객체 반환 */
const fruits1 = ["사과", "오렌지", "바나나", "멜론", "망고"];
const fruits2 = fruits.map(x => `*${x}*`);
fruits1; // (5) ['사과', '오렌지', '바나나', '멜론', '망고']
fruits2; // (5) ['*사과*', '*오렌지*', '*바나나*', '*멜론*', '*망고*']

/* 반복문 조회 */
for (let i = 0; i < fruits.length; i++) {
    console.log(fruits[i]);
} // 사과, 오렌지, 바나나, 멜론, 망고

/* 심볼릭 조회 */
for (const fruit of fruits) {
    console.log(fruit);
} // 사과, 오렌지, 바나나, 멜론, 망고
```
