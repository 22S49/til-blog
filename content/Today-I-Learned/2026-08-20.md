#### \[데이터 표준 변환] JSON
- JavaScript Object Notation — 자바스크립트 객체 표기법
- 다른 플랫폼(파이썬, 자바, C# 등) 간 소통을 위한 표준 데이터 형식
- 자바스크립트의 객체를 정의하는 형식을 빌려 온 것 — 자바스크립트가 아니고 그냥 문자열!
- 형식 — {'이름':'값', '이름':'값', …}
	- 리스트나 딕셔너리와 같은 데이터 구조일 때 변환 (함수는 변환되지 않음)
```python
import json

# Python 객체를 JSON 문자열로 변환, 직렬화
user = {
    'name':'김철수',
    'age':20
}

json_string = json.dumps(user, ensure_ascii=False)
print('json_string:', json_string, 'type:', type(json_string))
# json_string: {"name": "김철수", "age": 20} type: <class 'str'>

# JSON 문자열을 Python 객체로 변환, 역직렬화
nums_string = '[1, 2, 3, 4, 5]' # 문자열 데이터
user_string = '{"name": "김철수", "age": 20}' # 문자열 데이터

nums = json.loads(nums_string)
user2 = json.loads(user_string)

print('nums:', nums, 'type:', type(nums))
# nums: [1, 2, 3, 4, 5] type: <class 'list'>
print('user2:', user2, 'type:', type(user2))
# user2: {'name': '김철수', 'age': 20} type: <class 'dict'>

# 파일 입출력으로 확장
import json

## dict to json, 직렬화
user = {
    'name':'김영희',
    'age':20,
    'mobile':'010-0000-0000'
}

with open('user.json', 'w', encoding='utf-8') as fp:
    json.dump(user, fp, indent=4, ensure_ascii=False)

## json to dict, 역직렬화
with open('user.json', 'r', encoding='utf-8') as fp:
    user2 = json.load(fp)

print(user2, 'type:', type(user2))
# {'name': '김영희', 'age': 20, 'mobile': '010-0000-0000'} type: <class 'dict'>
```
- 직렬화(Serialize) — Python 객체에서 전송 가능한 JSON 형태로 변환
- 역직렬화 — JSON 문자열(전송 받은 문자열)을 Python 객체로 변환

#### 파일 입출력
- 실행 (Open) — 파일 입출력을 위해 열기, 기본 작업은 읽기(입력)
	- open('파일경로', )
		- open() 이후 명시적으로 close() 해주어야 함
	- with open()
		- 첫 라인에서 \_\_enter__() 실행 ⇢ 마지막 라인 실행 후 \_\_exit__() 호출 (자동 파일 닫기)
```python
# 자원관리도구 클래스 만들어 보기: with open() 구동원리 이해하기
class MyResource:

    def __enter__(self):
        print('__enter__ 함수 호출')
        return self # MyResource 객체를 그대로 반환

    # with 구문이 종료되었을 때 또는 예외가 발생했을 때 호출
    # 예외 발생 시 exc_type은 예외 클래스 종류를 반환
    # 예외 발생 시 exc_val은 예외 메세지를 반환
    # 예외 발생 시 exc_tb는 트레이스백 메세지를 반환
    # 예외가 발생하지 않으면 매개변수는 모두 'None'으로 반환
    def __exit__(self, exc_type, exc_val, exc_tb):
        print('__exit__ 함수 호출')
        
with MyResource() as o: # 시작 시 __enter__ 함수가 호출된다. 
    print(o)
    # 종료 시 __exit__ 함수가 호출된다.
```
- 입력 (Input) — 파일에 있는 데이터 읽기
	- read() — 전체 텍스트 읽기
	- readline() — 한 라인씩 읽기 ⇢ 한 라인씩 전체 텍스트 읽기에 활용, while문과 사용, 메모리 절약
	- readlines() — 라인별로 읽어서 리스트로 반환 ⇢ 메모리 소비 많기 때문에 간단한 파일에 활용

#### 동기식 함수
- 일반적으로 정의하는 함수는 전부 동기식 (서브루틴)
```python
# 동기식 함수(서브루틴)
import time

def work(title, seconds):

    time.sleep(seconds)      # 임의 소요시간 지정, 동기식 형태로 지연
    print(title, '완료')

start = time.perf_counter()  # 작업 시작 시간 기록
work('A작업', 2)
work('B작업', 3) # A작업 동안 B작업은 Blocking 상태
work('C작업', 1) # B작업 동안 C작업은 Blocking 상태
end = time.perf_counter()    # 작업 종료 시간 기록
print('걸린 시간:', end-start)

# 출력 결과
# A작업 완료 
# B작업 완료 
# C작업 완료 
# 걸린 시간: 6.001646799966693
```
#### 비동기 함수
- 비동기 함수는 비동기 내에서만 실행 가능 (코루틴)
- 제너레이터와 유사하게 실행하면 결과를 보지 않고 바로 (실행하자마자) 제어권을 다음 작업에 넘김
	- 그렇기 때문에 각각 실행되는 것 (동기 함수는 결과를 보고 제어권을 넘기기 때문에 연달아 실행)
	- 이벤트 루프가 계속 돌면서 결과가 준비됐는지 확인하고, 준비되면 그 작업을 깨워서 반환한다.
		- 식당에 비유하기 — 주문 = 작업, 어웨이트 = 웨이터, 이벤트 루프 = 주방 
	- 스레드는 하나뿐이지만, 기다리는 동안 놀지 않고 다른 작업에게 순서를 넘겨주는 것
		- 작업이 동시에(병렬로) 돌아가는 것이 아니라 
		- 하나의 스레드가 기다리는 틈을 쪼개서 여러 작업을 번갈아 처리하는 것 (동시성)
```python
# 비동기식 함수 (코루틴)
import asyncio
import time

async def async_work(title, seconds):

    await asyncio.sleep(seconds)   # 임의 소요시간 지정, 비동기 형태로 지연
    print(title, '완료')

async def main():
    start = time.perf_counter()  # 작업 시작 시간 기록
    await asyncio.gather(
        async_work('A작업', 2), # 실행 후 제어권을 다음 작업에 넘김
        async_work('B작업', 3), # A작업과 동시에 시작 (Non-Blocking)
        async_work('C작업', 1)  # B작업과 동시에 시작 (Non-Blocking)
    )
    end = time.perf_counter()    # 작업 종료 시간 기록
    print('걸린 시간:', end-start)

await main()

# 출력 결과
# C작업 완료 
# A작업 완료 
# B작업 완료 
# 걸린 시간: 3.01394179998897
```
#### 비동기 함수 작동 원리
1. 이벤트 루프(중앙 관리자 역할, 스케쥴링)가 A, B, C 세 가지 코루틴을 모두 시작 
	- 세 가지 코루틴은 이벤트 루프의 실행 대기열에 순서대로 입장
2. 실행 가능한 작업(A작업) 꺼내서 실행
3. A작업이 await를 만나서 대기 신호를 받으면, 그 작업을 보류(일시중단)
	- A작업은 제어권을 이벤트 루프에게 반납 (await를 만나자마자 제어권을 이벤트 루프에게 반납)
	- 작업 제어권은 항상 이벤트 루프를 거쳐서 다른 작업으로 넘어감 (제어권은 작업 간 직접 이동하지 않음)
4. 이벤트 루프가 다른 실행 가능한 작업(B작업)을 꺼내서 실행 ⇢ B작업이 await를 만나서 제어권 반납
5. 이벤트 루프가 다른 실행 가능한 작업(C작업)을 꺼내서 실행 ⇢ C작업이 await를 만나서 제어권 반납
6. 이벤트 루프가 모든 코루틴을 실핸하고 나면 대기열이 비었기 때문에 결과가 먼저 준비될 대기시간을 계산
7. 보류한 작업의 결과가 나올 시간이 되면 이벤트 루프는 해당 작업을 깨워서 다시 Queue에 전달
8. 각 작업은 보류되었던 지점에서 이어서 작업을 실행하고 결과를 반환 ⇢ 각 작업별로 이 이벤트가 반복됨
#### 동기식과 비동기의 쓰임
- 동기식이 적합한 경우
    - CPU 위주 작업: 순수 연산, 반복문, 행렬 계산, 이미지/데이터 처리 등 CPU를 계속 쓰는 작업 (연산 중심 작업)
    - 단순하고 순서가 중요한 로직: 스크립트 한 번 실행하고 끝나는 작업, 디버깅이 쉬워야 하는 코드
    - 라이브러리가 동기만 지원: 예를 들어, 일부 DB 드라이버나 오래된 라이브러리는 비동기를 지원하지 않음
- 비동기가 적합한 경우
    - I/O 바운드 작업: 기다리는 시간이 있는 작업인 경우 (CPU가 노는 동안 다른 작업을 처리하게 할 때)
    - 네트워크 요청: 여러 API를 동시에 호출할 때 (예: 여러 웹사이트 크롤링, 여러 외부 서비스에 동시 요청)
    - 웹 서버: FastAPI, aiohttp 등 — 수천 개의 클라이언트 요청을 동시에 처리해야 할 때 
    - DB 쿼리: 여러 쿼리를 동시에 날리고 결과를 한꺼번에 기다릴 때
    - 파일 I/O: 대용량 파일을 여러 개 동시에 읽고 쓸 때
    - 채팅봇/실시간 서비스: 여러 사용자의 메시지를 동시에 처리할 때
#### writerow()와 writerows()
- writerow()는 반드시 1차원 리스트(한 줄 분량) 를 넣어야 정상적으로 열(column)들로 나뉘어 쓰여진다.
- 2차원 리스트를 쓰고 싶으면 writerows()를 쓰거나, `for row in data:` `writer.writerow(row)`처럼 
  반복문으로 써야 한다.
#### JSON 반환 형태에 따른 함수 쓰임
- json.dump(obj, fp)
    - 파일 객체에 직접 쓴다. 굳이 변수에 담을 필요가 없다.
    - None을 반환한다. (반환값 없음)
    - 파일로 저장할 때 사용

#### 1번 문항
- **Q**. 다음 코드를 실행했을 때 출력되는 결과로 올바른 것은 무엇인가요?
```python
scores = [45, 80, 55, 90, 30]
result = list(filter(lambda x: x >= 60, scores))
print(result)
```
- **A**. \[80, 90]
- *filter()는 조건문(lambda x: x >= 60)이 참인 요소만 걸러내므로 60 이상인 80과 90만 선별되어 리스트로 반환됩니다.*
#### 2번 문항
- **Q**. 반복 가능한 객체(Iterable)의 모든 요소에 동일한 규칙(함수)을 일괄 적용하여 새로운 형태로 변환할 때 사용하는 함수의 이름은 무엇인가요?
- **A**. map()
- *map()은 리스트 등 반복 가능한 객체의 모든 요소에 동일한 함수(예: 람다식)를 일괄 적용해 새로운 값으로 변환해 주는 함수입니다. 조건에 맞는 요소만 골라내는 filter()와는 역할이 다릅니다.*

#### 4번 문항

#### 5번 문항
- **Q**. 1초가 걸리는 API 요청 10개를 동기식으로 순차 처리하면 총 10초가 소요됩니다. 동일한 요청을 asyncio.gather()를 이용해 비동기로 동시 처리하면 총 소요 시간은 어떻게 되나요?
- **A**. 가장 오래 걸리는 작업 하나의 시간만큼만 소요된다
- *비동기 동시 처리는 각 요청의 대기 시간을 중첩하여 관리하므로, 전체 소요 시간은 개별 시간의 합이 아니라 가장 늦게 응답하는 작업 하나의 시간으로 단축됩니다. 동기식처럼 시간이 합산되거나 즉시 완료된다는 설명은 비동기 동시성의 원리와 맞지 않습니다.*
