# 연습장
## 식별자(Key)
- 키(Key)는 특정 컬럼 또는 컬럼의 조합에 역할을 부여해주는 개념
#### **기본키 (Primary Key)** ^4bc95b
- 하나의 레코드를 식별할 수 있는 대표 컬럼 또는 컬럼의 조합
- 개체 무결성 ─ 중복 불가 (유일무이) ⇢ NULL 불가 (값이 반드시 있어야 한다.)
#### **외래키 (Foreign Key)** ^f809c4
- 외래키가 있는 테이블이 자식 테이블, 외래키가 가리키는 테이블이 부모 테이블
	- 자식 테이블과 부모 테이블은 identifying relationship
- 외래키가 부모 테이블을 참조함으로써 부모 테이블이 자식 테이블에게 해당 값을 공유한다. 
- 참조 무결성
	- 부모 테이블에 없는 참조값을 자식 테이블이 사용할 수 없다.
	- 자식 테이블이 사용하고 있는 참조값은 부모 테이블에서 삭제할 수 없다. (자식 테이블을 삭제하면 가능)
		- 연결되어 있던 식별자가 삭제되어 관계 구조가 깨지지 않도록 하는 제약조건 
## SQL 명령어
### DDL (Data Definition Language) ─ 데이터 정의어
- DDL 작업은 롤백 불가
- CREATE
	- 제약조건
		- PRIMARY KEY ─ 중복 허용하지 않음. 비어있는 값(NULL) 허용하지 않음
		- NOT NULL ─ 비어있는 값(NULL) 허용하지 않음 ⇢ 필수 항목인 경우 활용
		- UNIQUE ─ 중복을 허용하지 않음. 단, NULL 중복은 허용
		- UNIQUE NOT NULL ─ 중복을 허용하지 않음. NULL 중복 또한 허용하지 않음
	- 기타조건
		- CHECK ─ 특정 조건에 해당하는지 확인. 특정 조건에 한정시킨다. 비교 또는 논리 연산자를 사용할 수 있다.
		- DEFALT ─ 기본값을 지정하거나 내장 함수, 내장 상수 등을 불러올 수 있다. 
			- *e.g.* 현재 날짜와 시간 표기 ─ CURRENT_TIMESTAMP
		- REFERENCES ─ 외래키가 참조할 부모 테이블의 열이름을 지정한다. 
			- 관련이 있다고 무조건 외래키를 지정할 필요는 없다. 보통 참조하면서 제약조건을 걸어야 할 때 사용한다. 
				- 관계를 지어주기 위해 사용한다기보다 무결성 제약조건을 걸기 위해 사용한다. [[2026-09-03#^f809c4|2026-09-03]]
			- ON DELETE CASCADE ─ 부모 테이블의 레코드가 삭제되면 자식 레코드도 삭제 (잘 쓰지 않음)
			- ON DELETE SET NULL ─ 부모 테이블의 레코드가 삭제되면 자식 레코드의 참조값을 NULL로 치환
```sqL
CREATE TABLE 테이블명 ( -- 아래 코드 내용 중 대괄호 안에 표기한 건 선택 옵션
	열이름1 데이터타입 [제약조건1 제약조건2 …] [DEFAULT 기본값] [REFERENCES 부모테이블명 (열이름)], 
	열이름2 데이터타입 [제약조건1 제약조건2 …] [DEFAULT 기본값], 
	PRIVARY KEY (열이름1, 열이름2, …) -- 여러 컬럼의 조합으로 기본키를 생성할 경우 (복합기본키)
); --세미콜론은 문장이 끝났음을 알려주는 역할
```
- ALTER ─ 테이블명, 열이름, 열 추가/삭제 등의 수정 작업 ^0783a1
	- 열 추가 ─ `ALTER TABLE 테이블명 ADD COLUMN 열이름 자료형 [제약조건];`
	- 열 삭제 ─ `ALTER TABLE 테이블명 DROP COLUMN 열이름;`
	- 열 이름 변경 ─ `ALTER TABLE 테이블명 RENAME COLUMN 기존열이름 TO 변경열이름;`
	- 열 타입 변경 ─ `ALTER TABLE 테이블명 ATLER COLUMN 열이름 TYPE 자료형 USING (열이름::자료형);
	- 열 조건 설정
			- 데이터 타입이나 기본값
				- `ALTER TABLE 테이블명 ALTER COLUMN 열이름 SET 제약조건명;`
				- `ALTER TABLE 테이블명 ALTER COLUMN 열이름 SET DEFAULT 기본값;`
			- 데이터 무결성 보장규칙
				- `ALTER TABLE 테이블명 ADD CONSTRAINT 지정구분자 PRIMARY KEY (열이름, …);`
				- `ALTER TABLE 테이블명 ADD CONSTRAINT 지정구분자 UNIQUE (열이름, …);`
				- `ALTER TABLE 테이블명 ADD CONSTRAINT 지정구분자 CHECK (조건식);`
				- `ALTER TABLE 테이블명 ADD CONSTRAINT 지정구분자 FOREIGN KEY (열이름) REFERENCES 참조테이블명 (참조열이름) [ON DELETE CASCADE|SET NULL];`
	- 열 조건 삭제
		- `ALTER TABLE 테이블명 ALTER COLUMN 열이름 DROP 제약조건명;`
		- `ALTER TABLE 테이블명 DROP CONSTRAINT 지정구분자;`
		- `ALTER TABLE 테이블명 ALTER COLUMN 열이름 DROP DEFALUT;`
- DROP ─ 스키마와 인스턴스 모두 초기화 (완전제거)  `DROP TABLE 테이블명;`
- TRUNCATE ─ 스키마는 유지하면서 인스턴스만 초기화 `TRUNCATE TABLE 테이블명;`

| 항목     | DELETE     | TRUNCATE | DROP   |
| ------ | ---------- | -------- | ------ |
| 명령어 분류 | DML        | DDL      | DDL    |
| 삭제 범위  | 행 일부 또는 전체 | 행 전체     | 행×열 전체 |
| 저장 공간  | 유지         | 삭제       | 삭제     |
| 인덱스    | 유지         | 삭제       | 삭제     |
| 스키마 구조 | 유지         | 유지       | 삭제     |
| 테이블 자체 | 유지         | 유지       | 삭제     |

> [!NOTE] 소프트 삭제
> - deleted_at 열이 NULL이 아니면 삭제로 판단한다. (실제로 삭제하는 것이 아니라 삭제 상태로 만드는 것)
> - 실무에서 데이터 삭제는 민감 사항이기 때문에 하드 삭제가 아닌 소프트 삭제를 사용하는 경우가 있다.
> 	- 필요 시 삭제 상태인 데이터에 대해 암호화를 적용하여 지정된 기간 동안 데이터를 보존하기도 한다.

### DML (Date Manipulation Language) ─ 데이터 조작어 ─ CRUD
- DML 작업은 커밋 전이라면 롤백 가능 ─ 최근 SQL 클라이언트들은 자동커밋을 기본 설정으로 하고 있어서 유의
- INSERT(추가)
```sql
-- 열이름을 명시하고 데이터를 추가할 때 (e.g. 특정 열에 데이터를 넣는 경우, 기본값 포함 열이름은 생략)
INSERT INTO 테이블명 (열이름1, 열이름2, 열이름3) VALUES (값1, 값2, 값3), (값1, 값2, 값3), …; 
-- 열이름을 굳이 명시하지 않아도 될 때 (e.g. 모든 열에 데이터를 순서대로 추가하는 경우)
INSERT INTO 테이블명 VALUES (값1, 값2, 값3), (값1, 값2, 값3), …;
```
- UPDATE(수정) ─ 원하는 데이터를 찾기 위한 범위를 설정하는 조건식(비교·논리 연산 등 WHERE절) 활용 ^e2a25c
	- WHERE절을 쓰지 않으면 데이터를 다 날리거나 SQL 인젝션 해킹에 이용 당할 수 있다. 적절히 사용해야 한다. 
	- `UPDATE 테이블명 SET 열이름1 = 변경값1, 열이름2 = 변경값2, … [WHEARE 조건식];
- DELETE(삭제) ^823d83
	- 테이블의 모든 데이터 삭제 ─ `DELETE FROM 테이블명;` ~ TRUNCATE와 유사한 역할이되 커밋 전이면 롤백 가능
	- 테이블의 일부 데이터 삭제 ─ `DELETE FROM 테이블명 WHERE 조건식;` 
- DQL (Date Query Language) ─ 데이터 질의어 ─ SELECT [[2026-09-07]]
### DCL (Date control Language) ─ 데이터 제어어
- GRANT(권한 부여), REVOKE(권한 삭제)
- TCL (Transaction Control Language) ─ 트랜잭션 제어어
	- Transaction ─ SQL의 실행 단위
	- COMMIT ─ 데이터를 DB에 영구 반영
	- ROLLBACK ─ COMMIT 전에 반영 내용 되돌리기 (COMMIT 후는 회복 불가)
## 데이터베이스 정규화
- 데이터 중복과 이상현상을 개선하기 위해서 테이블의 구조를 단계적으로 개선하는 과정 
	- 제3정규형는 제2정규형 만족을 전제로 하고 제2정규형은 제1정규형 만족을 전제로 한다. 
- 정규형을 한다고 해서 무조건 좋은 것은 아니다. 완전 정합성보다는 최종 정합성을 추구하는 편이다.(반정규화)
	- 완전 정합성
		- 항상 100% 정확하고 중복이 없도록 한다. 
		- 데이터 변경이 발생하면 그 순간 모든 곳에서 항상 동일하고 정확한 값을 보장하는 것
		- *e.g.* 정규화를 철저히 지킨 데이터베이스 ─ 여러 테이블을 조인해야 하기 때문에 연산 비용이 크고 느리다. 
	- 최종 정합성
		- 성능을 위해 어느 정도 중복을 허용하고 추후 수정을 감수하며 융통성 있게 작업한다. 
		- 당장은 값이 서로 다를 수 있어도 나중에 (결국) 일치시키는 것을 허용하는 방식. 버전 관리와 동기화를 접목
		- *e.g.* 반정규화 데이터베이스 ─ 조회 성능을 위해 일부러 데이터를 중복 저장하기 때문에 속도가 빠르다. 
		- *e.g.* 정규화를 너무 열심히 했을 때의 오류 발생 가능성
			- 가격 테이블에서 가격이 오른 순간 작년 영수증 금액까지 바뀌는 경우 발생
- 제1정규형(1NF) ─ 원자값(더 이상 분해할 수 없는 값)을 유지한다. 한 셀에는 하나의 값만 있어야 한다. 
- 제2정규형(2NF) ─ 일반 컬럼은 복합 기본키 전체에 종속되어야 한다. 일부 기본키에 부분 종속을 허용하지 않는다.
- 제3정규형(3NF) ─ 일반 컬럼 간 종속 관계가 있어서는 안된다. 종속 관계는 반드시 기본키와 직접 연결되어야 한다.

# 데일리 퀘스트
#### 1번 문항
- **Q.** 다음 중 DDL(Data Definition Language)에 해당하는 명령어는 무엇인가요?
- **A.** CREATE TABLE
- *CREATE TABLE은 테이블 구조를 정의하는 DDL 명령입니다. INSERT, SELECT, UPDATE는 데이터를 조작하는 DML 명령입니다.*
#### 2번 문항 

- **Q.** 테이블 내에서 각 행(Row)을 유일하게 식별하며, 중복 값과 NULL 값을 가질 수 없는 열을 무엇이라고 하나요?
- **A.** primary key
- *기본키(PK)는 테이블에서 각 행을 유일하게 식별하는 열로, 중복 불가와 NULL 불가라는 두 가지 핵심 규칙을 가집니다.*
#### 3번 문항

- **Q.** INSERT INTO 문 실행 시, INT 타입 열에 문자열 '홍길동'을 입력하려고 하면 어떤 일이 발생하나요?
- A. 데이터베이스가 오류를 발생시키고 해당 INSERT를 거부한다
- *데이터 타입이 맞지 않으면 데이터베이스는 오류를 발생시키고 해당 INSERT를 거부하여 잘못된 데이터 저장을 방지합니다. 자동 변환이나 부분 저장, 단순 경고 처리는 이루어지지 않습니다.*
#### 4번 문항

- **Q.** FK가 참조하는 값이 반드시 참조 대상 테이블의 PK에 존재해야 한다는 규칙을 무엇이라고 하나요?
- **A.** 참조 무결성
- *참조 무결성(Referential Integrity)은 외래키(FK)가 참조하는 값이 반드시 참조 대상 테이블의 기본키(PK)에 실제로 존재해야 한다는 규칙으로, 이를 통해 데이터 간 관계의 유효성이 유지됩니다.*
#### 5번 문항

- **Q.** 수강 신청 테이블에서 student_name이 student_id에만 의존하고 course_name이 course_id에만 의존하는 경우, 이를 개선하기 위해 적용하는 정규화 단계는 무엇인가요?
- **A.** 2NF
- *2NF는 복합키를 사용하는 테이블에서 복합키 전체가 아니라 일부 키에만 의존하는 열을 분리하는 단계입니다. 1NF는 한 칸에 하나의 값만 저장하는 단계이고, 3NF는 PK가 아닌 컬럼 간의 의존 관계를 제거하는 단계입니다.*
