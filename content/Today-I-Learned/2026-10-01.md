# innerHTML
- 내부 콘텐츠를 HTML 코드로 해석하고 화면에 반영
- HTML 조각을 직접 만들어서 넣어야 할 때 사용하되, 보안문제(XSS 공격) 발생 가능
# textContent
- 내부의 HTML 태그를 해석하지 않고 순수한 텍스트 문자열로만 처리
	- 이름, 댓글, 검색어, 입력창 값처럼 사용자가 입력한 값을 화면에 보여줄 때
	- 서버에서 받아온 문자열을 단순 텍스트로 표시할 때
	- 숫자, 날짜, 메시지 등 태그가 필요 없는 모든 경우
- HTML 파싱 과정이 없기 때문에 innerHTML보다 속도가 빠르다. 
# 이벤트(Event)

# 이벤트 콜백
## 이벤트 핸들러(EventHandler) 
- 이벤트가 발생했을 때 실행되는 함수. 핸들러 요소는 모두 비동기식으로 작동 (이벤트가 발생할 때 실행)
- HTML 요소의 이벤트 속성으로 생성 ─ `on` 접두사를 가진 이벤트명 하나만 등록 가능
	- 프로퍼티가 하나이기 때문에 핸들러도 하나만 등록되고 다시 할당하면 덮어써진다. 
```html
<!-- 인라인 방식 -->
<button onclick="alert('클릭')">버튼</button>

<!-- 프로퍼티 방식 -->
<script>
	button.onclick = function () { // 요소의 이벤트핸들러 속성에 함수 대입
	  console.log('클릭1');
	};
	button.onclick = function () { // 요소의 이벤트핸들러 속성에 함수 대입
	  console.log('클릭2');         // 새로운 함수 재할당 → '클릭2'만 실행
	};
</script>
```
## 이벤트 리스너(EventListener) 
- 이벤트 핸들러를 등록하는 방식 중 하나. 이벤트 핸들러와 같은 의미로도 사용
- 같은 이벤트에 여러 개의 핸들러를 등록할 수 있고 누적된다. 
- `document.addEventListener(이벤트명, 이벤트핸들러, 캡처링여부);`
	- 이벤트 전파 ─ 캡처링 단계 → 타겟 단계 (이벤트 핸들러 실행, 이벤트 발생) → 버블링 단계
		- 버블링 단계에서 타겟 단계에서 발생했던 이벤트가 상위 요소로 전파된다. (상위 요소에도 이벤트 발생)
		- 캡처링 여부가 `false`이면 버블링 단계에서 전파가 발생(기본값)하고 `true`이면 캡처링 단계에서 전파
	- 리스너 제거 ─ `document.removeEventListener(이벤트명, 이벤트핸들러, 캡처링여부);`
		- 리스너를 제거할 때 이벤트핸들러는 생성 시와 동일한 함수를 참조해야 한다.
			- 따라서 익명 함수나 화살표 함수로 등록한 리스너는 제거할 수 없다. 필요 시 변수에 할당 후 제거
			- 또한 리스너가 외부 변수를 참조(클로저)하면 리스너가 살아있는 동안 그 변수도 GC 불가하다.
				- 리스너가 window(전역)에 붙는다면 스코프 변수를 계속 참조해서 메모리 누수가 발생할 수 있다. 
			- 캡처링 여부 또한 생성 시와 동일한 불리언 값으로 지정해야 한다. 맞지 않으면 지워지지 않음 
	- 일회성 실행 ─ `document.addEventListener(이벤트명, 이벤트핸들러, {once: true});`
```html
<!-- 박스 중첩 구조 -->
<div class="box box1">
	<div class="box box2">
		<div class="box box3"></div>
	</div>
</div>

<script>
/*
	box3를 클릭하는 경우 발생하는 프로세스
	-------------------------------------------
	캡처링 ↓  box1(패스) → box2(실행) → box3(기점)
	타깃      box3(실행)
	버블링 ↑  box3(기점) → box2(패스) → box1(실행)
*/
	window.addEventListener("DOMContentLoaded", function(){
		const box1 = document.querySelector(".box1");
		const box2 = document.querySelector(".box2");
		const box3 = document.querySelector(".box3"); 

		box1.addEventListener("click", function(){
			console.log("box1 클릭");
		});       // 버블링 단계에서 실행
		box2.addEventListener("click", function(){
			console.log("box2 클릭");
		}, true); // 캡처링 단계에서 실행 → 타겟 단계에 앞서 있으면 가로챈다. (먼저 실행)
		box3.addEventListener("click", function(){
			console.log("box3 클릭");
		});       // 타겟 단계에서 실행
	});
</script>
```
## 이벤트 객체 
- 이벤트 핸들러의 첫번째 매개변수 → 발생한 이벤트와 관련된 정보를 포함한다. 
- `target` ─ 어느 리스너가 실행되든 실제로 이벤트가 발생한 가장 안쪽 요소 (내가 어디를 클릭했는가)
- `currentTarget` ─ 현재 실행 중인 이벤트(리스터)가 붙어 있는 요소 
	- function 핸들러의 `this`와 동일하지만 화살표 함수에서는 다르게 작동하므로 유의
- `stopPropagation()` ─ 이벤트 통제 매서드. 이벤트 전파 차단
- `stopImmediatePropagation()` ─ 같은 요소의 다른 이벤트도 함께 차단 (설정 외 이벤트 실행 방지)
- `preventDefault()` ─ 이벤트 전파와는 관계 없이 요소의 기본 동작(링크 이동, 폼 제출 등) 취소 
### 이벤트 객체 제어 실습

```html
<!-- 박스 중첩 및 링크 요소 포함 구조 -->
<div class="box1">
    <div class="box2">
        <a href="https://example.com" class="link"><span class="text">링크</span></a>
    </div>
</div>

<script>
/*
	'링크' 텍스트(span)를 클릭하는 경우 발생하는 프로세스
	-----------------------------------------------
	캡처링 ↓  box1(패스) → box2(패스) → a(패스) → span(기점) (캡처링용 리스너 없음 → 일괄 패스)
	타깃      span(패스, 리스너 없음)
	버블링 ↑  span(기점) → a(link A, B 실행) → box2(실행) → box1(실행) (버블링용 리스너 실행)
	-----------------------------------------------
	※ link A, B는 타깃 단계(span)가 아니라 span의 부모인 a의 버블링 단계에서 실행
*/
    const box1 = document.querySelector(".box1");
    const box2 = document.querySelector(".box2");
    const link = document.querySelector(".link");

    // box1: 버블링 단계에서 실행 (세 번째 인자: false)
    box1.addEventListener("click", function(e){
        console.log("box1 클릭");
    });
    // box2: 버블링 단계에서 실행 (세 번째 인자: false)
    box2.addEventListener("click", function(e){
        console.log("box2 클릭");
    });
    // link: 버블링 단계에서 실행 (세 번째 인자: false)
    link.addEventListener("click", function(e){
        e.preventDefault();               // 링크 이동(기본 동작) 취소
        e.stopPropagation();              // 부모(box2, box1)로 전파 차단
        // e.stopImmediatePropagation();  // 전파 차단 + 아래 리스너(B)도 실행 안 됨
        console.log("link A 클릭");
    });
    link.addEventListener("click", function(e){
        // stopPropagation()만 썼다면 실행됨 / stopImmediatePropagation()이면 실행 안 됨
        console.log("link B 클릭");
    });
</script>
```
- A에서 `preventDefault()`를 호출하면 `e.defaultPrevented === true` 상태
	- link A와 link B는 같은 클릭 이벤트의 `e`를 공유하기 때문에 B에서 `preventDefault()`를 호출하지 않아도 링크 이동 동작(\<a> 태그 기본 동작)이 취소된다.
		- `stopImmediatePropagation()`으로 B가 실행되지 않는 경우와 별개로 어쨌든 링크 이동 동작을 취소
- 콘솔 출력 비교
	- 메서드 통제가 없는 경우 ─ `link A → link B → box2 → box1`
	- `stopPropagation()` ─ `link A → link B` ─ 같은 요소 외 다른 이벤트 차단
	- `stopImmediatePropagation()` ─ `link A` ─ 같은 요소의 다른 이벤트도 차단
- target / currentTarget 값
	- target은 어느 리스너가 실행되든 항상 span 
		- 단, 자식 요소 밖의 마진 영역 (부모 요소의 패딩 영역) 을 클릭할 경우 target은 부모 요소가 된다. 
	- currentTarget은 전파 경로를 따라 리스너가 붙은 요소를 가리킨다. (캡처링, 버블링도 구분해서 붙음)
		- 단, 전파가 끝난 후에는 `e.currentTarget`이 `null`이 되기 때문에 필요시 핸들러 안에 변수 할당 필요
# 타이머 콜백

- *cf.* 이벤트 콜백함수가 이벤트 발생 시 실행되는 비동기식 작동이라는 점과 비교
	- 시간지연 콜백함수는 그 시간이 도래했을 때 실행되는 비동기식 작동 → 이벤트 콜백함수와 같은 구조
	- `setTimeout(이벤트핸들러, 지연시간);` ─ 지연실행, 이벤트핸들러 함수를 대기상태로 두었다가 호출
	- `setInerval(이벤트핸들러, 지연시간);` ─ 반복지연실행, `clearInterval(핸들러등록번호);`로 취소 가능
```js
setTimeout(function(){  // 등록된 이벤트 핸들러 등록번호 반환 → 등록된 이벤트 핸들러 취소 시 활용
	                    // 이벤트 핸들러 취소: clearTimeout()
    console.log("지연실행");
}, 3000);               // 1000 = 1초
console.log("실행완료"); // "실행완료" 출력 → 최소 3초 후 → "지연실행" 출력
```

> [!NOTE] 자바스크립트는 싱글 스레드 언어
> - 스레드 ─ 작업자, 작업단위. 콜스택과 실행영역함수로 구성 (콜스택은 함수가 실행되기 위한 메모리 영역)
> - 자바스크립트는 콜스택이 하나뿐인 싱글 스레드 방식을 채택 → 한 번에 함수 하나만 실행
> 	- 싱글 스레드라서 비동기식 방식이 필요해졌다. (처리를 위해 마냥 기다릴 수는 없으니까)
> 	1. 자바스크립트 스레드는 기다리는 일을 브라우저에게 넘기고 (브라우저가 따로 처리하고) 
> 	2. 끝난 작업은 이벤트 루프가 순서대로 스레드에 전달 (콜백이 큐에 들어옴) 하고 한가할 때 실행시켜준다.

# WebAPI
- 기다리는 일, 조건이 되면 콜백을 큐에 넣는 역할
- 자바스크립트 언어 자체의 기능이라기보다 브라우저가 제공하는 기능에 가깝다. 
	- 자바스크립트에서는 함수나 객체 형태로 코드처럼 쓸 수 있다. 
	- 실제 처리는 자바스크립트 스레드가 아니라 브라우저 스레드가 행한다. 

|                            | 분류      | 설명                   |
| -------------------------- | ------- | -------------------- |
| `setTimeout`               | Web API | 시간이 지나면 콜백 호출        |
| `setTimeout`에 넘기는 함수       | 콜백 함수   | 타이머 콜백 (시간지연 콜백)     |
| `addEventListener`         | Web API | 이벤트가 발생하면 콜백 호출      |
| `addEventListener`에 넘기는 함수 | 콜백 함수   | 이벤트 콜백 (이벤트 핸들러/리스너) |
# async
- HTML \<script async> 속성 ─ 스크립트 파일을 HTML 파싱과 동시에 내려 받고 다운로드 완료시 즉시 실행
- 자바스크립트 `async` 키워드 ─ 함수가 항상 Promise를 돌려주고 함수에 `await` 사용을 가능하게 하는 문법
```js
button.addEventListener('click', async function () {  // Promise로 감싼 return 반환
  const res = await fetch('/api/data');               // 대기 상태의 Promise 반환
  ... });
```
## Promise
- 지금은 없지만 나중에 도착할(콜백할) 결과를 담은 객체
- Promise가 끝났을 때 then 콜백을 마이크로태스크 큐에 넣어 콜백 실행
	- 콜백만 사용할 경우 요청 → 응답 → 다음 요청이 중첩돼서 읽기 어려워지는 현상을 방지 (`then` 체인 사용)
	- 단계마다 에러를 확인해야 하는 콜백 방식과 달리 어디서든 에러가 발생하면 `catch`에서 확인 가능
	- `Promise.race`, `Promise,allSettled` 등으로 응답이 온 (요청에 대한 상태가 반환된) 개수 셈 가능
	- `await`는 Promise만 기다려 줌 → Promise를 돌려주거나 Promise로 감싸면 `async/await` 사용 가능
		- *cf.* `async/await` ─ `then` 체인을 동기 코드처럼 읽히게 만든 문법
			- `await`는 함수 안에서만 기다리기 때문에 자바스크립트 스레드는 멈추지 않고 함수만 일시중단 된다.
			- `await` 뒤의 코드는 `then` 콜백처럼 마이크로태스크로 처리된다. 
- 상태값 ─ pending(대기), fulfilled(성공: 결과 반환), rejected(실패: 에러 발생)
```js
/* then 체인 방식 */ 
fetch('/api/data')                            // URL로 HTTP 요청 → Promise(pending) 반환
  .then(res => {
    if (!res.ok) throw new Error('서버 오류'); // 이렇게 던지면 catch로 감
    return res.json();                
    // fetch는 404, 500 응답도 Promise(fulfilled) 처리하므로 서버 오류를 직접 확인해야 한다.
  })
  .then(data => console.log(data))
  // 성공 실행 예약 → 응답이 오면(Promise(fulfilled)) 콜백 실행
  .catch(err => console.error(err));
  // 실패 실행 예약 → 어디서든 실패(Promise(rejected))하면 남은 then도 건너뛰고 catch 실행
console.log("다음 줄"); // WebAPI(fetch)에 아직 응답이 없으면 바로 실행

/* async/await 방식 */
async function load() {
  try {
  
    // URL로 HTTP 요청 → Promise(pending) 반환, 이 함수만 대기
    const res = await fetch('/api/data');
    
    // fetch는 404, 500도 fulfilled 처리하므로 직접 확인, 던지면 catch로 감
    if (!res.ok) throw new Error('서버 오류');
    
    // 응답 본문을 JS 객체로 변환 (이것도 Promise)
    const data = await res.json();
    
    // 응답이 온 뒤에 실행
    console.log(data);
    
  // 어디서든 실패(rejected)하거나 throw되면 남은 코드는 건너뛰고 여기로
  } catch (err) { 
    console.error(err);
  }
}
load();
console.log("다음 줄"); // load()가 첫 await에서 중단되고 스택이 풀리므로 바로 실행
```

|then 체인|async/await|
|---|---|
|`fetch(...)`|`const res = await fetch(...)`|
|`.then(res => { if (!res.ok) ...; return res.json(); })`|`if (!res.ok) throw ...;` 와 `const data = await res.json();`|
|`.then(data => console.log(data))`|`console.log(data);`|
|`.catch(err => ...)`|`try { ... } catch (err) { ... }`|

> [!NOTE] 비동기 작업의 두 가지 흐름
> - 콜백만 쓰는 경우 
> `setTimeout(콜백, 3000)`
> → Web API가 3초 대기 → 만료되면 콜백을 태스크 큐에 넣음 
> → 이벤트 루프가 스택이 비면 콜스택으로 옮김 → 콜백 실행
> - Promise를 쓰는 경우 
> `fetch('/api')`
> → Web API가 서버 응답 대기 → 응답이 오면 Promise가 성공 상태로 바뀌고 결과값을 보관 
> → then 콜백을 마이크로태스크 큐에 넣음 
> → 이벤트 루프가 스택이 비면 콜스택으로 옮김 → then 콜백 실행 (결과값을 받음)
> 
> |                       | 구현 주체          | 처리하는 곳                            |
| --------------------- | -------------- | --------------------------------- |
| `setTimeout`, `fetch` | 브라우저 (Web API) | 브라우저 스레드                          |
| `Promise`             | 자바스크립트 엔진      | JS 스레드 (`then` 콜백은 마이크로태스크 큐로 이동) |

# Ajax
- Asynchronous JavaScript And XML
- 페이지를 새로고침하지 않고 백그라운드에서 서버와 데이터를 주고 받아 화면의 일부만 바꾸는 방식
	- 네트워크 요청을 Web API가 처리 → `setTimeout`과 동일한 구조 (타이머 대신 서버 응답을 기다림)
	- *e.g.* 검색창 자동완성, 좋아요 버튼 등
- 이름에는 XML이 들어가지면 지금은 대부분 JSON으로 쓴다. 
```js
fetch('/api/posts')
  .then(res => res.json())        // 응답 본문을 JS 객체로 변환
  .then(posts => {
    // 받은 데이터로 화면 갱신 (Ajax의 핵심)
  });
```
