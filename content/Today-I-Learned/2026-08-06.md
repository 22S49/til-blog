	- 프로젝트마다 가상 환경을 구축하고 프로젝트에 맞게 사용
- 파이썬 자체에서 가상환경 지원 ⇢ 속도가 느리고, 의존성 문제가 자주 발생 (하나 설치하면 다른 게 안됨)
	- python -m venu …
	- 아나콘다
- 파이썬 가상환경 지원 외부도구 ⇢ 의존성을 동일한 환경으로 구축할 수 있음 
	- uv
		- rust 기반으로 속도가 빠름
		- 프로젝트 단위 관리에 유용
		- 의존성  궁합이 잘 맞음
		- 단, 정식 버전이 아니어서 버전 변경이 잦음
		- powershell에서 설치해야 함
#### 버전표기 방식
- e.g. 0.12.2
	- 첫째 자리: 메이저 버전
		- 하위 버전과 호환 불가
	- 둘째 자리: 마이너 버전
		- 하위 버전과 호환 가능 & 기능 추가 or 작은 변경
		- 근데 파이썬은 마이너 버전이 올라갔는데 호환이 안되는 경우도 있음
	- 셋째 자리: 패치 버전
		- 취약점 수정, 버그 수정, 코드 개선
		- 패치 버전이 0인 경우 버그가 많을 수 있다는 의미일 수 있음
#### uv 프로젝트 생성 + 가상환경 구축
- uv init
	- 보통 파이썬 최신 버전을 다운 받음, 버전 지정이 필요할 땐 —python 3.13 (메이저, 마이너 버전까지)
	- 현재 폴더에서 만들거나 uv init "프로젝트명"
- pyproject.toml
	- 가상환경 명세 ⇢ 공동 작업 시 공유해서 같은 환경에서 개발할 수 있도록 함
	- 라이브러리가 추가되면 명세에도 관련 내용이 추가됨
- 환경변수를 적용하는 시점에 따라서 uv 명령어가 안 먹힐 때도 있음 ⇢ cmd 재시작
- .venv
	- 최초 실행, 명세(의존성 추가), 싱크 ⇢ 가상환경이 생성됨 ⇢ 활성화 ⇢ 가상환경 사용 가능
	- .venv\Scripts\activate
	- 소괄호 안에 내 프로젝트 폴더명이 뜨면 이 프로젝트에서 가상환경이 활성화되었다는 의미
		- e.g. (02-python) C:\Users\AX0130\Documents\ax_study\02_PYTHON>
	- 가상환경 비활성화
		- .venv\Scripts\deactivate.bat
	- 깃허브에는 이 가상환경을 올리지 않음
- uv sync
	- pyproject.toml 파일이 있는 그 환경에서 사용하면 명세에 따라 가상환경이 일괄 설치됨
	- 기존 제약조건 등을 수정하고 한 경우에는 반드시 uv sync 해주어서 같은 환경을 만들어야 함
	- requires-python (제약조건)
		- e.g. ">=3.13" ⇢ 3.13 이상의 버전으로만 변경할 수 있음
		- 필요 시 제약조건 자체를 변경할 수 있음
- 파이썬 버전 변경 설치: uv python pin 3.13 
- 파이썬 파일을 실행할 때, 파이썬 명령어를 써도 되지만 대부분 uv 환경에서는 uv 명령어 사용
- main.py
	- uv 0.12부터 main.py 파일 자동 생성하지 않음
	- main.py 직접 만들거나 기타 작업파일로 시작해야 함
	- 진입점 함수 구조
		- 프로그램이 시작될 때 가장 먼저 실행되는 함수 (여기부터 시작하라고 알려주는 역할)
		- `if __name__ == "__main__":` 
			- 핵심 구문, 이 파일을 직접 실행할 때만 `main()`을 호출하고, 다른 파일에서 import해서 쓸 때는 자동 실행되지 않도록 막아주는 역할
		```
	def main():          # 1. 함수 정의
	    print("Hello!")  # 2. 실행할 코드

	if __name__ == "__main__":  # 3. 이 파일이 직접 실행될 때만
	    main()                  # 4. main 함수 호출
		```

#### 변수와 동적 타이핑
- 변수
	- 특정 값에 접근하기 위한 이름표
	- 값을 가진 공간의 주소를 가진 이름표
	- 메모리에 있는 답을 참조하는 것, 변수 = 참조 = 레퍼런스
	- 값이 바뀔 때마다 가르키는 주소도 달라짐
	- 변수명 사용 가능 문자: 영문(대소문자), 숫자, $, _
	- 한글도 가능하지만 권장하지 않음, 되도록 공통어를 사용하는 것이 좋음
	- 숫자는 변수명 맨 앞에 올 수 없음
	- 변수명에는 공백을 포함할 수 없음
	- 예약어는 변수명으로 사용할 수 없음 (if, for, while, true, ...)
	- 전체 코드는 하나의 문장처럼 읽혀야 함, 따라서 변수명은 의미 있는 단어로 활용 권장
	- 여러 단어 구성은 언더바로 구분 (스네이크 케이스)
	- 변하지 않는 변수명은 대문자로 구성
- 자료
	- 연산에 사용되는 값
	- 자료형: 자료의 종류 (숫자형(float, int), 문자형(str), 논리형(bool))
	- 동적 타이핑: 입력된 자료를 인식해서 자료형을 자동으로 지정 
		- vs. 정적 타이핑: 내가 직접 자료형을 수동으로 지정
#### garbage collector
- x에 새로운 값이 대입되면서, 기존에 있던 주소 삭제
	- 필요 없는 값이니까 제거해서 메모리를 효율적으로 사용
-  예전에는 값을 선언하고 기존 메모리를 직접 삭제했었는데
	- 요즘 언어들은 garbage collector 내재로 메모리를 자동으로 회수
- 근데 중간에 다른 값을 할당했다가 돌아왔을 때, 기존 메모리를 제거하지 않고 주소를 다시 참조
	- 극한의 효율을 추구하는 파이썬의 특징
	- 많이 쓰는 범위의 값들은 그 공간이 이미 만들어져 있고 그 공간을 쓰기 때문 (예: 숫자 20, 10 등)

### 오늘의 퀘스트
#### 1번 문항
- **Q**. uv init 명령어를 프로젝트 폴더에서 실행했을 때 즉시 일어나는 일로 가장 올바른 것은 무엇인가요?
- **A**. pyproject.toml, .python-version, main.py 등 기초 명세 파일들만 생성된다
- *uv init은 프로젝트의 기초 메타데이터 파일만 생성하며, 실제 파이썬 다운로드와 가상환경(.venv) 구축은 이후 uv run이나 uv add를 실행하는 시점에 이루어집니다. 나머지 선지는 실제 uv의 동작과 다른 내용입니다.*
#### 2번 문항
- **Q**. 파이썬 공식 표준 규격(PEP 621)을 따르며 프로젝트 이름, 버전, 의존성 등을 하나의 파일로 통합 관리하는 선언적 명세서 파일의 이름을 쓰세요.
- **A**. pyproject.toml
- *pyproject.toml은 requirements.txt나 setup.py 등으로 파편화되어 있던 설정을 하나로 통합한 현대 파이썬의 표준 명세서 파일입니다.*
#### 3번 문항
- **Q**. uv init으로 만든 가상환경(.venv)에서 주피터 노트북 셀을 정상적으로 실행하기 위해 반드시 추가로 설치해야 하는 패키지는 무엇인가요?
- **A**. ipykernel
- *ipykernel은 주피터 UI와 가상환경 내부 파이썬 인터프리터 간의 통신을 중계하는 핵심 엔진으로, uv add ipykernel 명령어로 프로젝트별 가상환경에 개별 설치해야 합니다. 나머지는 데이터 분석용 라이브러리로 통신 엔진과는 무관합니다.*
#### 4번 문항
- **Q**. REPL(Read Evalute Print Loop, 대화형 셸) 방식과 스크립트(.py) 구동 방식을 비교한 설명으로 옳지 않은 것은 무엇인가요?
- **A**. REPL은 터미널 세션을 종료해도 작성한 코드가 메모리에 그대로 유지된다
- *REPL은 휘발성을 가져 터미널이나 세션을 종료하면 작성했던 코드가 메모리에서 모두 사라집니다. 반대로 스크립트 방식은 파일로 저장되어 영속성을 갖습니다.*
#### 5번 문항
- **Q**. 파이썬에서 변수에 새로운 값을 재할당하면, 기존 데이터가 아닌 새 데이터의 메모리 주소를 가리키게 됩니다. 이때 재할당 전후로 변수가 가리키는 메모리 주소값이 바뀌었는지 확인할 수 있는 내장 함수는 무엇인가요?
- **A**. id()
- *id() 함수는 변수가 참조하는 객체의 메모리 고유 주소값을 반환하므로, 재할당 시 주소가 새 데이터로 바뀌는 것을 눈으로 확인할 수 있습니다. type()은 자료형을 확인하는 함수로 주소 확인과는 다릅니다.*
