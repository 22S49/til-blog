#### 드롭아웃 기법
- 딥러닝에서 과적합을 방지하기 위한 규제(Regularization) 기법
- 영향력이 강한 가중치가 계속 커지면 과적합이 발생 ⇢ 일정 비율의 출력을 랜덤하게 0으로 변경 (드롭아웃)
- 영향력이 강한 가중치의 출력이 0으로 변경 ⇢ 작은 가중치도 학습을 통해 큰 가중치가 될 수 있음 ⇢ 일반화
	- 일반화
		- 실제값에 너무 가까운 그래프(예측값)가 아닌 조금 러프한 그래프(예측값)가 그려지도록 한다. 
		- e.g. 총합이 100이 되어야 하는 식이 있음. 
			- 어떤 항의 가중치를 임의로 0으로 바꾸면 100을 맞추기 위해 다른 항의 가중치를 높이는 원리
- 예측할 때에는 쓰지 않고 학습할 때만 쓴다. **(중요)** 훈련할 때만 일반화 해서 편중되지 않도록 골고루 학습
- 드롭아웃 비율은 정해진 것은 없음 ⇢ 연구의 영역이며 일반적으로 20%~50%로 설정하는 경향

❌ 에러 1: torch.cuda.is_available() → False

원인: PyTorch가 CPU 버전으로 설치됨

해결: pip uninstall torch torchvision torchaudio 후 위의 CUDA 버전 명시 명령어로 재설치 ⇢ 가상환경 껐다 끄기

❌ 에러 2: CUDA error: no kernel image is available for execution on the device

원인: GPU 아키텍처와 PyTorch 빌드 버전 불일치 (특히 RTX 30xx, 40xx 시리즈)

해결: PyTorch 최신 버전으로 업그레이드 또는 nightly 버전 설치

❌ 에러 3: RuntimeError: CUDA out of memory

원인: GPU 메모리 부족

해결:

- batch_size 줄이기

- torch.cuda.empty_cache() 호출

- mixed precision 학습 사용 (torch.cuda.amp)

❌ 에러 4: DLL load failed / ImportError

원인 (Windows): Visual C++ Redistributable 또는 CUDA 툴킷 미설치

해결: [https://visualstudio.microsoft.com/downloads/](https://visualstudio.microsoft.com/downloads/) 에서 재배포 가능 패키지 설치

#### RNN
- 순환신경망, 시계열 데이터에 특화된 모델 ⇢ 순서를 기억하는 모델
- 문장(자연어) 데이터도 시계열 데이터 — 어순에 따라 의미가 완성되기 때문
	- 원핫 인코딩을 이용하면 차원의 저주 발생
		- 단어와 단어 사이에 유의미한 관계를 파악하기 어려움 — 임베딩 필요
	- 임베딩(Embedding) — 지정된 작은 차원의 실수 값으로 압축 (차원 축소)
		- 단어와 단어 사이에 유의미한 관계를 파악하기 위해 사용 (유의미성을 파악하기 위한 도구)
		- 실수 값 = 실수 밀집 벡터 = 의미성이 있는 값
- **입력층 ⇢ 선형결합(가중합) ⇢ 활성화 함수 ⇢ 은닉층 출력 ⇢ 선형결합(로짓) ⇢ 활성화 함수 ⇢ 출력층 출력**

##### 임베딩
- 임베딩을 추가하면 모델 파라미터가 추가된다. — 입력 가중치, 절편, *new!* 순환 가중치
- 임베딩 가중치 행렬 (순환 가중치)
	- 실수 밀집 벡터를 만들기 위한 가중치 행렬
	- 처음에는 어떤 벡터가 중요한지 모르니까 무작위로 가중치 초기화
	- 랜덤 초기화 ⇢ 학습 ⇢ 역전파 ⇢ 가중치 업데이트 반복하면서 의미성을 파악한다.
- 임베딩 인덱스 개수
	$$\text{Embedding}(w) = \text{One-Hot}(w) \times W_{emb} = v$$
	
	- e.g. 1000개 단어 ⇢ 임베딩 층 ⇢ 각 단어가 실수값으로 변환

> [!NOTE] Title
> ## 임베딩(Embedding)
- 모듈 개념으로 이해 
- 임베딩만 하고 임베딩 값을 다르게 활용할 수 있음 
- 우리가 배운 머신러닝 분야에서는 임베딩이 레이어(층)에 전달하고 연산헤 활용하는 개념으로 배움


##### 순환층
- DNN의 은닉층과 같은 역할 — 추가로 시계열 정보, 즉 은닉 상태를 포함한다. 순서를 기억한다. 
- 은닉 상태
	- 앞 선 타임스텝의 맥락을 가지고 있는 값. 맥락 데이터. 컨텍스트 벡터
	- 맥락을 위한 가중치를 추가로 가지고 있다. 재귀학습한다. (재귀학습 대상: 셀) ⇢ 느리다.
	- 선형결합(원시점수)에 활성화 함수를 적용한 결과
	- 재귀학습의 재료가 된다. 
		- 해당 타임스텝의 출력 재료이자 다음 타임스텝의 원시점수 계산 재료
	- 최종 은닉 상태는 모든 타임스텝을 표현한다.
		- 병목현상이 발생할 수 있기 때문에 오랜 단계의 스텝은 기억하지 못하는 장기의존성 문제 발생
			- 해결 방안 — LSTM (Long Short Term Memory)
				- 단기기억 — 은닉 상태
				- 장기기억 — 셀 상태
				- LSTM에서의 컨텍스트 벡터 = 은닉 상태 + 셀 상태

##### 셀(Cell)
- 매 타임스텝마다 반복 적용되는 하나의 연산 단위
	- 셀 구성 — 선형결합 ⇢ 활성화 함수 ⇢ 은닉 상태 계산
- 순환층을 시간축으로 펼쳤을 때 각 타임스텝에서 실행되는 계산 블록
- 은닉 상태의 차원을 구성하는 여러 개의 노드들로 구성 (셀 ⊃ 노드)
- 셀을 펼쳐보면 여러 개의 타임스텝과 그 안에 여러 개의 노드들로 구성된다. 
	- 순환신경망은 결과뿐만 아니라 그 결과의 맥락(순서) 정보를 같이 연산해야 하므로 
	  노드를 재료로 임베딩 연산이 적용되고 그 연산(셀)은 타임스텝만큼 반복된다. 
- LSTM에서는 은닉 상태와 함께 컨텍스트 벡터의 요소가 된다. 

##### 타임스텝(TimeStep)
- 셀을 몇 번 호출했는지 나타내는 순서. 셀 전체가 한 번 완전히 실행 = 타임스텝 하나
	- e.g. 첫 번째 셀 = 여러 개 셀 중에 하나가 아니라 첫 번째 반복으로 해석
- 동일한 파라미터(가중치)를 가진 셀 하나가 매 타임스텝마다 재사용되는 것 (재귀)
	- 따라서 ReLU를 사용하게 되면 가중치가 뻥튀기 되는 현상이 발생 ⇢ 기술기 소실 문제 발생
	- ReLU의 기울기 소실 문제 해결을 위해 하이퍼볼릭 탄젠트 함수 사용 (-1에서 1사이로 압축)
		- 그런데 이것도 타임스템이 많아질 수록 병목현상이 발생할 수 있어서 LSTM으로 보완

- **순환층**은 이 전체 구조를 감싸는 개념이야. 하나의 순환층이란 사실 "같은 셀 하나를 타임스텝마다 반복해서 적용한 것"을 말해. 그래서 그림처럼 t-1, t, t+1로 옆으로 펼쳐 놓으면 마치 여러 개처럼 보이지만, 실제로는 **동일한 셀(같은 가중치)이 매 타임스텝마다 재사용**되는 거야.
- **타임스텝**은 그 반복이 일어나는 시점 하나하나. 각 타임스텝마다 셀은 그 시점의 입력(x_t)과 이전 타임스텝에서 넘어온 은닉 상태(h_{t-1})를 받아서, 새 은닉 상태(h_t)를 계산해 다음 타임스텝으로 넘겨줘. 그림의 가로 화살표가 이 흐름이야.
- **셀**은 그 타임스텝 하나에서 실행되는 연산 단위. "입력 + 이전 은닉 상태 → 새 은닉 상태"를 계산하는 수식(가중치 행렬과 활성화 함수)이 들어있는 블록이라고 보면 돼.
- **노드(유닛)**는 셀 안에서 은닉 상태 벡터를 구성하는 개별 원소들. 노드 개수 = 은닉 상태의 차원 수야. 그림에서 셀 안의 파란 점 4개가 "이 셀은 4차원 은닉 상태를 가진다"는 뜻이라고 생각하면 돼.

정리하면 순환층 > 임베딩 > (반복되는) 셀 > (그 안의) 노드, 이고 타임스텝은 그 반복이 일어나는 시간축의 단위야.

`nn.Linear`(완전연결층, Fully Connected Layer)의 구조 때문입니다.

**이유**

`nn.Linear(784, 128)`은 내부적으로 (128, 784) 크기의 가중치 행렬을 가지고, 입력 벡터와 **행렬곱(matrix multiplication)**을 수행합니다. 행렬곱을 하려면 입력이 1차원 벡터 형태여야 합니다. 즉 `nn.Linear`는 애초에 "2차원 이미지"라는 개념을 모릅니다. 그냥 숫자들이 쭉 나열된 벡터를 받아서, 각 출력 뉴런이 그 벡터의 모든 원소에 가중치를 곱해서 더하는 연산을 할 뿐입니다.

그런데 이미지는 (28, 28) 형태, 즉 세로/가로라는 2차원 공간 구조를 가지고 있죠. 이걸 그대로 `nn.Linear`에 넣을 수 없으니, `flatten`으로 (28,28) → (784,)로 펴서 "784개의 숫자가 나열된 벡터"로 만들어주는 겁니다.

반대로 `nn.Conv2d`(합성곱층)는 2차원 구조를 그대로 유지하면서 처리하기 때문에 flatten이 필요 없고, 오히려 flatten을 하면 공간 정보를 잃어버려서 성능이 떨어집니다. CNN을 배우게 되면 이 차이를 더 명확히 느끼실 거예요.

### 코드 스타일 차이 체감 포인트

**모델 정의**

케라스는 이렇게 레이어를 쌓는 식이고:

python

```python
model = keras.Sequential([
    keras.layers.Flatten(input_shape=(28, 28)),
    keras.layers.Dense(128, activation='relu'),
    keras.layers.Dense(10, activation='softmax')
])
```

파이토치는 클래스를 상속받아서 직접 forward 로직을 씁니다:

python

```python
class Net(nn.Module):
    def __init__(self):
        super().__init__()
        self.fc1 = nn.Linear(28*28, 128)
        self.fc2 = nn.Linear(128, 10)

    def forward(self, x):
        x = x.view(-1, 28*28)
        x = torch.relu(self.fc1(x))
        return self.fc2(x)
```

**학습 루프**

- 케라스는 `model.compile()` → `model.fit()` 두 줄이면 학습이 끝나는 반면
- 파이토치는 `for epoch in range(...):` 안에서 순전파, 손실 계산, `loss.backward()`, `optimizer.step()`을 직접 다 작성해야 합니다.

### 리스트 인덱싱과 다른 점 (주의할 부분)

튜플은 **불변(immutable)** 이라서, 인덱싱으로 값을 읽는 건 되지만 값을 바꾸는 건 안 돼요.

python

```python

t[0]        # 10 - 읽기는 OK
t[0] = 100  # TypeError! - 수정은 불가능
```

리스트였다면 `lst[0] = 100`처럼 수정이 가능했겠지만, 튜플은 한 번 만들어지면 내용을 바꿀 수 없다는 게 핵심 차이입니다.

LSTM(Long Short-Term Memory)에서 이 역할을 하는 컴포넌트는 **셀 상태(Cell State), 기호로는 CtC_t Ct​**입니다.

**구조적 특징**

셀 상태는 은닉 상태(hidden state, hth_t ht​)와는 별도로 존재하는 "정보의 컨베이어 벨트" 같은 경로입니다. 매 타임스텝마다 아래와 같이 갱신됩니다.

Ct=ft⊙Ct−1+it⊙C~tC_t = f_t \odot C_{t-1} + i_t \odot \tilde{C}_tCt​=ft​⊙Ct−1​+it​⊙C~t​

- ftf_t ft​: 망각 게이트(forget gate) — 이전 셀 상태 Ct−1C_{t-1} Ct−1​ 중 얼마를 유지할지 결정 (0~1 값)
- iti_t it​: 입력 게이트(input gate) — 새 후보 정보 C~t\tilde{C}_t C~t​ 를 얼마나 반영할지 결정
- ⊙\odot ⊙: 원소별 곱(element-wise product)

**정보 유실 방지에 기여하는 방식**

1. **덧셈 기반 갱신 (Additive Update)**  
    셀 상태는 비선형 활성화 함수(tanh, sigmoid)를 반복적으로 통과하며 값이 곱해지는 구조가 아니라, 게이트로 조절된 값을 **더하는** 방식으로 갱신됩니다. 일반 RNN의 은닉 상태처럼 WW W 행렬을 매 스텝 곱하지 않기 때문에, 역전파 시 그래디언트가 ftf_t ft​ 값에 의해서만 스케일링됩니다.
2. **그래디언트 소실 완화**  
    일반 RNN의 그래디언트는 시간을 거슬러 올라가며 가중치 행렬과 활성화 함수 미분이 계속 곱해져 지수적으로 작아지거나(vanishing) 커지는(exploding) 문제가 있습니다. 반면 셀 상태를 통한 역전파 경로는 ∂Ct/∂Ct−1=ft\partial C_t / \partial C_{t-1} = f_t ∂Ct​/∂Ct−1​=ft​ 형태로, 망각 게이트가 1에 가까운 값을 유지하면 그래디언트가 거의 감쇠 없이 먼 과거까지 전달될 수 있습니다. 이를 흔히 **"constant error carousel"**이라 부릅니다.
3. **선택적 기억/망각**  
    망각 게이트 ftf_t ft​와 입력 게이트 iti_t it​가 학습을 통해 "어떤 정보를 오래 유지하고 어떤 정보를 버릴지"를 데이터로부터 스스로 조절하므로, 불필요한 과거 정보는 걸러내고 중요한 장기 의존성만 셀 상태에 누적시킬 수 있습니다.

정리하면, 셀 상태 CtC_t Ct​는 게이트로 통제된 덧셈 갱신 구조 덕분에 역전파 경로에서 그래디언트가 급격히 소실되지 않도록 하여, 시퀀스 초반의 정보가 뒤쪽 타임스텝까지 유실되지 않고 전달될 수 있게 합니다.
인코더가 시퀀스의 마지막 타임스텝까지 처리를 마치면, LSTM은 **은닉 상태 hTh_T hT​**와 **셀 상태 CTC_T CT​** 두 가지를 최종 출력으로 갖게 됩니다 (T는 입력 시퀀스의 마지막 타임스텝). 이 둘을 묶어서 디코더의 초기 상태로 전달하는 구조를 설명하면 다음과 같습니다.

**1. 두 상태의 역할 분리**

- hTh_T hT​: 인코더가 지금까지 읽은 문장의 "요약된 표현" — 다음 출력을 만드는 데 직접 쓰이는 정보
- CTC_T CT​: 장기적으로 보존해온 내부 기억 — 게이트를 통해 조절되며 축적된 문맥 정보

이 둘은 서로 다른 역할을 하기 때문에 하나로 합쳐지지 않고, **튜플 형태로 함께 전달**됩니다.

context=(hT,CT)\text{context} = (h_T, C_T)context=(hT​,CT​)

**2. 디코더로의 전달 방식**

디코더도 동일한 LSTM 구조이므로, 자신의 초기 상태 (h0dec,C0dec)(h_0^{dec}, C_0^{dec}) (h0dec​,C0dec​)가 필요합니다. 인코더-디코더 구조에서는 이 초기 상태를 인코더의 최종 상태로 그대로 초기화합니다.

h0dec=hTenc,C0dec=CTench_0^{dec} = h_T^{enc}, \quad C_0^{dec} = C_T^{enc}h0dec​=hTenc​,C0dec​=CTenc​

즉, 인코더의 "마지막 순간의 은닉 상태"와 "마지막 순간의 셀 상태"가 각각 디코더 LSTM 셀의 hh h, CC C 입력 슬롯에 그대로 꽂히는 구조입니다. 디코더는 이 초기 상태로부터 출발해서, 매 스텝 자신이 생성한 이전 출력 토큰(보통 `<sos>`로 시작)을 입력으로 받아 다음 토큰을 순차적으로 생성합니다.

**3. 구조적 의미**

- 이 방식에서는 인코더가 처리한 전체 입력 시퀀스의 정보가 **고정 크기의 벡터 쌍 (hT,CT)(h_T, C_T) (hT​,CT​) 하나로 압축(bottleneck)**됩니다.
- 디코더는 입력 문장을 직접 보지 못하고, 오직 이 압축된 상태만으로 전체 디코딩 과정을 진행해야 합니다.
- 이것이 바로 기본 Seq2Seq 구조의 한계로 지적되는 지점입니다 — 문장이 길어질수록 hTh_T hT​ 하나에 모든 정보를 압축해야 하므로 정보 손실이 발생하기 쉽고, 이를 해결하기 위해 이후 **어텐션(Attention) 메커니즘**이 도입되어 디코더가 인코더의 모든 타임스텝 은닉 상태 h1,...,hTh_1, ..., h_T h1​,...,hT​에 접근할 수 있도록 확장됩니다.


**1. 컨텍스트 벡터 크기가 고정되는 이유**

LSTM의 은닉 상태 hth_t ht​와 셀 상태 CtC_t Ct​는 셀 내부의 가중치 행렬 크기(hidden dimension, dd d)에 의해 차원이 결정됩니다. 이 차원은 모델 설계 시 미리 정해진 하이퍼파라미터이며, 타임스텝마다 갱신되긴 하지만 **차원 자체는 변하지 않습니다**.

입력 시퀀스가 몇 개의 토큰으로 구성되든, 인코더는 각 스텝에서 같은 크기의 ht∈Rdh_t \in \mathbb{R}^d ht​∈Rd, Ct∈RdC_t \in \mathbb{R}^d Ct​∈Rd를 계속 업데이트할 뿐이므로, 마지막 스텝의 (hT,CT)(h_T, C_T) (hT​,CT​)도 항상 Rd\mathbb{R}^d Rd 크기를 유지합니다. 즉 문장이 5단어든 50단어든 컨텍스트 벡터의 "그릇 크기"는 동일합니다.

**2. 문장이 길어질 때 앞부분 정보의 변화**

문제는 이 "그릇 크기"가 고정되어 있는데, 담아야 할 정보(전체 시퀀스의 내용)는 문장 길이에 비례해서 늘어난다는 점입니다.

- 문장 초반의 정보는 C1,C2,...C_1, C_2, ... C1​,C2​,... 형태로 셀 상태에 들어간 뒤, 이후 수십~수백 개의 타임스텝을 거치며 매번 망각 게이트 ftf_t ft​와 곱해지고 새로운 정보가 계속 더해집니다.
- 망각 게이트가 완벽하게 1을 유지하지 않는 이상(실제로는 학습된 값이라 대부분 1보다 작음), 초반 정보는 매 스텝 조금씩 감쇠(decay)되며, 동시에 뒤에서 들어오는 새 정보와 같은 고정 차원 공간을 "나눠 써야" 합니다.
- 결과적으로 문장이 길어질수록 초반 단어의 정보는 후반부 정보에 점점 덮어써지듯 희석되어, 마지막 (hT,CT)(h_T, C_T) (hT​,CT​)에는 문장 뒷부분의 정보가 상대적으로 더 강하게 남고 앞부분 정보는 흐릿해지는 경향이 나타납니다.

**3. 현상의 명칭과 해석**

이 현상을 **정보 병목(Information Bottleneck)** 현상이라 부르며, 이로 인해 발생하는 성능 저하는 흔히 **장기 의존성 문제(long-range dependency problem)**의 연장선으로 논의되고, Seq2Seq 맥락에서는 구체적으로 이 압축 구조 자체를 **"bottleneck problem"**이라 지칭합니다.

이름이 붙은 이유를 정보 흐름 관점에서 보면:

- 인코더 → 디코더로 가는 정보의 통로가 오직 (hT,CT)(h_T, C_T) (hT​,CT​)라는 **하나의 좁은 관(pipe)**뿐입니다.
- 병(bottle)의 목처럼, 입력 시퀀스가 아무리 많은 정보를 담고 있어도 이 좁은 구간을 통과할 때는 고정된 용량으로 압축되어야 합니다.
- 병목 지점을 통과하는 과정에서 필연적으로 정보 손실이 발생하고, 특히 병목에서 먼 지점(=문장 초반)일수록 손실 폭이 커집니다.

**1. 병목 현상의 정의**

정보 병목(Information Bottleneck) 현상이란, 가변 길이의 입력 시퀀스가 담고 있는 모든 정보를 인코더가 고정된 차원(dimension)의 벡터, 즉 최종 은닉 상태·셀 상태 (hT,CT)(h_T, C_T) (hT​,CT​) 하나로 압축해야 하는 구조적 제약을 의미합니다. 입력 길이와 무관하게 정보를 전달할 통로의 "용량"이 항상 동일하게 고정되어 있기 때문에, 시퀀스가 길어질수록 압축 과정에서 필연적으로 정보 손실이 발생하는 현상을 가리킵니다.

**2. 장기 의존성 문제의 원인**

- 문장 초반의 정보는 셀 상태 CtC_t Ct​에 저장된 뒤, 이후 수십~수백 개의 타임스텝을 거치며 매 스텝 망각 게이트 ftf_t ft​(0~1 사이 값)와 반복적으로 곱해집니다.
- ftf_t ft​가 1보다 작은 값을 가질 때마다 과거 정보는 조금씩 감쇠(decay)되며, 동시에 매 스텝 새로 입력되는 정보가 같은 고정 차원 공간에 계속 누적되어 초반 정보와 "공간을 경쟁"하게 됩니다.
- 순전파 관점에서는 이런 반복적 감쇠·희석 때문에, 역전파 관점에서는 그래디언트가 여러 스텝을 거슬러 올라가며 작아지는 경향(그래디언트 소실) 때문에, 문장 앞부분의 정보가 학습 과정에서 충분히 강화되지 못하고 최종 상태에 약하게만 반영됩니다.
- 결과적으로 시퀀스 길이가 길어질수록 초반 토큰과 후반 토큰 사이의 의존 관계를 모델이 포착하기 어려워지는 것이 장기 의존성 문제입니다.

이 문제의식이 바로 이후 디코더가 인코더의 마지막 상태 하나가 아니라 **모든 타임스텝의 은닉 상태 h1,...,hTh_1, ..., h_T h1​,...,hT​에 직접 접근**하도록 하는 **어텐션 메커니즘**의 도입으로 이어지게 됩니다.

||장기 의존성 문제|정보 병목 현상|
|---|---|---|
|발생 위치|하나의 RNN/LSTM 내부에서 시간축을 따라|인코더 → 디코더로 넘어가는 "경계 지점"에서|
|원인|그래디언트가 반복 곱셈으로 소실|가변 길이 정보를 고정 크기 벡터에 압축|
|LSTM으로 해결되나?|셀 상태(C_t)의 덧셈 구조 덕분에 어느 정도 완화됨|LSTM을 써도 여전히 남음 — 압축 자체는 구조적 한계라 완화가 안 됨|

**핵심**: LSTM은 셀 상태 덕분에 "타임스텝 내부의" 장기 의존성 문제는 어느 정도 해결했지만, Seq2Seq 구조 자체가 "마지막 순간의 벡터 하나"로 전체를 압축해야 하는 병목은 여전히 남아있었어요. 그래서 문장이 길어지면 결국 초반 정보가 희석되는 현상(=장기 의존성 문제의 증상)이 병목 구조 때문에 다시 나타나는 거죠.

**기존 Seq2Seq+LSTM의 한계 복습**

디코더는 인코더의 마지막 상태 (hT,CT)(h_T, C_T) (hT​,CT​) 하나만 받았죠. 어텐션을 도입하면 디코더가 인코더의 **모든** 타임스텝 은닉 상태 h1,h2,...,hTh_1, h_2, ..., h_T h1​,h2​,...,hT​에 직접 접근할 수 있게 됩니다. 이때 "어느 시점의 정보를 얼마나 참고할지"를 결정하는 게 바로 QKV 구조입니다.

**LSTM 문맥에서 Q, K, V의 정체**

|요소|LSTM/Seq2Seq에서의 실체|
|---|---|
|**Query**|디코더가 현재 스텝에서 갖고 있는 은닉 상태 sts_t st​ (또는 htdech_t^{dec} htdec​) — "지금 이 단어를 생성하려면 입력 문장의 어느 부분이 필요한가?"|
|**Key**|인코더의 각 타임스텝 은닉 상태 h1,...,hTh_1, ..., h_T h1​,...,hT​ (그 자체이거나, 여기에 가중치 행렬을 곱한 변환값) — "이 시점의 정보는 이런 내용이었다"는 색인|
|**Value**|인코더의 각 타임스텝 은닉 상태 h1,...,hTh_1, ..., h_T h1​,...,hT​ (Key와 동일한 벡터를 쓰거나, 별도 변환을 거친 값) — 실제로 가져올 내용물|

**동작 흐름을 LSTM 타임스텝으로 풀면**

1. 디코더가 두 번째 단어를 생성하려는 순간, 자신의 은닉 상태 s2s_2 s2​를 Query로 사용합니다.
2. 이 Query를 인코더의 모든 h1,...,hTh_1, ..., h_T h1​,...,hT​(Key)와 하나씩 유사도 계산합니다.  
    e2,i=score(s2,hi)e_{2,i} = \text{score}(s_2, h_i)e2,i​=score(s2​,hi​)
3. 이 점수들을 softmax로 정규화해서 어텐션 가중치 α2,i\alpha_{2,i} α2,i​를 얻습니다 — "지금 이 단어를 만들 때 입력 문장의 ii i번째 시점이 얼마나 중요한가"
4. 가중치대로 인코더 은닉 상태(Value)들을 섞어서 **컨텍스트 벡터** c2c_2 c2​를 새로 만듭니다.  
    c2=∑iα2,i hic_2 = \sum_i \alpha_{2,i} \, h_ic2​=i∑​α2,i​hi​
5. 이 c2c_2 c2​를 디코더의 다음 계산에 함께 넣어줍니다 (기존의 고정된 CTC_T CT​ 하나 대신, 매 스텝마다 새로 계산되는 동적인 컨텍스트).

**핵심 변화**

- 기존: 디코더가 "인코더 마지막 순간의 기억 (hT,CT)(h_T, C_T) (hT​,CT​)" 하나만 강제로 물려받음 → 병목
- 어텐션 도입 후: 디코더가 매 생성 스텝마다 "지금 필요한 정보(Query)"를 기준으로 인코더의 **모든 시점**(Key로 색인된 h1...hTh_1...h_T h1​...hT​)을 다시 검색해서, 필요한 만큼(Value)만 동적으로 가져옴 → 병목 해소

즉, LSTM의 셀 상태가 "시간축을 따라 정보를 나르는 컨베이어 벨트"였다면, 어텐션의 QKV는 "그 컨베이어 벨트에 의존하지 않고, 필요할 때마다 과거 전체를 직접 검색해서 필요한 부분만 꺼내오는 지름길"을 만들어준 것이라고 볼 수 있습니다. 이 아이디어가 이후 RNN/LSTM 자체를 완전히 걷어내고 어텐션만으로 구성한 **Transformer**로 이어지게 됩니다.
