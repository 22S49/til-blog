# SELECT
- DML에 해당하며 DQL(Date Query Language, 데이터 질의어)라고 하기도 한다.
- 실행 순서
	- FROM ⇢ WHERE ⇢ GROUP BY ⇢ HAVING ⇢ SELECT ⇢ ORDER BY (1차 정렬 ⇢ 2차 정렬)
		- 테이블 확인 ⇢ 조건 충족 행 추출 ⇢ 그룹화 ⇢ 그룹 조건 필터링 ⇢ 조회 컬럼 선택 ⇢ 정렬
```postgresql
-- 모든 열 조회 / SELECT는 SELECT ALL을 기본으로 한다. 
SELECT * FROM 테이블명 LIMIT 조회할행수 OFFSET 시작위치 -- 또는 LIMIT 시작위치, 조회할행수
[WHERE 조건식] 
[GROUP BY 열이름1, 열이름2, …]
[ORDER BY 열이름1 [ASC|DESC], 열이름2 [ASC|DESC], …]; 

-- 특정 열 조회 
SELECT 열이름1, 열이름2, … FROM 테이블명;

-- 중복 없이 특정 열 조회
SELECT DISTINCT 열이름 FROM 테이블명;

-- 중복 없이 특정 열의 조합으로 조회
SELECT DISTINCT 열이름1, 열이름2, … FROM 테이블명;
```
# SQL 조건문
## WHERE
- 조회의 범위를 좁힌다. 
	1. 비교 연산자 ─ >(크다), <(작다), >=(크거나 같다), =(같다) ─ 문자형은 비교 연산자 사용 불가
		- A 이상 B 이하 범위 지정 ─ BETWEEN *A* AND *B*
	2.  논리 연산자 ─ AND(합집합), OR(교집합), NOT(여집합)
		- OR(교집합) 연산자는 IN으로 표현할 수 있다.
			- *e.g.* `WHERE state = 'NY' OR state = 'CA';` = `WHERE state IN('NY', 'CA');`
	3. 포함 여부 ─ IN(포함 시 TRUE), NOT IN(미포함 시 TRUE)
	4. 빈값 확인 ─ IS NULL(값이 빈 상태인지), IS NOT NULL(값이 있는 상태인지) ⇠ 괄호 필수
	5. 패턴 조회 ─ %(와일드카드)를 활용해 패턴 기반 조회 가능
		- LIKE('키워드') ─ 키워드와 정확히 매칭되는 데이터 조회 ⇢ `WHERE IN ('키워드')`와 동일한 조회 결과
		- LIKE('키워드%') ─ 키워드로 시작하는 패턴 조회
		- LIKE('%키워드') ─ 키워드로 종료하는 패턴 조회
		- LIKE('%키워드%') ─ 키워드가 포함된 패턴 조회 
- **(중요)** 집계함수를 포함한 조건 사용 불가 ⇢ 필요시 group by 전용 조건절 having을 사용해야 한다.  ^baac76
## CASE WHEN
- 조건에 따른 다른 값을 부여하는 함수
```postgresql
SELECT 열이름1, 열이름2, …, CASE WHEN 조건식1 THEN 결과1 -- CASE WHEN 앞에 콤마 필수
								WHEN 조건식2 THEN 결과2 
								ELSE 결과3 -- 모든 조건이 거짓일 때 
								END AS 새로운열이름 -- 조건이 끝났음을 알리고 새로운 결과열 생성
						   FROM 테이블명; 
```
# SQL NULL 연산
- 데이터베이스(SQL)에서 NULL은 알 수 없는 값(Unknown) 또는 데이터가 없음을 의미
- NULL에 대한 모든 산술·비교 연산의 결과는 NULL
	- NULL에 어떤 숫자(더하기, 빼기, 곱하기, 나누기 등)를 연산해도 결과는 항상 NULL
	- `NULL = 100`이나 `NULL <> 100` 같은 비교 연산도 참/거짓이 아닌 NULL 반환
	- DB 조회 시 NULL로 인해 값이 사라지는 것을 방지하려면 NULL 처리 함수를 사용해
		- COALESCE ─ 나열된 인자 중 NULL이 아닌 첫 번째 값 반환 (모든 인수가 NULL이면 NULL 반환)
    ```postgresql
    SELECT COALESCE(열이름, 대체값) FROM 테이블명;
    SELECT COALESCE(연락처1, 연락처2, '연락처 없음') FROM 회원; -- 연락처 모두 없으면 '연락처 없음'
    SELECT COALESCE(NULL, 0) + 100; -- 결과: 100 (NULL을 0으로 대체)
    ```

> [!NOTE] AS절 
> - 열이름을 별칭으로 임시 변경한다. (출력 결과 화면에만 별칭으로 보인다.)
> - 테이블을 별칭으로 접근할 수 있도록 한다. 여러 테이블로부터 복합 조회할 때 유용하다. 
> - `SELECT list_price AS price FROM order_items AS oi;`
> - `SELECT list_price AS price FROM order_items oi;` ─ AS 명령어는 생략 가능
# SQL 집계함수
- NULL이 아닌 레코드 개수 ─ `SELECT COUNT(열이름) FROM 테이블명;`
- 합계 ─ `SELECT SUM(열이름) FROM 테이블명;` 
- 평균 ─ `SELECT AVG(열이름) FROM 테이블명;`
- 최소값 ─ `SELECT MIN(열이름) FROM 테이블명;`
- 최대값 ─ `SELECT MAX(열이름) FROM 테이블명;`
## 그룹화 집계 ─ GRUOP BY
 - 특정 컬럼 기준으로 (컬럼의 동일 값 기준으로) 그룹을 만들어 집계함수를 사용한다. 
 - 레코드 개수는 그룹화 된 결과 개수만큼 조회된다. 
 - select 컬럼은 반드시 group by에 명시된 컬럼만 사용해야 한다.
 - group by 전용 조건절 ─ `HAVING 집계함수조건;` [[2026-09-07#^baac76]]
# 테이블 결합
## 행 기준
- 컬럼 구조 (컬럼 명, 컬럼 수, 컬럼 타입) 가 동일한 테이블 간 결합을 전제로 한다. 
- 합집합 ─ UNION ─ 중복 제거를 기본값으로 서로 합한다.
```postgresql
SELECT order_id, order_date FROM orders
WHERE order_date <= '2016-01-17' -- 행 46개
UNION -- 행 1,615개 (중복제거)
SELECT order_id, order_date FROM orders
WHERE order_date >= '2016-01-15' ORDER BY order_date; -- 행 3,190개
```
- 교집합 ─ INTERSECT ─ 공통적인 것만 추출한다.
```postgresql
SELECT order_id, order_date FROM orders
WHERE order_date <= '2016-01-17'
INTERSECT
SELECT order_id, order_date FROM orders
WHERE order_date >= '2016-01-15' ORDER BY order_date;
```
- 차집합 ─ EXCEPT ─ 가장 왼쪽 컬럼을 기준으로 공통적인 것을 제외한다.
## 열 기준
- 컬럼 구조가 달라도 공통키 (일반적으로 PK와 FK) 를 가지고 있는 경우 데이터 간 결합이 가능하다. 
- 무작위 열 결합 ─ `SELECT * FROM 테이블명1, 테이블명2, …;`─ 카테시안 곱, 데카르트 곱
- 조건부 열 결합
	- 두 테이블을 (열이름이 다르더라도) 공통적인 값을 기준으로 하나처럼 조회될 수 있게 결합 ⇢ JOIN의 원리
	- 여러 개의 조건으로 결합하고 싶은 경우 ON절에 AND를 사용할 수 있다. 
	- 동등 조인 (내부 조인, 교집합) ─ \[INNER] JOIN
		- *e.g.* `SELECT * FROM orders o JOIN stores s ON o.store_id = s.store_id;`
			- *cf.* `SELECT * FROM oders o, store s WHERE o.store_id = s.store_id;`와 동일
	- 외부 조인
		- LEFT|RIGHT JOIN ─ 주테이블은 무조건 모두 출력하고 보조테이블은 있는 것만 출력
			- LEFT JOIN ─ `주테이블 LEFT JOIN 보조테이블;`
			- RIGHT JOIN ─ `보조테이블 RIGHT JOIN 주테이블;`
		- FULL \[OUTER] JOIN ─ 양쪽 모두 주 테이블로 인식해서 무조건 모두 출력
```postgresql
-- 테이블 3개 결합 예시
SELECT
	o.order_id, o.order_date,
	s.store_name,
	f.first_name staff_first_name,
	f.last_name staff_last_name,
	c.first_name, c.last_name
FROM orders o
	LEFT JOIN customers c ON o.customer_id = c.customer_id
	LEFT JOIN stores s ON o.store_id = s.store_id
	LEFT JOIN staffs f ON o.staff_id = f.staff_id
```
