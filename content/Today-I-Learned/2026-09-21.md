# Javascript
- 인터프리터 언어 ─ 자바스크립트 해석 엔진을 포함 (*e.g.* 크롬 기준 V8 엔진, Node.js 런타임 등)

## js 변수 선언자
- 변수선언 종류 ─ `const`, `let`, `var`  
- 변수명 작성법 (= 함수명 작성법. 단, 생성자 함수는 앞글자를 대문자로 쓰는 것이 관례) ^a3d961
	- 알파벳(대소문자), 숫자, \_, $ 문자로만 구성하되 숫자는 맨 앞에 올 수 없다.
	- 예약어 (if, throw, …) 등은 사용 불가하다.
	- 변수는 CamelCase 로 작성하고 상수(const로 정의한 변수)는 대문자와 언더바로 작성한다.
- 변수에 할당할 값의 기본 타입 (데이터 타입) ─ number, string, boolean, null, undefined
- 변수 선언은 `const`로 선언하고 변경이 필요한 경우만 `let`으로 정의한다. (`var`은 사용하지 않는다.)

> [!NOTE] 변수 재선언(redeclaration)와 변수 재할당(reassignment)
> - 재선언 ─ 변수 공간 (이름표) 를 하나 더 만들고 내용물도 새롭게 넣기 (이름 재사용) ⇢ js 에서 지양하는 방법
> 	- *cf.* 선언 ─ 변수의 자리를 확보하는 것 (공간을 확보하고 그곳을 가리키는 것)
> - 재할당 ─ 변수 공간을 그대로 놓고 (이름표 그대로 놓고) 내용물만 바꿔치기
> 	- *cf.* 할당 ─ 변수의 자리를 확보하고 실제 값을 넣는 것 (확보한 공간에 값을 넣는 것)
> - *cf.* python에서는 재선언, 재할당 개념이 없다. 쓰임에 따라 재선언이 될 수도 재할당이 될 수도 있는 것

|                      | 파이썬                                                                                   | 자바스크립트                                                                                           |
| -------------------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| **최초 생성**            | `box = "사과"`                                                                          | `let box = "사과"`                                                                                 |
| **값 변경**             | `box = "바나나"`                                                                         | `box = "바나나"`                                                                                    |
| **같은 문법 <br>두 번 쓰기** | 문제 없음 (그냥 값 교체)                                                                       | 에러 (재선언 취급)                                                                                      |
| **선언 개념**            | 사실상 없음 (할당과 동일)                                                                       | 명확히 구분됨                                                                                          |
| **원시값 개념**           | 객체<br>X=5 ⇢ 5라는 객체 선언 및 할당<br>X=8 ⇢ 5라는 객체를 8로 바꾸는 게 아니라 X를 8객체에 옮겨 붙임<br>(rebinding) | 객체가 아닌 순수 값<br>X=5 ⇢ X라는 변수에 5값이 있음<br>X=8 ⇢ X라는 변수에 있던 5값이 8값으로 덮어 씌움                           |
| **기타 참고**            | 숫자, 문자열 포함 거의 모든 것이 객체<br>변수는 이름표이기 때문에 참조(가리킴) 방식으로 동작                               | 숫자, 문자열 등 원시값은 객체가 아니라 값 자체<br>⇢ 이 때 변수는 참조(가리킴) 방식으로 동작하지 않음<br>⇢ 리스트, 배열 등 객체는 참조(가리킴) 방식으로 동작 |
### `var` 
- `let`, `const` 선언자가 나온 배경 ─ `var`는 변수 동작을 예측할 수가 없다. 버그를 찾기가 어렵다. 안정성이 떨어진다.
	- 호이스팅 문제 발생 ⇢ 선언 전에 호출해도 오류 발생 없이 undefined로 초기화 ⇢ 버그가 숨겨진다.
		- undefined로 초기화 하면 undefined가 진짜 이 변수의 값인지 호이스팅 상태인지 알 수 없어서 문제
	- 함수 레벨 스코프 ⇢ 블록 코드를 무시하는 변수의 유효범위(scope) 문제가 발생하고 전역변수가 오염된다. 
	- 선언 키워드 생략 허용 ─ 선언자를 생략하고 변수를 지역변수로 정의하면 전역변수가 된다. (암묵적 전역 변수)
```jsx
// 함수 레벨 스코프 문제 발생
if (true) {
  var box = "사과"; // 블록 안에서 선언했는데
}
console.log(box);  // 블록 밖에서도 접근됨! (의도치 않은 경우가 많음)

// 함수 레벨 스코프 문제 해결
if (true) {
  let box = "사과"; // 블록 안에서만 존재
}
console.log(box);   // 에러! box는 여기서 안 보임
```
### `let`, `const` 

- 스코프가 다르면 같은 이름이어도 재선언처럼 보이지만 실제로는 별개의 변수이다. 
- 함수 블록 스코프 ⇢ 블록 코드 내에서 변수를 선언하면 그 안에서만 유효 ⇢ 변수의 유효범위(scope) 문제 해소
- `let`은 변수이고 `const`는 변수를 상수화 하는 것 
	- *이 변수는 절대 재할당되지 않는다.* 를 코드로 명시하고 값 변경을 원천 차단하려는 의도적 표현

| 선언자     | 스코프    | 재선언 | 재할당 | 호이스팅            | 언제 쓰나                          |
| ------- | ------ | --- | --- | --------------- | ------------------------------ |
| `var`   | 함수 스코프 | 가능  | 가능  | undefined (초기화) | 레거시 코드 유지보수 아니면 안 씀            |
| `let`   | 블록 스코프 | 불가능 | 가능  | TDZ (오류)        | 값이 바뀔 예정인 변수                   |
| `const` | 블록 스코프 | 불가능 | 불가능 | TDZ (오류)        | 왠만하면 이거부터 쓰고, 재할당 필요할 때만 `let` |
### 호이스팅
 - 정의한 변수(함수)가 최상위 객체에 할당되는 현상 ⇢ 변수(함수) 정의 위치에 상관 없이 호출 가능 
 - 자바스크립트 엔진이 코드를 실행하기 전에 미리 스코프 안의 선언들을 스캔해 두는 절차 (JS의 코드 처리 방식)
	 - 선언들을 스캔한다. = 내용물은 아직 뭔지 모르지만 일단 선언된 변수가 있는지 확인하고 최상단에 선언한다.
 - 호이스팅 구동 방식
	- 정의한 변수(함수)가 window 객체의 하위 속성으로 추가 (웹브라우저 기준)
		- *e.g.* `console.log(window);`
	- 정의한 변수(함수)가 global 객체의 하위 속성으로 추가 (Node.js 기준)
		- *e.g.* `console.log(globalThis);`
	- 윈도우 호출과 변수(함수) 정의를 하나의 런타임으로 실행하는 경우 윈도우 호출을 먼저 했어도 인터프리터 함수이기 때문에 변수(함수) 정의까지 포함해서 윈도우 호출이 된다. (코드를 모두 조망한 다음에 변수 또는 함수 선언을 모두 끌어 올려서 윈도우 호출)
- 선언자별 구동 방식
	- `var` ─ 선언만 끌어올리기 때문에 undefined로 초기화
	- `let`, `const` ─ 선언만 끌어올리긴 하지만 undefined로 초기화하지 않고 TDZ 상태로 임시 초기화
		- Temporal Dead Zone 상태 ─ 이 변수 상자는 이름표는 있긴 한데 아직 열면 안된다고 알려주는 상태
```javascript
// js는 인터프리터 언어이기 때문에 아래 런타임은 하나의 객체처럼 작동한다.
console.log(window);          
console.log(add(10, 20));
function add(num1, num2) {
    return num1 + num2;    // 함수가 아래 정의되어 있더라도 window 객체 위로 할당된다. (호이스팅)
};

// var: 등록하면서 동시에 undefined라는 임시값까지 채워버림
console.log(box); // undefined
var box = "사과";

// let: 등록만 해두고, 값은 물론 "접근 자체"도 막아버림 (TDZ)
console.log(box); // ReferenceError
let box = "사과";
```
# js 데이터 타입
- 자바스크립트에는 여러 자료형(타입)이 있고, 크게 원시 타입과 객체 타입으로 나뉜다.
	- 이 타입에 해당하는 실제 데이터들 ─ 값(Value)
		- 이 값들은 독립적으로 변수에 저장되거나 변수에 저장된 객체의 프로퍼티가 된다. 
			- 프로퍼티는 객체가 아니고 객체 내부에 저장된 변수 개념이다.

> [!NOTE] 변수, 프로퍼티, 원시값 개념 비교
> - `let age = 25;` ─ `age`는 변수
> - `const user = {age: 25};` ─ `age: 25`는 프로퍼티
> - `25`, `"홍길동"`, `true` ─ 원시값
## 원시 타입 (Primitive Type)
- 단 하나의 값만 담는 단순한 자료형  ⇢ 자바스크립트도 동적 타이핑 언어이기 때문에 자료형은 알아서 지정된다. 
	- 숫자형 (Number) ─ 정수와 실수를 구분하지 않는 모든 숫자 형식 (*e.g.* 25, 3.14)
	- 문자열형 (String) ─ 작은 따옴표('') 또는 큰 따옴표("")로 감싼 텍스트 (*e.g.* "홍길동", 'hello' )
		- 문자열을 포함한 여러 변수를 더하기(+) 연산자를 쓰는 경우 문자열 결합이 된다. 
		- 템플릿 리터럴 ─ `${num1}+${num2}=${num1+num2}` ─ 백틱 내부에서 python의 f-string 처럼 사용
			- 하지만 포맷 지정자를 쓸 수 있는 문법은 없고 표현식 자체를 미리 가공해서 포맷을 표현할 수 있다. 
				- 소수점 자리 표현 ─ `(3.14159).toFixed(2);` ⇢ 3.14
				- 천 단위 콤마 ─ `(1234.5).toLocaleString();` ⇢ 1,234.5
				- 자리수 채우기 ─ `(5).toString().padStart(2, "0");` ⇢ 05
				- 16진수 변환 ─ `(255).toString(16);` ⇢ ff
				- 패딩 ─ `"5".padStart(3, '0');` ⇢ 005 ─ `"hi".padEnd(5, '.');` ⇢ hi...
				- 대소문자 변환 ─ `"hello".toUpperCase();` ⇢ HELLO ─ `"WORLD".toLowerCase();` ⇢ world
				- 슬라이스 ─ `"hello world".slice(0, 5);` ⇢ hello ─ `"hello world".substring(0, 5);` ⇢ hello
				- 공백 제거 ─ `" hi ".trim();` ⇢ hi ─ `" hi ".trimStart();` ⇢ hi_ ─ `" hi ".trimEnd();` ⇢  \_hi
				- 반복 ─ `"ab".repeat(3);` ⇢ ababab
				- *cf.* 이렇게 표현식을 가공하면 자료형이 String이 되므로 `Number()`나 `ParseInt()`로 되돌려야 한다.
					- 템플릿 리터럴은 어짜피 출력용 표현식이므로 자료형 변환에 상관 없이 써도 됨 
	- 불리언형 (Boolean) ─ true, false 
	- null ─ 값이 없음 (비어 있음) 상태임을 명시함 
		- null로 정의한 변수 num에 대해 `console.log(num);` 하면 null `console.log(typeof num3);` 하면 object
	- undefined ─ 할당되지 (정의되지) 않은 변수, 변수 선언 후 값을 대입하지 않을 경우의 기본값 ⇢ `let`으로 할당
	- 심볼형 (Symbol) ─ 고유한 식별자 
	- 빅인트형 (BigInt) ─ 엄청나게 큰 정수 
```javascript
// 문자열과 숫자형 결합
const num1 = 10; // number
const num2 = 20; // number
const result = num1 + "+" + num2 + "=" + (num1+num2) // string
console.log(result); // 10+20=30

// 템플릿 리터럴을 활용한 함수 호출 ⇢ react에서 많이 사용
const tpl = `${num1}+${num2}=${num1+num2}`
function func(...args) {
    console.log("args:", args);
}
func() // args: []
func`${num1}+${num2}=${num1+num2}` // args: [ [ '', '+', '=', '' ], 10, 20, 30 ]
```
## 객체 타입 (Object Type / 참조 타입) 
- 복잡한 데이터 구조를 담는 자료형

# Runnable 객체
- Runnable 객체는 체인의 기준이 되는 객체 (연결되는 기준 객체)
- 동기식
	- invoke() ─ 메세지에 대한 답변을 완성된 블록으로 한 번에 출력
	- stream() ─ 생성된 토큰(chunk)마다 출력. 단순 출력에 많이 사용한다. (chat 모델이 답변하는 모습과 유사)
	- batch() ─ 여러 메세지에 대한 답변을 완성된 블록으로 한 번에 출력
- 비동기 ─ ainvoke(), astream(), abatch() ─ 여러 개의 요청을 동시다발적으로 실행하고 싶을 때 사용
- *e.g.* `chain = prompt|model|parser` ─ 모두 동일한 `invoke()` 메서드를 가지고 있기 때문에 체인 동작 가능
```python
# 동기식 batch
message = [
    "안녕하세요.",
    "반갑습니다.",
    "당신의 연락처는 무엇인가요?",
]

for i, res in enumerate(chain.batch(message)):
    print(i, res)
    
# 동기식 stream
for chunk in chain.stream("안녕하세요."):
    print(chunk, end="")

# 비동기 stream
async def async_message():
    async for chunk in chain.astream("안녕하세요."):
        print(chunk, end="")
await async_message()
```
## RunnableLambda
- Runnable 객체로 매핑해주는 함수
- 앞선 체인이 Runnable이면 뒤에 있는 함수는 RunnableLambda로 감싸지 않아도 자동으로 Runnable이 된다. 
- `@chain` ─ RunnableLambda로 감싸지 않아도 데코레이터를 이용해 Runnable 객체를 매핑할 수 있다. 
```python
# Runnable lambda 함수 기본 형식
def func_a (message: str) -> str:
    return f"func_a: {message}"

def func_b (message: str) -> str:
    return f"func_b: {message}"

func_a_runnable = RunnableLambda(func_a)
func_b_runnable = RunnableLambda(func_b)

func_a_runnable.invoke("안녕하세요.")
func_b_runnable.invoke("반갑습니다.")

chain = func_a_runnable|func_b_runnable
chain.invoke("안녕하세요.") # 'func_b: func_a: 안녕하세요.'

# Runnable lambda 데코레이터 적용 
@chain
def func_a (message: str) -> str:
    return f"func_a: {message}"

def func_b (message: str) -> str:
    return f"func_b: {message}"

# func_a_runnable = RunnableLambda(func_a)
# func_b_runnable = RunnableLambda(func_b)

func_a_runnable.invoke("안녕하세요.")
func_b_runnable.invoke("반갑습니다.")

chain = func_a_runnable|func_b_runnable
chain.invoke("안녕하세요.") # 'func_b: func_a: 안녕하세요.'
```
- 정규식 등으로 데이터 마스킹이 필요할 때 Runnable 객체로 매핑해서 처리할 수 있도록 한다.

# 전화번호 마스킹 체인 결합

    pattern = re.compile(r"(010)\D*(\d{4})\D*(\d{4})")
    message = pattern.sub(r"\g<1>-****-****", message)
    return [HumanMessage(message)]

model = get_model()
