### 연습장
#### 객체(Object)
- 사물, 대상 ⇢ 모든 것
- 속성(변수)과 행위(함수)로 구성되며 속성과 함수로 정의할 수 있음
- 행위(함수, 메서드)는 다른 객체와 함께(상호작용) 사용
	- 다른 말로, 행위(함수)가 있어야 다른 객체와 상호작용이 가능
- 객체 지향 프로그래밍 — 객체 간 상호작용의 개념으로 프로그래밍 하는 방식
#### 클래스(Class)
- 객체를 만들기 위한 명세서
	- 어떤 부품, 기능 등이 필요한지에 대해서 정리한 명세서
- 명명 시 일반적으로 첫 문자는 대문자로 작성
- 마침표(.) 연산자를 통해서 객체의 인스턴스 변수, 메서드에 접근 가능
- 모든 클래스들은 Object 라는 상위 클래스를 부모로 갖는다. (항상 생략됨)
#### 초기화 함수: \_\_init\_\_ (생성자)
- 객체가 생성이 되면 가장 먼저 호출되는 메서드
- 객체가 생성된 직후에 해야 할 처음 작업들 (초기화 작업)
	- 클래스가 생성된 후가 아닌 객체가 생성된 후에 해야 할 처음 작업들
	- 주로 하는 작업은 인스턴스 변수에 최초로 값을 할당하는 작업 (초기화 작업)
- self 다음 매개변수는 객체를 생성할 때 직접 외부에서 초기화 값 지정 가능
#### self 키워드
- 클래스 내부에서 메서드의 첫 번째 매개변수 ⇢ 하지만 실제로 매개변수라기보다는 참조변수
- 객체가 생성되면 객체의 자원을 접근하기 위한 참조변수로 사용됨
	- 즉 생성되는 객체 자신, player = Character() 라고 하면 player 를 지칭하는 셈
- 클래스 내부에서만 사용 가능
- 조금 더 이해하기 
```python
class Character:
	# Character 클래스는 무조건 nickname 매개변수를 지정하고 객체를 생성해야 함
	# 왜냐하면 초기화 함수에 nickname 매개변수를 지정했으니까 
	# self는 객체 생성 시 그 객체를 지칭하는 생성자이므로 매개변수보다는 참조변수
	# e.g. Character() 이렇게만 객체 생성 시 TypeError 발생
    def __init__(self, nickname):
        # 객체가 만들어지고 nickname이라는 속성을 부르면 매개변수로 입력한 nickname을 반환
        # 똑같이 nickname 이라는 명칭을 쓰고 있지만 하나는 속성, 하나는 매개변수
        self.nickname = nickname 

player = Character("푸바오")
print(player.nickname)  # 푸바오
```

#### 메서드 오버라이딩
- 매서드 재정의

	- 이 때 super().부모메서드 형식으로 접근해서 호출할 수 있음
#### 다중상속 — 여러 부모 클래스를 상속 관계로 정의
- 같은 메서드가 있을 때 호출 우선순위 (MRO)
	- 자식 클래스의 메서드 > 상속 관계에서 왼쪽에 있는 클래스
```python
class ParentA:

    def a(self):
        print('ParentA - a()')

    def b(self):
        print('ParentA - b()')

class ParentB:

    def a(self):
        print('ParentB - a()')

    def c(self):
        print('ParentB - c()')

class Child(ParentA, ParentB): # c.a() 결과: ParentA - a()
    pass

class Child(ParentB, ParentA): # c.a() 결과: ParentB - a()
    pass
    
Child.__mro__ # Method Resolution Order
# (__main__.Child, __main__.ParentB, __main__.ParentA, object)

```
#### 프라이빗 변수와 이름 변형 규칙

### 1. `self.__pw`는 어디서든 같은 변수예요 (이름 맹글링)

파이썬은 클래스 안에서 `__pw`처럼 언더스코어 두 개로 시작하는 속성을 만나면, 실제로는 `_클래스이름__pw`로 이름을 바꿔버려요 (name mangling). 지금 코드에서는:

python

```python
self.__pw   # 실제로는 self._DoorLock__pw
```

`__init__`, `set_password`, `__repr__` 전부 **DoorLock 클래스 안에** 정의되어 있기 때문에, 이 세 메서드에서 쓰는 `self.__pw`는 전부 똑같이 `self._DoorLock__pw`로 변환돼요. 즉 **완전히 같은 변수**를 가리켜요. 차이가 없습니다.

(만약 DoorLock을 상속한 다른 클래스에서 `self.__pw`를 썼다면, 그건 `_자식클래스이름__pw`가 되어서 부모의 `_DoorLock__pw`와는 다른 변수가 돼요 — 이게 name mangling을 쓰는 이유 중 하나예요. 하지만 지금 코드엔 상속이 없으니 해당 없음.)

### 2. `__repr__`에서 "set_password를 다시 넣었다"는 게 무슨 뜻인가요?

지금 코드를 보면:

python

```python
def __repr__(self):
    return f'set_password(pw={self.__pw})'
```

이건 **`set_password()`를 실제로 호출하는 게 아니에요.** 그냥 `"set_password(pw=1234)"` 같은 **문자열을 만들어서 반환**하는 것뿐이에요. `repr(obj)`를 호출해도:

- 검증 로직(`len(str(pw)) >= 4`)이 실행되지 않고
- `'정상 변경되었습니다.'` 같은 출력도 안 나오고
- 실제 비밀번호가 바뀌지도 않아요

그냥 "겉보기에 set_password 호출문처럼 생긴 텍스트"일 뿐이에요. 그래서 이 코드 자체로는 **문제가 안 생겨요.**

---

혹시 진짜로 `__repr__` 안에서 `self.set_password(...)`를 **실제로 호출**하도록 코드를 짜신 거라면 (예를 들어 `return f'set_password(pw={self.set_password(pw)})'` 같은 식으로), 그건 얘기가 달라져요 — `print(obj)`나 `repr(obj)`를 부를 때마다 매번 검증 로직이 실행되고 "정상 변경되었습니다" 같은 부작용(side effect)이 발생하는 이상한 구조가 됩니다. `__repr__`은 객체를 "보여주기"만 해야지 상태를 바꾸는 부수효과를 일으키면 안 되는 게 원칙이에요.

지금 작성하신 코드 그대로 실행해보고 어떤 결과가 나왔는지 알려주시면 더 정확히 짚어드릴 수 있어요.

아 그럼 저건 디버깅 형식이니까 set_password 보다 doorlock으로 self.__pw 를 보여주도록 하는게 맞겠네? 근데 사실 self.__pw는 클래스 내에서 항상 동일하니까 set_password나 doorlock에서의 self.__pw는 걍 같은 변수이고

맞아요, 정확히 이해하셨어요.

**1) `self.__pw`는 걍 같은 변수 맞아요** — 앞서 설명한 것처럼 name mangling 때문에 `__init__`이든 `set_password`든 `__repr__`이든, DoorLock 클래스 안에서 쓰는 `self.__pw`는 전부 `self._DoorLock__pw`라는 동일한 변수를 가리켜요.

- **A**. super()

#### 5번 문항
- **Q**. 다음 코드를 실행했을 때 출력되는 결과로 옳은 것은 무엇인가요?

```python
class Animal:
    def breathe(self):
        print("숨을 쉽니다.")

class Dog(Animal):
    def bark(self):
        print("멍멍 짖습니다.")

baduk = Dog()
baduk.breathe()
baduk.bark()
```

- **A**. "숨을 쉽니다."와 "멍멍 짖습니다."가 순서대로 출력된다.
- *Dog 클래스는 Animal 클래스를 상속받았기 때문에 부모의 breathe 메서드를 그대로 사용할 수 있고, 자신만의 bark 메서드도 함께 사용할 수 있습니다. 따라서 두 메서드 호출 모두 정상적으로 실행되어 두 문장이 순서대로 출력됩니다.*
