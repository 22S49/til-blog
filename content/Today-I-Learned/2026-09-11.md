함수의 반환 타입 void

저장 프로그램 (Stored Program)
1. 함수 (Function) ─ 매개변수와 반환값으로 구성
	- SELECT 구문 내에서 사용 가능 
	- 단일 트랜잭션이기 때문에 TCL 사용 불가
	- *e.g.* AVG(..), SUM(..)
2. 프로시저 (Procedure) ─ 매개변수를 받을 수 있지만 반환값은 없음
	- 독립 프로그램으로서 트랜잭션 제어 가능 (TCL 사용 가능)
		- COMMIT, ROLLBACK 정의 가능
	- *e.g.* CALL 프로시저명(..);
3. 트리거 (Trigger)

원격 저장소 pull 안 하고 내 로컬에서 commit 해서 독고다이 상태인 경우
git pull 했다가 충돌이 나서 머지가 끝나지 않은 상태로 남아있는 경우

**"커밋 → 푸시 시도 → 오류나면 그제서야 pull"** 순서 대신, 습관을 이렇게 바꾸는 게 좋습니다:

1. 작업 시작 전에 `git pull` 먼저 (또는 `git fetch` + 상태 확인)
2. 로컬에서 작업 및 커밋
3. 푸시 전에 다시 한번 `git pull` (혹시 그 사이 원격이 바뀌었을 수도 있으니)
4. `git push`
### 먼저 상태 확인

bash

```bash
git status
```

여기서 충돌난 파일 목록이 보일 거예요 (Unmerged paths 항목).

### 선택지 두 가지

**① 이 머지를 마무리하고 싶다면**

1. 충돌난 파일들을 열어서 `<<<<<<<`, `=======`, `>>>>>>>` 부분 직접 정리
2. `git add <파일명>` (정리한 파일마다)
3. `git commit` (머지 커밋 완성)
4. 그다음 `git push`

**② 그냥 이 머지를 취소하고 깔끔하게 다시 시작하고 싶다면**

bash

```bash
git merge --abort
```

이러면 머지 시도 이전 상태로 돌아가요. 그다음 이걸로 다시 시도하세요:

bash

```bash
git pull --rebase origin feature/user-details
```

지금 로컬에 중요한 작업git mer이 남아있는 상태라 `--abort`가 안전할 수도 있어요. `git status` 결과 먼저 보여주시면 어느 쪽이 나을지 알려드릴게요.
