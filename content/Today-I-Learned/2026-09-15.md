# CSS
- Cascading Style Sheet ─ 연쇄·상속 스타일 시트
- HTML 문서에 정의된 요소들의 시각적 스타일을 지정하는 스타일시트 언어
- 상속 기반이기 때문에 스타일 적용의 상속 관계를 구분할 수 있어야 한다. 
## 문법 구조
- 선택자(selector)
	- 전체 선택자 (\*)
	- 그룹 선택자 ─ 태그, 클래스, 아이디를 그룹지어서 스타일 적용
		- `span, .a, .b {..}` ─ a 또는 b인 요소에 스타일 일괄 적용 (OR)
		- `.a.b {..}` ─ a이면서 b인 요소에 스타일 적용 (AND)
	- 속성 선택자 ─ 지정된 속성이 있으면 스타일 적용 ⇢ 다른 선택자와의 조합할 때 많이 사용
		- `선택자[속성명]` 또는 `선택자[속성명="값"]` 형식으로 사용 (선택자는 생략할 수 있음)
		- 정규식 같이 쓸 수도 있음 ─ `선택자[속성명^="값"]`, `선택자[속성명$="값"]`, `선택자[속성명*="값"]`
	- 태그 선택자 ─ 태그 단위로 스타일 적용 ─  `태그명{..}` ⇢ 공통 스타일 적용에 많이 활용
	- 클래스 선택자 ─ 태그의 클래스명 단위로 스타일 적용 ─ `.클래스명{..}` ⇢ 세부 스타일 적용에 많이 활용
		- 하나의 태그에 여러 클래스를 적용할 수 있고 여러 클래스에 대해 스타일 일괄 적용도 가능 
			- `class="a b"` ─ 태그 하나에 클래스 여러 개 적용 (띄어쓰기 공백으로 연결)
	- 가상 선택자 ─ `클래스선택자:가상선택자 {..}` 형식으로 가상 클래스를 만들어 스타일 적용
		- 위치 선택자
			- `:first-child` ─ 첫 번째 자식 요소에 스타일 적용 (타입 무관)
			- `:last-child` ─ 마지막 자식 요소에 스타일 적용 (타입 무관)
			- `:nth-child(N)` ─ N번째 자식 요소에 스타일 적용 ⇢ N 위치에 수식이나 패턴이 들어갈 수 있다. 
				- 키워드 (`odd`, `even`): 홀수(`odd`, 1, 3, 5...)나 짝수(`even`, 2, 4, 6...) 번째 요소를 선택
				- `An+B` 패턴 ─ `n`이 `0`부터 시작하는 정수일 때, `An + B` 계산 결과에 일치하는 요소를 선택
				- `-n + B` (특정 번호까지 선택) ─ `B`번째 요소 부터 그 이전(처음)까지 모두 선택
				- `n + B` (특정 번호부터 이후 선택) ─ `B`번째 요소 부터 끝까지 모두 선택
				- 범위 지정 (`A`와 `B` 조합) ─ `:nth-child(n+2):nth-child(-n+5)` ⇢ 2번째부터 5번째까지의 요소 선택
			- `:first-of-type` ─ 같은 타입의 첫 번째 자식 요소에 스타일 적용
			- `:last-of-type` ─ 같은 타입의 마지막 자식 요소에 스타일 적용
			- `:nth-of-type` ─ 같은 타입의 N번째 자식 요소에 스타일 적용 ⇢ `:nth-child`와 혼용되지 않도록 유의
			- `:only-of-type` ─ 형제 요소들 중에서 같은 태그(타입)의 요소가 자기 자신 하나뿐인 요소에 스타일 적용
		- 조건 선택자
			- `:not(선택자)` ─ 지정된 선택자가 아닌 요소에 스타일 적용
			- `:is(선택자1, 선택자2, ..)` ─ 여러 선택자를 그룹으로 묶어서 스타일 적용 (이 중 하나라도 해당하면~)
				- 중첩 사용 가능 ─ e.g. `:is(a, b):is(c, d)` 또는 `:is(a, b) div`
				- *cf.* `:where()` 선택자와 똑같이 동작하지만 우선순위 `:where()`는 우선순위가 항상 0 ⇢ 덮어쓰기 용도
		- 상태 선택자
			- `:hover` ─ 마우스가 요소에 올라 간 상태
			- `:focus` ─ 특정 요소가 선택이 된 경우 또는 커서가 (가리키고) 있는 상태
			- `:checked` ─ 체크 표시가 된 상태
			- `:read-only` ─ 읽기 전용 상태 
			- `:disabled` ─ 비활성 상태 (↔ `:enabled`)
		- 요소 추가 선택자
			- 반드시 추가할 내용(content)이 있어야 출력된다. 스타일링 용도여도 `content=""` 해야 함
			- 요소 추가 선택자에서 추가할 내용(content)는 inline property 이므로 개행, 패딩 불가
			- `::before` ─ 자식의 첫 번째 요소로 추가
			- `::after` ─ 자식의 마지막 요소로 추가
			- `::placeholder` ─ 가이드라인 텍스트 (*e.g.* `textarea::placeholder {..}`)
			- `::selection` ─ 드래그 영역 (*e.g.* `.text::selection {..}`)
	- 아이디 선택자 ─ 하나만 지정 가능하고 유일한 이름으로 지정 (하나만 선택하는 속성) ─ `#아이디명{..}`
	- 복합 관계 선택자 
		- 하위 선택자 (`조상  자손`) ⊃ 자식 선택자 (`부모 > 자식`)
			- 조상자손 ─ 위계 상관 없이 포함되는 범위 전부
			- 부모자식 ─ 바로 한 칸 위아래 상호 관계
		- 일반 형제 선택자 (`기준 ~ 아래`) ⊃ 인접 형제 선택자 (`기준 + 아래`)
			- 형제형제 ─ 기준 뒤에 오는 같은 부모를 둔 동일 계층의 관계
```html
<div class="box">           ← 부모(조상)
  <h2>제목</h2>              ← 자식이자 형제
  <p>첫 번째 문단</p>         ← 자식이자 형제
  <section>                  ← 자식이자 형제
    <p>섹션 안의 문단</p>     ← section의 자식 (div 입장에서는 손자)
  </section>
</div>
```
- 스타일 속성(property) ─ color, background, width, height, …
- 스타일 값(value)
```css
/* h1 태그를 선택하여 글자 색상은 파란색으로, 글자 크기는 20픽셀로 설정하는 예제 */
h1 {
  color: blue;       /* h1 요소의 글자 색상을 파란색으로 지정 */
  font-size: 20px;   /* h1 요소의 글자 크기를 20픽셀로 지정 */
}
```
## 적용 방법
- 인라인 스타일 ─ HTML 태그 내부 style 속성에 직접 설정
- 내부 스타일 시트 ─ HTML 태그 내부 \<head> 영역 안에 \<style> 태그로 정의
	- \<style> 요소는 문서의 \<head> 안에 위치하는 것이 적절하다.
		- 브라우저는 HTML을 위에서 아래로 읽기 때문에 head에서 미리 스타일을 불러와야 FOUC 방지 가능
		- 실제 콘텐츠와 설정 및 디자인 정보를 분리해 코드의 가독성과 유지보수를 높일 수 있음
- 외부 스타일 시트 ─ HTML와 분리해 스타일시트 파일(.css)을 생성하고 \<link> 태그로 연결하는 방식
	- *e.g.* `<link rel="stylesheet" href="./style.css">`
- *cf1.* 작성 위치 기준 적용 우선순위 ─ 인라인(inline) > 내부(embed) = 외부(external)
	- 선택자 명시도가 같다면 내부(embed)와 외부(external) 중 나중에 로딩/작성된 것이 최종 적용된다. 
- *cf2.* 선택자 기준 적용 우선순위 ─ `!important` > 인라인 스타일 > 아이디 > 클래스 > 태그 > 전체 선택자
	- 적용 범위가 좁을 수록 우선순위가 높아진다. (단, `!important` 적용시 우선순위를 무시하고 절대 적용)
	- 스타일을 좁근 범위에 특정하거나 강하게 지정하는 경우 변경 불가 ⇢ 클래스 수준에서의 스타일 적용 권장 

> [!NOTE] 큰 속성(shorthand)과 파생 속성(longhand)
> - shorthand
> 	- 단축 속성, 큰 속성
> 	- 여러 속성을 한 번에 지정
> 	- *e.g.* `background`, `font`, `margin`
> - longhand
> 	- 개별/세부 속성, 파생 속성
> 	- shorthand에서 파생된 개별 속성
> 	- *e.g.* `background-color`, `font-size`, `margin-top`

> [!NOTE] 명시도 (Specificity)
> - CSS에서 작성 순서로 우선순위를 정하지 않고 순서를 의도적으로 지정할 수 있도록 하는 장치
> - 각 스타일이 얼마나 구체적/의도적으로 지정됐는지 판단해서 더 구체적인 의도를 우선하는 장치
> 	- 전체 규칙 ⇢ 그룹 예외 ⇢ 개별 예외와 같은 계층적 스타일링을 가능하도록 한다. 
> 	- 카테고리별 점수가 공식 스펙에 규정되어 있고 단순 점수 합산이 아닌 자릿수 비교 및 개수 비교로 산정한다. 

# AWS 특강
- 내 퍼블릿 깃허브에 있는 html 파일 서버로 띄우기
	1.  인스턴스 생성
		1. 원하는 리전으로 선택이 잘 되어 있는지 확인
		2. 원하는 OS 선택 ⇢ 일반적으로 우분투 LTS 두 번째 또는 세 번째 이전 버전 (안정성 측면)
			- 전력 사용이 적은 64비트 ARM 버전으로 선택 (금액 최대한 절감)
		3. 보안그룹은 기본값으로 선택하지 말고 직접 설정할 수 있는 여지 두기 ⇢ 기본값은 SSH 충돌 날 수 있음
	2. 보안그룹 설정 ─ SSH(내 IP), IPv4, IPv6 설정
	3. 탄력적 IP 설정 ─ 한 계정당 4개까지만 발급 가능. AWS는 퍼블릭 IP를 주기적으로 변경하기 때문에 설정 필요
	4. 인스턴스 연결
	5. 리눅스 설정
``` bash
sudo apt update                     ⇢ 우분투 패키지 목록 최신 상태로 갱신
sudo apt install nginx -y           ⇢ 웹 서버 프로그램인 nginx 설치
git clone [Github_URL]              ⇢ 내 깃허브 저장소를 서버 디렉토리로 복제
cd [Github_project_folder]          ⇢ 방금 clone 한 프로젝트 폴더로 이동

sudo cp something.html /var/www/html/index.nginx-debian.html
 ⇢ 프로젝트 폴더 안의 html 파일을 nginx의 기본 웹 루트 경로('/var/www/html/')에 
	'index.nginx-debian.html'이라는 이름으로 복사
 ⇢ nginx는 기본적으로 'index.nginx-debian.html' 파일을 첫 화면으로 보여주기 때문에
	이 작업이 끝나면 인스턴스의 IP로 접속했을 때 해당 html이 뜨게 된다.
```
- 서버사이드 렌더링
	- 서버에서 렌더링해서 클라이언트에 보냄
	- 그로스 마케팅 등에는 서버 접근 이력 등을 모니터링하기 때문에 서버사이드 렌더링이 효과적
- 클라이언트사이드 렌더링
	- 서버로부터 리소스를 받아서 클라이언트에서 렌더링
	- 인터렉티브 요소가 많은 페이지는 리소스가 많이 들기 때문에 클라이언트사이드 렌더링이 효과적
	- 클라이언트로 보내서 렌더링하게 하면 되니까 서버의 RAM이 작아도 상관 없다.
