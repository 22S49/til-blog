-  loc — 행이름으로 검색(선택)

		- df.loc\[시작행:종료행, \[컬럼명1, 컬럼명2, …]]
		- df.loc\[\[행라벨1, 행라벨2], … , 시작컬럼:종료컬럼]

	- iloc\[0:2, 0:2] — 인덱스 0~1, 컬럼 0~1

### 파이썬/넘파이/판다스의 "없음(결측치)" 표현 정리

#### 1. `None`

- 파이썬 기본 내장 객체로, "값이 없음"을 나타내는 순수 파이썬 타입입니다.
- 타입은 `NoneType`이며, 어떤 자료형에도 속하지 않습니다.
- pandas Series에 `None`을 넣으면 상황에 따라 자동으로 `NaN`으로 변환되기도 합니다 (숫자형 컬럼일 때).

python

```python
x = None
print(type(x))  # <class 'NoneType'>
```

#### 2. `NaN` (Not a Number)

- IEEE 754 부동소수점 표준에서 정의된 "숫자가 아님"을 나타내는 특수 float 값입니다.
- `numpy.nan`, `float('nan')` 등으로 생성됩니다.
- **중요한 특징**: `NaN == NaN`은 `False`입니다. 즉 자기 자신과도 같지 않습니다.
- pandas에서 결측치를 표현하는 전통적인 방식이며, 정수형 컬럼에 NaN이 들어가면 컬럼 전체가 `float64`로 강제 변환됩니다.

python

```python
import numpy as np
np.nan == np.nan  # False
np.isnan(np.nan)  # True (확인은 이 함수로)
```

#### 3. `<NA>` (pandas.NA)

- pandas 1.0부터 도입된 **새로운 결측치 표현**으로, nullable 정수형(`Int64`), nullable boolean(`boolean`), string 타입 등에서 사용됩니다.
- `NaN`과 달리 정수형에서도 결측치를 표현할 수 있어서, 정수 컬럼에 결측치가 있어도 float로 변환되지 않습니다.
- `pd.NA`는 3값 논리(three-valued logic)를 따릅니다: `pd.NA == pd.NA`는 `False`가 아니라 `pd.NA`(알 수 없음)를 반환합니다.

python

```python
import pandas as pd
s = pd.Series([1, 2, None], dtype="Int64")
print(s)
# 0       1
# 1       2
# 2    <NA>
# dtype: Int64
```

#### 4. `NaT` (Not a Time)

- 날짜/시간(datetime) 데이터에서의 결측치를 나타냅니다. `NaN`의 datetime 버전이라고 보면 됩니다.

python

```python
pd.Series([pd.Timestamp('2024-01-01'), None])
# 자동으로 NaT로 변환됨
```

#### 5. `null` (JSON/DB 맥락)

- 파이썬 자체 문법은 아니고, JSON이나 SQL 등 다른 시스템에서 쓰는 표현입니다.
- `pd.read_json()`이나 `pd.read_sql()` 등으로 데이터를 불러올 때 JSON의 `null`이나 SQL의 `NULL`이 pandas에서는 `NaN` 또는 `None`으로 매핑됩니다.

### 요약 비교표

|표현|소속|주 사용처|비교 결과|
|---|---|---|---|
|`None`|파이썬 내장|일반 객체, object 타입 컬럼|`None == None` → `True`|
|`NaN`|numpy/float|전통적 결측치 (float 컬럼)|`NaN == NaN` → `False`|
|`NaT`|pandas|datetime 결측치|`NaT == NaT` → `False`|
|`<NA>`|pandas (신규)|nullable 정수/문자열/불리언|`pd.NA == pd.NA` → `pd.NA`|
|`null`|JSON/SQL|외부 데이터 포맷|파이썬 문법 아님|

### 결측치 확인 방법

비교 연산자로 직접 확인하지 말고 전용 함수를 쓰는 게 안전합니다.

python

```python
pd.isna(x)      # None, NaN, NaT, pd.NA 모두 True로 감지
pd.notna(x)     # 반대
df.isnull()     # isna()의 별칭, 동일하게 동작
```

궁금한 부분—예를 들어 `dtype`에 따라 어떻게 자동 변환되는지, 혹은 결측치 처리(`fillna`, `dropna`) 실습—이 있으면 더 파볼게요.

replace 하면 자료형은 바뀌지 않아?

좋은 질문이에요. `replace()`는 상황에 따라 dtype이 바뀔 수도 있고 안 바뀔 수도 있습니다. 케이스별로 정리해드릴게요.

### 1. 값 → 값 치환: dtype이 유지되는 경우가 많음

python

```python
s = pd.Series([1, 2, 3])
s.replace(2, 200)
# dtype: int64 그대로 유지
```

숫자를 숫자로, 문자열을 문자열로 치환하는 등 **같은 종류의 값**으로 바꾸면 dtype은 보통 유지됩니다.

### 2. NaN/None으로 치환 → dtype이 float로 바뀔 수 있음

이게 실무에서 자주 만나는 케이스입니다.

python

```python
s = pd.Series([1, 2, 3])  # dtype: int64
s2 = s.replace(2, np.nan)
print(s2.dtype)  # float64로 바뀜!
```

정수형(`int64`) 컬럼은 애초에 `NaN`을 담을 수 없기 때문에, `NaN`을 넣는 순간 pandas가 자동으로 `float64`로 업캐스팅합니다. (이전 답변에서 말씀드린 것처럼 `int64`는 결측치를 표현 못 하니까요.)

### 3. 문자열 → 숫자, 숫자 → 문자열처럼 이종 치환

python

```python
s = pd.Series(['a', 'b', 'c'])
s.replace('a', 1)
print(s.dtype)  # object 그대로 (혼합 타입이라)
```

object dtype 컬럼은 애초에 여러 타입을 섞어 담을 수 있어서, 특정 값만 다른 타입으로 바꿔도 dtype 표시는 `object`로 유지됩니다 (내부적으로는 섞여 있음).

### 4. nullable 타입(`Int64`, `string` 등)을 쓰면 정수 유지 가능

python

```python
s = pd.Series([1, 2, 3], dtype="Int64")  # nullable int
s2 = s.replace(2, pd.NA)
print(s2.dtype)  # Int64 그대로! float로 안 바뀜
```

정수형인데도 결측치를 표현해야 한다면, 앞서 설명한 `pd.NA`를 지원하는 nullable dtype(`Int64`, `Float64`, `boolean` 등 대문자로 시작하는 타입)을 쓰면 `replace`로 NaN을 넣어도 dtype이 안 바뀝니다.

### 확인하는 습관

dtype이 예상치 못하게 바뀌었는지는 항상 `.dtypes`로 체크하는 게 안전합니다.

python

```python
print(df.dtypes)          # replace 전
df = df.replace(...)
print(df.dtypes)          # replace 후, 비교
```

---

요약하면: **같은 카테고리 값끼리 치환하면 dtype 유지**, **결측치(NaN)로 치환하면 int→float처럼 업캐스팅될 수 있음**, **nullable dtype을 쓰면 이걸 피할 수 있음**입니다.

#### 4번 문항
- **Q**. 타이타닉 데이터에서 '나이(age)'처럼 숫자형 데이터의 결측치를 채울 때 일반적으로 사용하는 대표값은 무엇인가요?
- **A**. 평균
- *숫자형 데이터는 산술 계산이 가능하므로 전체 데이터의 평균(mean)으로 결측치를 자연스럽게 채울 수 있습니다. 반면 항구 이름 같은 문자/범주형 데이터는 평균을 낼 수 없어 최빈값(mode)을 사용합니다.*
#### 5번 문항
- **Q**. Pandas의 Copy-on-Write(CoW) 환경에서 데이터를 안전하게 수정하기 위한 방법으로 가장 적절한 것은?
- **A**. .loc\[]를 사용하여 한 번의 단일 작업으로 위치를 지정해 수정한다.
- *.loc\[]나 .iloc\[]는 단일 작업으로 원본의 정확한 메모리 위치에 접근해 100% 안전하게 수정할 수 있습니다. 대괄호를 연속으로 사용하는 방식은 두 단계로 나뉘어 처리되어 임시 복사본이 생길 수 있어 위험합니다.*
