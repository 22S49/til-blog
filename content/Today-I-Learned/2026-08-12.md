### 연습장
#### 자료구조 — 스택(Stack)
- 아래가 막혀 있는 원통에 쌓이는 구조 — Last Input First Out
	- 가장 마지막에 넣었던 자료를 가장 먼저 꺼낸다
	- 가장 먼저 넣었던 자료를 가장 마지막에 꺼낸다
#### 자료구조 — 큐(Queue)
- 대기열, 선착순 처리 — First Come First Service
- 양쪽이 뚤린 원통에 한 방향으로 밀어넣는 구조
	- 가장 먼저 넣었던 자료를 가장 먼저 꺼낸다
	- 가장 마지막에 넣었던 자료를 가장 마지막에 꺼낸다
#### 함수
- 사용 목적 — 반복되는 작업을 정의, 코드의 재활용, 필요할 때 꺼내 씀
- 구성 요소 — 입력, 처리, 출력
- 정의 방법
```python
def 함수이름(매개변수, …): # 함수 내에서 생산만 하는 경우 매개변수가 없을 수 있음
	
	처리하는 내용 정의
	
	return 반환값 # 함수 실행 결과가 다음 로직에 활용되는 경우 필수 (함수를 값처럼 쓸 때)
	# 그냥 함수를 실행하고 끝이면 return으로 마무리하지 않아도 무방
```
- 호출 방법 — 함수이름(*인수*)
- 매개변수 — 함수 호출 시 입력 부분에 값을 담아주는 변수, 함수에 정의된 변수
	- 매개변수 없는 함수도 있음
- 인수 — 호출 시 사용된 값, 함수에 투입된 값
#### 정적 메모리
- 한 번 기록되면 제거하지 않음
- 항상 사용될 수 있는 코드들이 (바로 쓸 수 있게) 탑재되어 있음
	- **코드**
		- 내장함수
		- 문법(조건문, 제어문, …)
	- **전역변수** — 함수 외부에 정의된 변수
#### 동적 메모리
- 실행 중 생성과 소멸을 반복함 (실행 과정 중에 발생)
	- 실행 과정 중 정의한 코드, 변수, …
	- 가비지콜렉터 활동 무대
- **힙** 영역 메모리 (객체 전용 메모리)
	- 사용하지 않을 때 삭제됨
	- 파이썬에서는 함수도 객체가 됨 ⇢ 함수에 대한 명세 할당 
		- 인터프리터 언어 특징 — 바로바로 정의되어야 하기 때문에 동적 메모리 활용
		- *cf. 컴파일 언어는 함수를 코드 그 자체로 보고 정적 메모리로 할당하고 정의*
		- 함수 명세 객체
			- PyFunctionObject
				- Pycode Object — 매개변수 정의, 수행코드 정의
```python
calc2 = calc # 함수명이 함수객체를 참조하기 때문에 새로운 이름표 지정 가능, 힙 영역
calc2(20) # 동일한 함수 정의 객체를 참조하고 실행, 스택 영역
calc is calc2 # True
calc2 = 10 # calc2의 참조가 달라졌으므로 calc에 대한 참조가 끊기고 calc2 함수 명세 제거
```
- **스택** 영역 메모리 (Call Stack)
	- 실행이 완료되면 삭제됨 — 동적 메모리이면서도 임시 메모리
	- 함수 실행 영역 메모리 ⇢ 함수를 호출했을 때 할당 ⇢ 함수 실행 완료 후 메모리에서 제거
	- 함수 실행 객체
		- PyFrameObject
			- 지역변수 — 함수 내부에 정의된 변수
			- f_locals — 변수에 대한 공간, 함수가 실행될 때만 유효, 지역변수는 여기에서 구체화
```python
# 함수 명세
def func(num):
    result = add(10, 20)
    result += num
    return result

# 함수 실행
# 동작 순서(Call Stack): func() 호출 → add() 호출 → add() 제거 → func() 제거
result = func(40)
result
```
#### 전역변수와 지역변수
```python
def add(num1, num2): # 매개변수, 지역변수 선언
    num3 = 30 # 지역변수 선언
    result = num1 + num2 + num3 # 지역변수 선언
    return result

result = add(10, 20) # 전역변수 선언 — add() 함수의 result와는 다른 변수 (이름만 같을 뿐)
result # 60 = 10 + 20 + 30
```
#### return
- 반환값 정의 — 반환값은 무조건 한 개 — 복수 데이터를 반환할 때는 튜플로 묶어서 하나로 반환
	- 튜블로 묶인 값을 나누고 싶으면 언패킹
- 함수 연산 종료 ⇢ 더이상 코드를 실행하지 않음
- 조건에 따라 함수 내에서 흐름을 종료하고 싶을 때에도 사용 가능
- 반환값이 없을 때 return을 생략할 수 있음 ⇢ return은 있지만 따로 명시하지 않는 것일 뿐
```python
def add(num):
    if num == 999:
        print('종료')
        return # break와 유사한 역할
        # 이 위치에 return을 두지 않고 add(999) 호출 결과: 종료 998001
    result = num ** 2
    return result
```
#### 위치 인수
- 매개변수 순서대로 인수 지정
- 위치 인수와 키워드 인수를 섞어 쓰기도 하는데, 위치 인수가 앞에 나온는 것(앞에 할당하는 것)이 관례
```python
def add(num1, num2, name, mobile):
    return f'{num1+num2}, {name=}, {mobile=}'
add(10, 20, mobile='010-0000-0000', name='김영희') # "30, name='김영희', mobile='010-0000-0000'"
add(mobile='010-0000-0000', 10, 20, name='김영희') # SyntaxError 발생
```
#### 키워드 인수
- 특정 매개변수의 이름(키워드)를 명시해서 인수 지정
- 키워드가 중요하고 순서는 상관 없음
- 위치 인수는 항상 값을 지정하는데 키워드 인수는 선택적으로 값 지정 가능
	- 기본값 매개변수 — 매개변수에 값을 할당하지 않아도 기본적으로 가질 수 있는 값 설정
``` python
def add(num1, num2, name, mobile='010-0000-0000'):
    return f'{num1+num2}, {name=}, {mobile=}'
add(10, 20, '김영희') # "30, name='김영희', mobile='010-0000-0000'"
```
- 기본값이 있는 매개변수는 오른쪽 끝부터 차례대로 정의
- 필요할 때만 매개변수를 할당 — 기본값을 None으로 할당
```python
# SyntaxError: parameter without a default follows parameter with a default
def add(num1, num2, name = None, mobile):
    return f'{num1+num2}, {name=}, {mobile=}'
# 정상동작
def add(num1, num2, mobile, name = None):
    return f'{num1+num2}, {name=}, {mobile=}'
add(10, 20, "010-0000-0000") # "30, name=None, mobile='000-0000-0000'"
```
#### 가변 인수 — \*args
- 가변적인 위치 인수
- 매개변수를 개수 상관 없이 지정 가능 (유동적 할당)
- 키워드 매개변수로는 사용 불가 (이름을 알 수 없으니까)
- 튜플 형태로 값이 넘어감
```python
def add(*nums):
    print(nums, type(nums), end='')
    return print(f' 반환값: {sum(nums)}')
add(10, 20, 30) # (10, 20, 30) <class 'tuple'> 반환값: 60
```
- 기타 번외 코드 — sum() 함수를 반복문으로 표현
```python
def add(*nums):
    total = 0
    for i in nums:
        total += i
    return total
add(10, 20, 30) # 60
```
#### 키워드 가변 인수 — \*\*kwargs
- 키워드 가변 인수도 오른쪽 끝부터 차례대로 정의 — 가변 인수보다도 우선순위가 낮음
- 키워드 가변 인수를 포함한 함수를 명세하고 원하는 키워드 인수를 넣고 싶을 때 키워드 인수로 지정
- 딕셔너리 형태로 값이 넘어감
```python
def print_user_info(name, age, *args, **kwargs):
        print(f'name:{name} / age:{age} / {args} / {kwargs}')

print_user_info('철수', 20, 20, mobile='010-0000-0000')
# name:철수 / age:20 / (20,) / {'mobile': '010-0000-0000'} — 가변 인수는 튜플

print_user_info('철수', 20, mobile='010-0000-0000')
# name:철수 / age:20 / () / {'mobile': '010-0000-0000'} — 가변 인수는 생략 가능

print_user_info('철수', 20, 'A', 20, mobile='010-0000-0000')
# name:철수 / age:20 / ('A', 20) / {'mobile': '010-0000-0000'} — 키워드 가변 인수는 딕셔너리
```
#### 프레임 객체 직접 확인하기
```python
import sys  # 인터프리터 내부 기능(sys._getframe 등)을 쓰기 위해 sys 모듈을 가져옴

def outer_func():
    x = 10  # outer_func의 지역 변수

    def inner_func():
        y = 20  # inner_func의 지역 변수

        # 1. 현재 실행 중인 프레임 객체 가져오기
        # → 지금 이 코드가 inner_func 안에서 실행 중이므로, frame은 inner_func의 실행 정보를 담음
        frame = sys._getframe()

        # frame.f_code: 이 프레임에서 실행 중인 코드 객체
        # .co_name: 그 코드가 속한 함수의 이름 → "inner_func" 출력
        print(f"1. 현재 실행 함수: {frame.f_code.co_name}")

        # frame.f_locals: 현재 프레임(inner_func)의 지역 변수 딕셔너리
        # → y=20을 포함해 {'y': 20, ...} 형태로 출력
        print(f"2. 현재 지역 변수(f_locals): {frame.f_locals}")

        # frame.f_globals: 이 코드가 실행되는 모듈의 전역 변수 딕셔너리
        # outer_func는 모듈 최상위에서 정의됐으므로 전역에 존재 → True 출력
        print(f"3. 전역 스코프 참조 여부: {'outer_func' in frame.f_globals}")

        # 2. f_back을 통해 부모 프레임(outer_func)으로 이동
        # f_back: 이 프레임을 호출한 "호출자(caller)"의 프레임
        # inner_func는 outer_func 안에서 호출됐으므로, f_back은 outer_func의 프레임
        parent_frame = frame.f_back

        # 부모 프레임(outer_func)의 함수 이름 → "outer_func" 출력
        print(f"4. 부모 함수 이름: {parent_frame.f_code.co_name}")

        # 부모 프레임(outer_func)의 지역 변수 딕셔너리
        # -> x=10을 포함해 {'x': 10, ...} 형태로 출력
        print(f"5. 부모 함수의 지역 변수: {parent_frame.f_locals}")

    inner_func()  # outer_func 안에서 inner_func 호출 -> 호출 스택이 outer_func -> inner_func로 쌓임

outer_func()  # 최상위(전역)에서 outer_func 호출 -> 실행 시작점
```

### 오늘의 퀴즈
#### 1번 문항
- **Q**. 다음 코드의 실행 결과로 옳은 것은? def introduce_self(name, age): print(f"이름: {name}, 나이: {age}") introduce_self(30, "홍길동")
- **A**. 이름: 30, 나이: 홍길동
- *위치 인수는 오직 순서만을 기준으로 매핑되므로, 첫 번째 인수 30이 name에, 두 번째 인수 "홍길동"이 age에 그대로 대입되어 의도치 않은 결과가 출력됩니다. 타입이 다르더라도 파이썬은 에러 없이 순서대로 값을 넣기 때문에 TypeError는 발생하지 않습니다.*
#### 2번 문항
- **Q**. 함수 정의 시 매개변수 앞에 별표 하나(\*)를 붙여 여러 인수를 전달받으면, 파이썬 인터프리터는 이를 어떤 자료구조로 묶어서 관리하나요?
- **A**. 튜플
- *\*args로 전달된 인수들은 순서대로 패킹되어 수정이 불가능한 튜플 구조로 함수 내부에 저장됩니다. 반면 \*\*kwargs는 키=값 형태로 전달된 데이터를 딕셔너리 구조로 관리한다는 점에서 구분됩니다.*
#### 3번 문항

- **Q**. 다음 함수 정의가 SyntaxError를 발생시키는 이유로 가장 적절한 것은? `def error_func(age=20, name):` `pass` 
- **A**. 기본값이 없는 매개변수(name)가 기본값이 있는 매개변수(age) 뒤에 위치했기 때문이다
- *인터프리터는 인수를 앞에서부터 차례대로 매핑하므로, 기본값 없는 매개변수가 기본값 있는 매개변수보다 뒤에 오면 어떤 값을 어디에 대입해야 할지 판단할 수 없어 문법 에러가 발생합니다. age라는 이름 자체나 함수명 규칙, 정수형 기본값 사용은 오류 원인이 아닙니다.*
#### 4번 문항
- **Q**. 함수 실행 중 return 문을 만나면 인터프리터는 어떻게 작동하나요? 한 문장으로 답하세요.
- **A**. 함수 실행 종료 **(오답)**
- *return을 만나는 순간 하위에 남은 코드가 있더라도 실행하지 않고 함수를 즉시 종료하며, 계산된 결과값을 호출부로 내보냅니다. 이는 return의 핵심 제어 특성입니다.*
#### 5번 문항
- **Q**. 다음 코드의 출력 결과로 옳은 것은? `def get_average(\*scores):` `if len(scores) == 0:` `return 0` `total = sum(scores)` `avg = total / len(scores)` `return avg` `result = get_average()` `print(result)
- **A**. 0
- *인수 없이 호출하면 scores는 빈 튜플이 되어 len(scores)0 조건이 참이 되므로 정수 0이 그대로 반환됩니다. 이 방어 코드가 없다면 0으로 나누는 ZeroDivisionError가 발생했겠지만, 조건문 덕분에 안전하게 처리됩니다.*
