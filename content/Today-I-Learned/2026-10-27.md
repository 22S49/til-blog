# 1. HTTP 메서드

|메서드|의미|요청 본문|응답 본문|안전*|멱등**|대표 성공 코드|
|---|---|---|---|---|---|---|
|**GET**|조회|없음|있음|O|O|200|
|**POST**|생성, 처리 요청|있음|보통 있음|X|X|201 (생성), 200/202|
|**PUT**|전체 교체 (없으면 생성)|있음|선택|X|O|200, 204 (생성이면 201)|
|**PATCH**|일부 수정|있음|선택|X|보통 X|200, 204|
|**DELETE**|삭제|보통 없음|보통 없음|X|O|204 (또는 200)|
|**HEAD**|GET인데 헤더만|없음|**없음**|O|O|200|
|**OPTIONS**|서버가 허용하는 메서드 확인 (CORS 사전 요청)|없음|선택|O|O|200, 204|
|**TRACE**|요청 경로 진단(에코)|없음|있음|O|O|200 (보안상 대부분 막아 둠)|
|**CONNECT**|프록시 터널 연결 (HTTPS 프록시)|없음|없음|X|X|200|

* **안전**: 서버 상태를 바꾸지 않음  
** **멱등**: 같은 요청을 여러 번 보내도 결과가 한 번 보낸 것과 같음

**POST vs PUT 차이**

- `POST /books` 두 번 → 책이 **2권** 생김 (멱등 아님)
- `PUT /books/1` 두 번 → 1번 책이 **같은 상태**로 유지 (멱등)

**FastAPI에서는**: `@app.get`, `@app.post`, `@app.put`, `@app.patch`, `@app.delete`, `@app.head`, `@app.options`, `@app.trace`로 쓰고, 상태 코드는 `status.HTTP_201_CREATED`처럼 상수로 써.

# 3. 헷갈리기 쉬운 쌍

|비교|차이|
|---|---|
|**401 vs 403**|401은 "누구세요?"(인증 안 됨), 403은 "알지만 안 돼요"(권한 없음)|
|**400 vs 422**|400은 요청 자체가 깨짐(JSON 문법 오류 등), 422는 문법은 맞는데 값이 규칙 위반|
|**404 vs 410**|404는 없음(원래 없었을 수도), 410은 있었는데 영구 삭제됨|
|**200 vs 201 vs 204**|각각 일반 성공, 새로 생성됨, 본문 없는 성공|
|**500 vs 502/503/504**|500은 내 서버 코드 버그, 502~504는 서버 앞뒤 연결/과부하 문제|
|**301/302 vs 307/308**|앞쪽은 POST가 GET으로 바뀔 수 있고, 뒤쪽은 메서드 유지|
