# ACID 원칙
- 트랜잭션의 네 가지 원칙
- Atomicity (원자성) ─ 쿼리는 모두 성공하거나 모두 실패해야 한다.
- Consistency (일관성) ─ 규칙(제약조건)을 위반해서는 안 된다. 
- Isolation (격리성) ─ 동시 트랜잭션이 서로 간섭되지 않아야 한다.
	- DB Lock
		- 비관적 Lock ─ 수정이 끝나야 잠금이 풀리게 하는 설정 
			- `SELECT .. FROM .. WHERE .. FOR UPDATE` 
			- *e.g.* 500이라는 데이터에 A가 -400, B가 -300을 동시에 주면 충돌 발생
				- A의 -400이 근소한 차이로 먼저 전달되면 처리 완료될 때까지 B를 받지 않는다.
				- 성능 저하 가능성이 있지만 강한 잠금 기능으로 안정성을 확보할 수 있다. 
		- 낙관적 Lock ─ 테이블 구성 시에 VERSION 컬럼을 두고 테이블 시 버전을 체크하고 관리
			- *e.g.* A (조회 ⇢ VER 1 ⇢ 수정 ⇢ VER2) ⇢ B (조회 ⇢ VER 1 ⇢ 수정 ⇢ VER1)
				- 데이터와 B 사용자가 요청한 버전이 서로 다를 때 예외 발생 (표면적으로, 프로그램적으로)
		- 외부 분산 Lock ─ DB가 여러 개일 때 여러 서버가 접근하므로 동시성 문제를 해결하기 어려움
			- 별도의 분산 Lock 서버를 두어서 "저 DB에 접근 가능한가요?" 물어보고 가능하다고 하면 접근
- Durability (지속성) ─ COMMIT 하면 DB에 영구적으로 반영된다. COMMIT 전까지는 트랜잭션이 끝난 게 아니다. 
# 트랜잭션 제어어
- Transaction Control Language
	- 트랜잭션을 제어하는 명령로 DCL의 하위 명령어 분류에 해당
	- 여러 개의 DML 작업을 하나의 단위로 묶어 하나의 트랜잭션이라고 한다. 
		- 트랜잭션 내에 오류가 발생하는 쿼리가 있는 경우 트랜잭션 내 모든 쿼리가 실패한다.
- 트랜잭션 실행 (트랜잭션 수동 실행) ─ `BEGIN; .. COMMIT;`
- 트랜잭션 복구 (커밋전에 복구 가능) ─ `ROLLBACK;`
# Supabase
- 클라우드 RDMS 
- 환경변수 설정
	- SUPABASE_URL
	- SUPABASE_PUBLISHABLE_KEY
	- SUPABASE_ANON_KEY
		- 최근에는 `Publishable and secret API keys`를 쓴다.
		- 일부 기능들은 `Legacy anon, service_role API keys`를  쓰기 때문에 설정 필요

> [!NOTE] 환경변수 파일 생성 vs. 시스템 환경변수 설정
> - 환경변수 파일 생성 ─ 각 프로젝트별 필요한 환경변수를 저장하고 내부적으로 공유할 수 있음
> - 시스템 환경변수 설정 ─ 로컬에 환경변수를 저장하고 공유 없이 

```python
import os
from dotenv import load_dotenv
from supabase import create_client

  

# .env 파일의 환경 변수를 메모리로 불러옵니다. (.env 파일의 환경 변수를 로컬 시스템의 환경 변수로 등록합니다.)

# 본 실습에서는 .env 파일을 사용하지 않고 직접 로컬 시스템의 환경 변수를 등록했으므로 생략합니다.

# 환경 변수는 숫자가 있어도 모두 문자열로 인식합니다.

# load_dotenv()

  

url = os.getenv("SUPABASE_URL") # os.environ.get 매서드로도 불러올 수 있습니다.

key = os.getenv("SUPABASE_PUBLISHABLE_KEY")

  

# Supabase 클라이언트 객체 생성

supabase = create_client(url, key)

  

print("Supabase 클라이언트가 성공적으로 연동되었습니다!")
```
