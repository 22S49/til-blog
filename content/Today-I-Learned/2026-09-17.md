# CSS Grid
- 부모 요소에 설정하고 자식 요소에 적용한다. (자식에 스타일을 일괄 적용하기 위해 부모가 통제한다.)
	- `template-columns` 및 `grid-template-rows`
		- 생성할 컬럼 수만큼 크기를 나열하면 컬럼 구역이 설정된다. 
		- *e.g.* `grid-template-columns: 150px 1fr 2fr` ─ 2열, 3열을 남아 있는 공간에 대해 1/3, 2/3 만큼 할당
		- *e.g.* `grid-template-columns: repeat(3, 1fr)` ─ 열을 3개 만들고 모든 열의 너비를 1fr로 같게 한다.
	- 
	- `grid-column` 및 `grid-row`
		- `grid-column|row: 1/3;` ─ 1번 열에서 3번 열까지 차지한다. (마지막 칸은 제외하고 1, 2열 차지)
		- `grid-column|row: span 2;` ─ 전체 열 중 2개 열 차지
	- `place-items` ─ 자식 요소 배치
		- stretch (기본값) / start (좌상단) / end (우하단) / center (정가운데)
# CSS Gap
- grid, flexbox, multi-column layout 등에서 사용
	- `row-gap` ─ 행별 여백
	- `column-gap` ─ 열별 여백
	- `gap` ─ 행열 여백 (수치 2개 나열 또는 1개 나열 시 행열에 동일한 수치 적용)

> [!NOTE] DOM (Document Object Model)
> 브라우저가 HTML 문서를 읽어서 만드는 트리 구조의 데이터
> 예를 들어 `<ul> <li>사과</li> <li>바나나</li> </ul>` 라는 코드가 있으면 
> - 브라우저는 이걸 그냥 텍스트로 두지 않고, 각 태그를 노드(node)로 만들어서 부모-자식 관계로 연결한 트리 생성
> - 이 트리가 DOM 이고 요소들이 나열된 순서를 DOM 순서라고 한다. 
> - *cf.* CSS `align-items`의 `order` 속성은 DOM 순서와 상관없이 시각적 위치만 변경한다. 

# CSS Overflow
- `visible` ─ 넘치는 컨텐츠가 있어도 보인다. (기본값)
- `hidden` ─ 넘치는 컨텐츠를 감춘다. 
- `scroll` ─ 스크롤바를 노출시켜 넘치는 값을 담는다. 넘치지 않더라도 스크롤바를 노출한다. (X축 Y축 상시 노출)
- `auto` ─ 넘치는 값이 있으면 스크롤바를 노출하고 그렇지 않으면 스크롤바를 노출하지 않는다. (필요한 축만 노출)
# CSS Baorder
- `border-width` ─ 경계선의 두께 
- `border-style` ─ none(선 없음, 기본값), solid(직선), dashed(파선), dotted(점선), double(이중실선)
- `border-color` ─ 경계선의 색상 (*cf.* 단축표현 ─ `border: 2px solid red;`)
- `border-radius` ─ 경계선의 모서리를 둥글게 
# CSS Background
- `background-color` ─ 배경색
- `background-image` ─ url 함수에 이미지 경로 명시
- `background-repeat` ─ 배경 이미지 반복 설정
	- `repeat` ─ X축 + Y축 반복 
	- `repeat-x` ─ X축 반복
	- `repeat-y` ─ Y축 반복
	- `no repeat` ─ 반복하지 않음
- `background-position` ─ 배경 이미지 위치 설정
	- `background-position: 100px 50px` ─ 좌로부터 100px 위로부터 50px 떨어진 위치
	- `backgroud-position: left|right top|bottom` ─ 각 순서에 수치를 두어서 위치를 설정할 수 있다. 
		- `background-position: center center` ─ 이미지를 정 가운데 배치한다. 
- `background-size` ─ 배경 이미지 크기 설정
	- `background-size: 200px 100px` ─ 가로 200px 세로 100xp 크기 (*cf.* 한쪽만 설정할 경우 원본 비율 유지)
	- `cover` ─ 이미지의 비율이 배경 요소와 차이가 있는 경우 일부 이미지는 짤린다. 
	- `contain` ─ 이미지가 모두 보일 수 있도록 채운다. 
- `background-attachment`
	- `fixed` ─ 스크롤을 해도 배경 이미지는 고정된다. 배경 이미지가 길어도 보여지는 이미지 구역은 고정된다. 
	- `scroll` ─  스크롤 시 배경 이미지도 함께 스크롤 된다. 배경 이미지가 길면 아래쪽 이미지가 보인다.
	- `local` ─ 내용에 고정 (배경 이미지가 요소 내부 스크롤에도 같이 따라간다.)
- 단축 표기법 ─ `background: 경계선_색상 이미지 반복 고정 위치 사이즈 배경_색상` 
	- 적어도 색상 또는 이미지 중 하나는 정의해야 함 (색상 또는 이미지는 필수이고 그 외는 선택 속성)
# Position
- 위치(배치)
	- 절대위치 ─ static (기본값)
	- 상대위치 배치 기준
		- relative ─ 속성이 정의되어 있는 요소가 기준 (현재 위치 기준)
			- absolute ─ 문서 전체가 기준
				- 단, 부모가 상대속성 (relative, absolute, fixed)이면 부모가 기준점이 된다. 
		- fixed ─ 뷰포트(viewport, 현재 보이는 화면) 기준
	- 상대위치 방향 속성 ─ left(좌 ⇢ 우), right(우 ⇢ 좌), top(위 ⇢ 아래), bottom(아래 ⇢ 위)

# 스타일 초기화 데모
``` css
@import url('https://fonts.googleapis.com/css2?family=Noto+Sans+KR:wght@100..900&display=swap');

/* 스타일 초기화 작업 */

* {
    outline: none;
}

body {
    margin: 0;
}

ul, ol, dl, dt, dd {
    margin: 0;
    padding: 0;
    list-style: none;
}

a {
    text-decoration: none;
}

img {
    border: 0;
}

/* 전역 변수 선언 */

:root {
    --primary-font-family: "Noto Sans KR", sans-serif;
    --primary-font-size: 13px;
    --primary-font-color: #313131;
    --primary-layout-max-size: 727px;
    --primary-layout-min-size: 320px;
}

/* 스타일 공통 설정 */

* {
    box-sizing: border-box;
    font-family: var(--primary-font-family);
}

html {
    font-size: var(--primary-font-size);
    background: silver;
}

body {
    color: var(--primary-font-color);
    max-width: var(--primary-layout-max-size);
    min-width: var(--primary-layout-min-size);
    min-height: 700px;
    background: #fff;
    margin: 0 auto;
}

/* 상단 로고, 메뉴 영역 */

header {
    display: flex;
    justify-content: space-between;
    height: 66px;
    border-bottom: 1px solid silver;
    align-items: center;
}

header > section {
    width: 20%;
}

header > section.right {
    text-align: right;
}
```

"브라우저 맘대로"가 아니라 정해진 공식대로 계산돼요.

**scale = max(컨테이너 가로/이미지 가로, 컨테이너 세로/이미지 세로)**

두 비율 중 **더 큰 쪽**을 기준으로 확대합니다. 그래야 두 축 다 "최소한 컨테이너를 다 덮는" 크기가 보장되거든요. 작은 쪽 비율로 맞추면 반대쪽 축에 빈틈이 생기니까(그건 `contain`의 방식), `cover`는 일부러 더 큰 배율을 골라서 넘치게 만들고 그 넘친 부분을 잘라내는 거예요.

방금 그린 이미지의 `cover` 패널로 계산해보면:

- 컨테이너: 220×140
- 이미지 원본 비율: 300×120 (가로가 긴 형태)
- 가로 기준 배율: 220/300 = 0.733
- 세로 기준 배율: 140/120 = 1.167
- 둘 중 큰 값인 **1.167**을 선택 → 이미지가 350×140이 됨 → 가로가 컨테이너보다 130px 더 커서 양옆이 잘림

핵심은 **비율(가로세로 비)은 항상 유지**되고, 두 축 중 하나는 정확히 컨테이너에 딱 맞고 나머지 한 축만 넘친다는 거예요. `contain`은 정반대로 두 비율 중 **작은 값**을 골라서 이미지 전체가 다 들어가게 하는 거고요.

| 상황 예시              | 컨테이너    | 이미지 원본  | 가로 배율 | 세로 배율        | cover 결과                       | contain 결과                   |
| ------------------ | ------- | ------- | ----- | ------------ | ------------------------------ | ---------------------------- |
| 가로로 넓은 이미지 (풍경)    | 220×140 | 300×120 | 0.733 | 1.167        | 1.167배  ⇢ 350×140, 좌우 130px 잘림 | 0.733배 ⇢ 220×88, 위아래 52px 여백 |
| 세로로 긴 이미지 (인물사진)   | 220×140 | 120×300 | 1.833 | 0.467        | 1.833배 ⇢ 220×550, 위아래 대폭 잘림    | 0.467배 ⇢ 56×140, 좌우 큰 여백     |
| 정사각형 컨테이너에 파노라마 사진 | 400×400 | 300×120 | 1.333 | 3.333        | 3.333배 ⇢ 1000×400, 좌우 심하게 잘림   | 1.333배 ⇢ 400×160, 위아래 큰 여백   |
| 컨테이너·이미지 비율이 똑같음   | 300×120 | 1.0     | 1.0   | 1배, 잘림/여백 없음 | 1배, 잘림/여백 없음                   |                              |

`cover` 자체엔 배율을 조정하는 옵션이 없어요. `cover`는 정의상 **"두 배율 중 큰 값"을 자동으로 계산**하는 키워드라서, 그 계산식에 사용자가 끼어들 여지가 없습니다. 항상 "빈틈없이 꽉 채우는 최소 확대"만 해요.

대신 확대 정도를 직접 조절하고 싶으면 이런 방법들을 씁니다:

1. **`background-size`를 퍼센트로 직접 지정**

css

```css
   background-size: 150%; /* cover보다 더 확대하고 싶을 때 */
```

숫자를 늘릴수록 더 확대되고, 잘리는 범위도 커져요. `cover`를 안 쓰고 이걸로 원하는 배율을 직접 정하는 거예요.

2. **`background-position`으로 "어디가 잘릴지"는 조정 가능**

css

```css
   background-size: cover;
   background-position: center top; /* 위쪽을 기준으로 유지, 아래쪽 위주로 잘림 */
```

배율 자체는 못 바꾸지만, 크롭되는 기준점(중심)은 바꿀 수 있어요. 인물 사진에서 얼굴이 잘리는 문제를 여기서 해결하는 거고요.

3. **`<img>` 태그라면 `object-fit: cover` + `object-position`**  
    background-image가 아니라 진짜 `<img>` 요소를 쓸 때는 이 조합이 동일한 역할을 해요.
4. **줌 자체를 원하면 `transform: scale()`**  
    `cover`로 꽉 채운 다음 추가로 더 확대하고 싶으면 `transform`을 얹는 방법도 있어요 (단, 이건 배경 전체가 요소 기준으로 늘어나는 거라 컨테이너 밖으로 넘칠 수 있어서 부모에 `overflow: hidden`이 필요할 때가 많아요).

- `background-attachment: scroll` → **상황 1**에서는 배경이 박스 따라 움직여요. 근데 **상황 2**에서는 배경이 안 움직여요 (박스에 고정돼있어서).
- `background-attachment: local` → **상황 1, 2 둘 다** 배경이 움직여요.

즉 둘의 차이는 딱 **상황 2 (채팅창처럼 박스 안에서만 스크롤할 때)**에서만 나타나요. 그 상황이 아니면 둘이 똑같이 동작해요.


14. **왜 Flexbox와 Grid가 둘로 나뉘었나**
    - 한 줄 흐름(헤더, 푸터)은 1차원이라 Flex, 행과 열이 함께 있는 카드 보드는 2차원이라 Grid가 맞습니다.
    - 사이트 하나에 둘이 공존하는 모습을 직접 보여줍니다.
15. **왜 `fr`, `flex-grow`가 있나**
    - 화면 폭이 계속 변하는데 `px`로 계산하면 매번 다시 계산해야 합니다. "남는 공간을 비율로 나눈다"고 선언하면 브라우저가 계산합니다.
16. **왜 `gap`을 쓰나**
    - 간격은 자식이 아니라 **부모가 관리하는 값**입니다. 자식에 margin을 주면 마지막 요소의 여백을 따로 처리해야 하는 문제가 생깁니다.
17. **왜 주축·교차축이라는 개념을 쓰나**
    - 방향이 `row`에서 `column`으로 바뀌면 `justify`와 `align`의 담당 방향도 같이 바뀝니다. "가로/세로"로 외우면 헷갈리는 이유입니다. 용어 사전의 주축·교차축 개념을 근거로 설명합니다.
18. **왜 `viewport` 메타 태그가 필요하고, 브레이크포인트는 왜 정해두나**
    - 모바일 브라우저는 별도 설정이 없으면 화면을 축소해서 보여줍니다. `width=device-width`가 있어야 미디어 쿼리가 기기 폭을 기준으로 동작합니다.
    - 768/1024는 기기군을 나누는 표준 경계입니다. 팀이 같은 숫자를 쓰면 화면이 전환되는 기준이 일관됩니다.
