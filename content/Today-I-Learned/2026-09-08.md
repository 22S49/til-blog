# 서브쿼리
- SELECT문에 SELECT가 포함된 질의 (외부쿼리 ⊃ 내부쿼리)
- 서브쿼리 실행순서 ─ 내부쿼리 ⇢ 외부쿼리
## 위치별 서브쿼리
- **스칼라 서브쿼리** ─ 값을 하나만 가지고 있는 형태의 서브쿼리 ─ `SELECT (서브쿼리), FROM .. WHERE ..`
- **인라인 뷰** ─ 가상(임시) 테이블 ─  `SELECT .. FROM (서브쿼리) WHERE ..`
	- 조회된 결과(메모리)를 테이블처럼(물리적 테이블은 아니지만 물리적 테이블처럼) 사용하는 형태
	- 그룹화한 가상의 테이블 내에서 특정 컬럼을 다시 조회할 수 있다. 
	- 가상의 테이블에 별칭을 부여해서 부가 조회 쿼리를 만들거나 JOIN을 할 수 있다. 
	- 사용례
		- 집계 결과에 다시 조건을 걸어야 하거나 (HAVING으로 안 되는 복잡한 조건) 윈도우 함수를 씌워야 할 때
		- 집계 결과를 다른 테이블과 다시 JOIN 해야 할 때
		- 여러 단계 집계를 이어서 해야 할 때 (집계의 집계) ─ *e.g.* 매장/상품별 재고 합계 ⇢ 매장별 평균 재고량
```postgresql
-- 그룹화: 최종 목적이 집계 결과일 때 주로 사용
SELECT store_id, product_id, sum(quantity) total_stock
FROM stocks
GROUP BY store_id, product_id;

-- 인라인뷰
SELECT * FROM (
SELECT store_id, product_id, sum(quantity) total_stock
FROM stocks
GROUP BY store_id, product_id
);
```
- **WHERE절 서브쿼리** ─ `SELECT .. FROM .. WHERE (서브쿼리)`
	- 상관 서브쿼리 ─ 내부쿼리의 결과를 외부 쿼리가 사용  ~ CTE로 가독성 있게 사용 가능
	- 단일행 서브쿼리 (값이 1개, 스칼라 서브쿼리와 같은 특성) ─ 비교연산 시 해당
	- 다중행 서브쿼리 (값이 여러 개) ─ `SELECT .. FROM .. WHERE IN|NOT IN|EXISTS (서브쿼리);
		- EXISTS ─ 레코드가 하나라도 반환되면 TRUE
			- 서브쿼리 작성 시 반드시 별칭으로 컬럼을 명시
			- IN 보다 성능이 좋음 (압도적으로 좋은 건 아님)
				- 모든 것을 조회하지 않고 한 개만 가져와도 TRUE가 반환되기 때문에
				- NOT IN은 서브쿼리 결과에 NULL이 포함되어 있으면 반환하지 않음
					- NOT IN 사용 시 IS NOT NULL 조건을 두거나 NOT EXISTS를 쓰는 것이 안전함
			- *cf.* 조회 성능 조회 ─ `EXPLAIN ANALYZE SELECT .. FROM ..`
```postgresql
-- EXISTS 사용: 행단위로 존재 여부만 확인 후 조건에 맞는 첫 번째 행을 찾으면 즉시 멈춤
SELECT product_id, product_name
FROM products p
WHERE EXISTS
	(SELECT * FROM stocks s WHERE s.product_id = p.product_id); 

-- IN 사용: 서브쿼리를 통쨰로 실행 후 직접 비교
SELECT product_id, product_name
FROM products
WHERE product_id IN 
	(SELECT product_id FROM stocks); 
```

	- 그래서 postgreSQL 사용 시에는 문자열 자료형으로 VARCHAR 보다 TEXT를 많이 쓴다.
다른 SQL 
- TEXT를 쓰면 할당 크기가 커서 성능 지연이 발생할 수 있으므로 VARCHAR나 TEXT를 적절히 선택해서 사용

UUID (Universally Unique Identifier)
- 자료형이자 식별자 ─ 암호화 알고리즘을 사용해 만든 문자열
	- 단순 숫자로 식별하는 경우 조회가 빠른 대신 보안에 취약
	- UUID 같은 문자열로 식별하는 경우 상대적으로 조회가 느릴 수 있지만 어느 정도 보안 설정 가능
- 32자로 표현 (128 byte) ─ 8자리-4자리-4자리-4자리-12자리
- *e.g.* ─ `id uuid PRIMARY KEY DEFAULT gen_random_uuid()`

CTE는 **Common Table Expression**의 약자입니다. 한국어로는 보통 "공통 테이블 표현식"이라고 번역해요.

- **Common**: 쿼리 안에서 여러 번 참조(재사용)할 수 있다는 의미
- **Table**: 실행 결과가 테이블처럼 취급됨 (컬럼과 행을 가진 형태)
- **Expression**: 실제로 저장되는 게 아니라, 쿼리 실행 시점에만 존재하는 임시 표현식

`WITH` 키워드로 시작해서 `WITH ... AS (...)` 형태로 쓰기 때문에 **"WITH 절"**이라고 부르기도 합니다. 둘 다 같은 걸 가리키는 말이에요.

방금 예시들을 전부 CTE로 바꿔볼게요. 문법 차이랑 왜 CTE가 더 읽기 편한지 같이 보여드릴게요.

### 기본 형태 비교

sql

```sql
-- 인라인 뷰 (서브쿼리를 FROM 절 안에 직접 씀)
SELECT *
FROM (
    SELECT store_id, product_id, SUM(quantity) total_stock
    FROM stocks
    GROUP BY store_id, product_id
) agg
WHERE total_stock >= 100;
```

sql

```sql
-- CTE (WITH로 먼저 이름 붙여서 선언한 뒤 아래에서 사용)
WITH agg AS (
    SELECT store_id, product_id, SUM(quantity) total_stock
    FROM stocks
    GROUP BY store_id, product_id
)
SELECT *
FROM agg
WHERE total_stock >= 100;
```

**결과와 성능은 동일**합니다. 차이는 순전히 **작성 위치와 가독성**이에요.

|       | 인라인 뷰                    | CTE                      |
| ----- | ------------------------ | ------------------------ |
| 정의 위치 | FROM 절 안, 필요한 곳에 바로      | 쿼리 맨 위에서 미리 선언           |
| 이름    | 괄호 닫고 뒤에 alias (`) agg`) | `WITH agg AS (` 처럼 앞에 이름 |
| 읽는 흐름 | 안쪽→바깥쪽으로 거슬러 올라가며 읽음     | 위→아래로 순서대로 읽음            |
| 재사용   | 같은 서브쿼리 또 쓰려면 복붙         | 같은 CTE를 여러 번 참조 가능       |

### 아까 예시들 CTE로 변환

**JOIN 붙이는 예시**

sql

```sql
WITH agg AS (
    SELECT store_id, product_id, SUM(quantity) total_stock
    FROM stocks
    GROUP BY store_id, product_id
)
SELECT s.name AS store_name, p.name AS product_name, agg.total_stock
FROM agg
JOIN stores s ON s.id = agg.store_id
JOIN products p ON p.id = agg.product_id;
```

**여러 단계 집계 (2단계 인라인 뷰) → CTE 여러 개**

sql

```sql
WITH agg AS (
    SELECT store_id, product_id, SUM(quantity) total_stock
    FROM stocks
    GROUP BY store_id, product_id
)
SELECT store_id, AVG(total_stock) avg_stock_per_product
FROM agg
GROUP BY store_id;
```

### 딱 한 줄 요약

**인라인 뷰 = 즉석에서 만들어 바로 쓰는 이름 없는 임시 테이블 / CTE = 미리 이름 붙여서 선언해두고 아래에서 쓰는 임시 테이블.** 문법만 다르고 실행은 사실상 같지만, 단계가 2개 이상 겹치는 순간부터는 CTE 쪽이 압도적으로 읽기 편합니다.

5번 문항

IN과 EXISTS의 차이에 대한 설명으로 가장 적절한 것은?

C. EXISTS는 조건을 만족하는 행이 하나라도 있으면 바로 TRUE를 반환하며 NULL에 영향받지 않는다

에이타니

정답이에요

EXISTS는 조건을 만족하는 행이 하나라도 존재하면 즉시 TRUE를 반환하고 NULL의 영향을 받지 않습니다. 반면 IN은 서브쿼리의 값 목록 전체를 가져와 비교하는 방식이며, 대량 데이터에서는 오히려 EXISTS가 더 유리한 경우가 많습니다.
