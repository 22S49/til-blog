클래스 이름을 역할로 짓나, 기능으로 짓나

Tailwind는 화면에서 쓴 낱개 클래스를 찾아서, 그 CSS만 만들어 줍니다.

일반 CSS 역할 기반: 클래스 하나에 여러 선언

.menu-card {
  display: flex;
  flex-direction: column;
  padding: 16px;
  border-radius: 16px;
}
<div class="menu-card">

유틸리티 클래스 기능 기반: 클래스 하나에 선언 하나

.flex       { display: flex; }
.flex-col   { flex-direction: column; }
.p-4        { padding: 16px; }
.rounded-2xl { border-radius: 16px; }
<div class="flex flex-col p-4 rounded-2xl">

왜 이렇게 만들어졌고, 왜 이렇게 관리할까 1/2 배치

왜 이렇게 만들어졌나왜 이렇게 관리하나
Flex와 Grid 일의 종류가 달라서 도구를 나눴다. 한 줄 흐름은 Flex(1차원), 행과 열이 함께 필요하면 Grid(2차원) 한 화면에 섞어 쓴다. 헤더는 Flex, 카드 보드는 Grid
주축과 교차축 방향이 바뀌면 정렬 기준도 같이 바뀌어야 해서, 가로 세로 대신 축으로 부른다 먼저 flex-direction을 정하고, 그다음 justify-content와 align-items를 본다
남는 공간 폭이 계속 변하니 px 계산 대신 "남는 공간을 비율로" 나눈다 (flex-grow, fr) grow, shrink, basis는 부모가 아니라 자식에 건다
간격 간격은 자식이 아니라 부모의 일이다 자식 margin 대신 gap으로 관리한다. 마지막 요소 예외 처리가 필요 없다

왜 이렇게 만들어졌고, 왜 이렇게 관리할까 2/2 반응형과 Tailwind

왜 이렇게 만들어졌나왜 이렇게 관리하나
반응형 기기가 다양해서 전환 기준이 필요하다 (768 / 1024px). viewport 메타가 없으면 모바일은 축소해서 보여준다 모바일이 기본이고, 커질 때만 덮어쓴다 (min-width가 누적됨)
Tailwind 이름 짓기와 CSS-HTML 오가기를 없애려고, 스타일을 요소 옆에 낱개로 둔다 반복되면 컴포넌트로 묶는다. 값은 외우지 않고 공식 문서에서 검색한다

배치 도구와 반응형 규칙은 그대로, Tailwind는 쓰는 방식만 바꾼 것입니다.
